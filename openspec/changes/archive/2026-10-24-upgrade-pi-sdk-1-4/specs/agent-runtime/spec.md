# Spec Delta

## MODIFIED Requirements

### Requirement: 持久化会话

系统 SHALL 将对话条目、文档与任务状态在展示前原子提交到本地 SQLite 存储，进程重启后重新打开同一存储 MUST 恢复全部会话。本次恢复保证以 Pi 1.4.0 创建的数据为基线；1.3 及更早会话测试数据可清理，不提供跨版本数据或未完成任务兼容。处于定时等待的后台任务 MUST 在重启后按原到期时间继续，而不是重新开始等待。

#### Scenario: 重启恢复

- **WHEN** 使用 Pi 1.4.0 的进程在模型回答途中被杀掉，随后重新启动并打开同一存储文件
- **THEN** 会话记录完整存在，且未完成的 run 可被恢复继续

#### Scenario: 重复提交去重

- **WHEN** 客户端用相同 requestId 重复提交同一条输入
- **THEN** 系统返回已有 submission 而不是创建第二条

#### Scenario: 等待中重启

- **WHEN** 新会话的标题生成任务处于到期前的等待，进程被杀掉后重新启动
- **THEN** 任务在原到期时间之后继续并只生成一次标题，等待不被重新计时

## ADDED Requirements

### Requirement: 崩溃循环任务停放

系统 SHALL 在同一后台任务连续被进程崩溃截断且期间没有提交新状态达到上限（默认 5 次）后停止重启它，并经宿主错误通道报告一次；被停放的任务 MUST NOT 阻止其他会话与任务运行。

#### Scenario: 反复崩溃的任务被停放

- **WHEN** 某任务在重启后仍反复在同一阶段使进程崩溃，连续达到重启上限
- **THEN** 该任务不再被自动运行，宿主错误通道收到一次停放报告，其余会话正常打开并可用

#### Scenario: 提交新状态后计数重置

- **WHEN** 任务被崩溃截断若干次后（未达上限）提交了新的状态
- **THEN** 其重启计数从零重新累计，不会因更早的崩溃被提前停放
