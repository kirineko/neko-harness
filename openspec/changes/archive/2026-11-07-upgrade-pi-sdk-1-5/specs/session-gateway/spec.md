# Spec Delta

## ADDED Requirements

### Requirement: 运行失败原因与继续接口

网关 SHALL 在会话视图中以可选字段提供该会话最近一次未得到回答的运行的失败原因（原因代码与有界详情），并提供"继续"会话操作。失败原因 SHALL 随运行结束与新运行开始同步到所有已连接前端；继续 MUST 经与提交相同的附着与归属校验，忙碌、无失败或 provider 不可用时返回可区分的错误。

#### Scenario: 多端同步

- **WHEN** Web 与 TUI 同时查看同一会话，运行因模型错误结束，一端选择继续
- **THEN** 两端都先显示失败原因，继续后两端的失败原因都消失并显示同一次新运行

#### Scenario: 重复继续

- **WHEN** 两端几乎同时对同一失败选择继续
- **THEN** 只有一次继续开始运行，另一端收到忙碌错误，不产生两次运行

### Requirement: 运行失败与继续的向后兼容

失败原因字段与继续接口 SHALL 作为可选扩展加入，不提升应用协议版本。缺少该字段 SHALL 表示网关不支持；新客户端连接旧网关时 MUST 隐藏继续入口且不报错，旧客户端连接新网关时 MUST 忽略新增字段而正常工作。

#### Scenario: 新界面连接旧网关

- **WHEN** 新 TUI/Web 连接不提供失败原因字段的旧网关
- **THEN** 会话照常使用，不显示失败原因与继续入口，不触发协议不兼容

#### Scenario: 旧界面连接新网关

- **WHEN** 旧版客户端连接新网关，会话中的运行失败
- **THEN** 客户端照常工作并忽略失败原因字段

### Requirement: 会话视图的完整 transcript

网关下发的会话视图 SHALL 继续包含会话的完整持久条目与实时调用数据，而不因上游视图改为有界窗口而截断；上下文占用 SHALL 按模型实际看到的活动上下文计算。窗口积压、重连或长会话 MUST NOT 使视图丢失中间条目。

#### Scenario: 长会话

- **WHEN** 会话已有数百条条目且运行中持续追加
- **THEN** 前端看到的条目从会话开头完整连续，新条目按顺序追加，不出现缺口

#### Scenario: 压缩后的上下文占用

- **WHEN** 会话发生压缩后继续对话
- **THEN** 视图仍显示压缩前的历史条目，上下文占用只按压缩后的活动上下文计算
