# Spec Delta

## MODIFIED Requirements

### Requirement: 批准后自动执行
用户批准计划 SHALL 绑定计划版本，且只有当前待批准版本可被批准。批准 MUST 使会话退出 plan 模式、恢复完整工具集，并自动提交一条要求按已批准计划执行的输入，输入中 SHALL 包含已批准计划的完整步骤，使会话立即开始执行。批准结果、工具集恢复与执行输入 MUST 在同一次持久提交中生效：要么全部生效，要么全部不生效。相同版本的重复批准或重启后的恢复 MUST NOT 产生第二条执行输入。

#### Scenario: 批准并执行
- **WHEN** 用户批准当前待批准计划
- **THEN** 会话退出 plan 模式，并以已批准计划为依据开始新一轮执行，工具集包含写工具

#### Scenario: 批准中途重启
- **WHEN** 用户批准计划时 gateway 恰好重启
- **THEN** 恢复后要么计划仍待批准且会话仍在 plan 模式，要么会话已退出 plan 模式且执行输入恰好存在一条，不会出现已批准却没有执行输入的状态

#### Scenario: 过期版本被批准
- **WHEN** 客户端对已被取代的版本提交批准
- **THEN** 请求被拒绝并返回该版本的最终状态，不退出 plan 模式、不启动执行

#### Scenario: 旧版本遗留的未执行批准
- **WHEN** 升级前已保存批准但执行输入尚未提交的会话在升级后首次启动
- **THEN** 启动时补交该执行输入且恰好一次

### Requirement: 要求修改
用户 SHALL 可对当前待批准计划选择要求修改并给出文字反馈（1–2000 字符）。要求修改 MUST 使计划置为 revision_requested，会话保持 plan 模式，并把反馈作为输入提交让模型修订；状态变更与反馈输入 MUST 在同一次持久提交中生效。同一版本的重复请求 MUST 幂等。

#### Scenario: 反馈驱动修订
- **WHEN** 用户对待批准计划提交"第 2 步拆开"并要求修改
- **THEN** 会话仍为 plan 模式，模型收到该反馈并可再次调研与提交新版本

#### Scenario: 空反馈
- **WHEN** 要求修改时反馈为空或超长
- **THEN** 请求被拒绝，计划仍为待批准
