# Spec Delta

## MODIFIED Requirements

### Requirement: 持久化会话

系统 SHALL 将对话条目、文档与任务状态在展示前原子提交到本地 SQLite 存储，进程重启后重新打开同一存储 MUST 恢复全部会话。本次恢复保证以 Pi 1.5.0 为基线：Pi 1.4.0 创建的存储 SHALL 原地打开并继续使用，不清理数据；一经 1.5 写入，回退到使用 Pi 1.4 的发布版本不受支持。处于定时等待的后台任务 MUST 在重启后按原到期时间继续，而不是重新开始等待。

#### Scenario: 重启恢复

- **WHEN** 使用 Pi 1.5.0 的进程在模型回答途中被杀掉，随后重新启动并打开同一存储文件
- **THEN** 会话记录完整存在；被中断的模型请求计为一次失败尝试，按重试策略重新请求，重试用尽时该轮以"已中断"失败结束而不是无限重发

#### Scenario: 重复提交去重

- **WHEN** 客户端用相同 requestId 重复提交同一条输入
- **THEN** 系统返回已有 submission 而不是创建第二条

#### Scenario: 等待中重启

- **WHEN** 新会话的标题生成任务处于到期前的等待，进程被杀掉后重新启动
- **THEN** 任务在原到期时间之后继续并只生成一次标题，等待不被重新计时

#### Scenario: 打开 1.4 创建的存储

- **WHEN** 用 1.5 打开 Pi 1.4.0 创建的存储文件
- **THEN** 已有会话、待办、计划、问题与后台任务记录全部可见并可继续使用，不要求删除存储

## REMOVED Requirements

### Requirement: 崩溃循环任务停放

**Reason**: Pi 1.5 不再停放达到重启上限的任务，也删除了 `retryTask`；停放的任务会让会话一直处于忙碌状态且没有恢复入口。

**Migration**: 由"崩溃到限任务结束"要求取代：任务到限后可见地结束，用户可以重新提交输入或使用"继续"。

## ADDED Requirements

### Requirement: 崩溃到限任务结束

系统 SHALL 在同一任务连续被进程崩溃截断且期间没有提交新状态达到上限（默认 5 次）后结束该任务，而不是停放或无限重启。工具调用 MUST 得到错误结果；模型生成 MUST 使该轮以"重启上限"失败结束并记录失败原因；结束 MUST 经宿主错误通道报告一次，且 MUST NOT 阻止其他会话与任务运行。

#### Scenario: 反复崩溃的任务结束

- **WHEN** 某会话的运行在重启后仍反复在同一阶段使进程崩溃，连续达到重启上限
- **THEN** 该运行以"重启上限"失败结束，会话回到空闲并显示失败原因，宿主错误通道收到一次报告，其余会话正常打开并可用

#### Scenario: 提交新状态后计数重置

- **WHEN** 任务被崩溃截断若干次后（未达上限）提交了新的状态
- **THEN** 其重启计数从零重新累计，不会因更早的崩溃被提前结束

### Requirement: 运行失败原因

当一次运行没有得到回答就结束时，系统 SHALL 记录最近一次失败的原因（模型错误、无可用模型、用户停止、重置、任务故障、孤立、已中断、重启上限、轮次上限、无可回答内容）及有界的详情文字。失败原因 SHALL 保留到下一次运行开始，并在下一次运行开始时清除；它 MUST 只描述最近一次运行，不累计历史。

#### Scenario: 模型错误

- **WHEN** 模型请求在重试用尽后仍失败
- **THEN** 会话回到空闲，失败原因为模型错误并附带错误文字，下一次提交输入后失败原因消失

#### Scenario: 用户停止

- **WHEN** 用户停止正在进行的运行
- **THEN** 失败原因为用户停止，排队输入按既有停止语义处理

### Requirement: 继续运行

系统 SHALL 允许对空闲且最近一次运行未得到回答的会话发起"继续"：不新增用户消息，基于现有上下文开始新的运行，排队中保留的输入先放入并加入该运行。会话忙碌或没有未回答的失败时 MUST 拒绝并返回可区分的错误；"继续"与普通输入一样 MUST 经 provider 启用与凭据校验。

#### Scenario: 失败后继续

- **WHEN** 运行因模型错误结束，用户在会话空闲时选择继续
- **THEN** 新的运行在原有上下文上开始，transcript 中不出现新的用户消息，成功回答后失败原因消失

#### Scenario: 忙碌或无失败时继续

- **WHEN** 会话正在运行，或最近一次运行已正常回答，客户端请求继续
- **THEN** 请求被拒绝并返回可区分的错误，不启动运行、不写入任何内容

### Requirement: 可选轮次上限

系统 SHALL 支持在配置文件中设置可选的单次运行工具轮次上限（正整数，缺省不限制），应用于此后新建的主会话与子 agent，已有会话不受影响。达到上限的那一轮工具执行完后，运行 MUST 以"轮次上限"失败结束，用户可用"继续"在该轮结果上接着运行。无效配置值 MUST 在启动时报错。

#### Scenario: 达到轮次上限

- **WHEN** 配置轮次上限为 3，模型在一次运行中连续发起工具调用
- **THEN** 第 3 轮工具执行完成后运行结束，失败原因为轮次上限，会话空闲且可继续

#### Scenario: 未配置

- **WHEN** 配置文件未设置轮次上限
- **THEN** 运行轮次不受限制，与升级前行为一致
