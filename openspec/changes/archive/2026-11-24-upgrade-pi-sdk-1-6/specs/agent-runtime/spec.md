# Spec Delta

## MODIFIED Requirements

### Requirement: 持久化会话

系统 SHALL 将对话条目、文档与任务状态在展示前原子提交到本地 SQLite 存储，进程重启后重新打开同一存储 MUST 恢复全部会话。本次恢复保证以 Pi 1.6.0 为基线：Pi 1.4.0 与 1.5.0 创建的存储 SHALL 原地打开并继续使用，不清理数据；一经 1.6 写入，回退到使用 Pi 1.5 或更早版本的发布版本不受支持。处于定时等待的后台任务 MUST 在重启后按原到期时间继续，而不是重新开始等待。

#### Scenario: 重启恢复

- **WHEN** 使用 Pi 1.6.0 的进程在模型回答途中被杀掉，随后重新启动并打开同一存储文件
- **THEN** 会话记录完整存在；被中断的模型请求计为一次失败尝试，按重试策略重新请求，重试用尽时该轮以"已中断"失败结束而不是无限重发

#### Scenario: 重复提交去重

- **WHEN** 客户端用相同 requestId 重复提交同一条输入
- **THEN** 系统返回已有 submission 而不是创建第二条

#### Scenario: 等待中重启

- **WHEN** 新会话的标题生成任务处于到期前的等待，进程被杀掉后重新启动
- **THEN** 任务在原到期时间之后继续并只生成一次标题，等待不被重新计时

#### Scenario: 打开 1.4 创建的存储

- **WHEN** 用 1.6 打开 Pi 1.4.0 创建的存储文件
- **THEN** 已有会话、待办、计划、问题与后台任务记录全部可见并可继续使用，不要求删除存储

#### Scenario: 打开 1.5 创建的存储

- **WHEN** 用 1.6 打开 Pi 1.5.0 创建的存储文件
- **THEN** 已有会话、待办、计划、问题与后台任务记录全部可见并可继续使用，不要求删除存储
