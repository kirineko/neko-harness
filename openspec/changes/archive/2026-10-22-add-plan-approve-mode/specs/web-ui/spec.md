# Spec Delta

## ADDED Requirements

### Requirement: Web 计划模式斜杠命令与状态标识
Web SHALL 只通过 `/plan` 斜杠命令进入或切换 plan 模式，不提供单独的进入按钮（待批准计划卡片上的「取消并退出计划模式」除外）。`/plan` SHALL 出现在命令菜单中并带说明，提交时在 plan 与 normal 模式间切换，命令本身不发送给模型、不进入输入历史；会话运行中输入 `/plan` MUST 提示需先等待或停止，且保留草稿、不切换。plan 模式下输入区 MUST 显示明确且可访问的模式标识。网关未发布计划字段时命令菜单 MUST 不列出 `/plan`，手动输入时提示该网关不支持。

#### Scenario: 命令切换与标识
- **WHEN** 用户在空闲会话输入并提交 `/plan`
- **THEN** 会话进入 plan 模式，输入区显示规划模式标识，草稿清空且没有消息发给模型；再次提交 `/plan` 退出并去除标识

#### Scenario: 运行中输入命令
- **WHEN** 会话回答中用户提交 `/plan`
- **THEN** 显示需先等待或停止的提示，模式不变，输入框内容保留

#### Scenario: 旧网关
- **WHEN** 连接的网关不支持计划能力
- **THEN** 命令菜单不含 `/plan`，输入区不显示模式标识

### Requirement: Web 计划卡片与决定
Web SHALL 在消息流中为 `submit_plan` 渲染计划卡片，展示标题、有序步骤、说明与状态（待批准、已批准、要求修改、已取代、已取消）。待批准卡片 MUST 提供「批准并执行」、「要求修改」（带文字反馈输入）与「取消并退出计划模式」操作；已结算卡片 MUST 只读显示最终状态。决定失败或被其他端抢先时 MUST 显示已结算的真实状态，计划标题与反馈按纯文本显示，步骤与说明（含「假设与风险」）按经过消毒的 Markdown 渲染。

#### Scenario: 批准
- **WHEN** 用户在待批准卡片点击"批准并执行"
- **THEN** 卡片变为已批准，模式标识消失，会话开始执行

#### Scenario: 要求修改
- **WHEN** 用户填写反馈并点击"要求修改"
- **THEN** 卡片变为要求修改，会话保持规划模式并收到反馈

#### Scenario: 取消并退出
- **WHEN** 用户在待批准卡片点击「取消并退出计划模式」
- **THEN** 卡片变为已取消，模式标识消失，会话回到 normal 模式，没有消息发给模型

#### Scenario: 被其他端抢先
- **WHEN** 用户点击批准时该计划已被另一端要求修改
- **THEN** 卡片显示已结算状态，不重复执行

### Requirement: Web 会话列表待批准标记
会话列表 SHALL 为有待批准计划的会话显示"等待批准"状态文字，与"等待回答"区分；浏览器标签标题的等待前缀 SHALL 也覆盖待批准会话。

#### Scenario: 其他会话待批准
- **WHEN** 当前不在该会话，且该会话提交了计划
- **THEN** 会话列表显示等待批准，状态在批准或取消后清除
