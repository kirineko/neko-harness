# Spec Delta

## ADDED Requirements

### Requirement: 排队输入遵循当前模式
会话未退出 plan 模式前，排队的 followUp 与 steer 输入 SHALL 一律在 plan 模式下处理：steer 在当前工具轮之后进入运行中的工作，followUp 在回答后开始下一轮，两者都只能使用只读工具，不得因计划已提交而绕过只读边界。处理任一普通输入 MUST 使待批准计划置为已取代，不视为批准。只有批准计划才会退出 plan 模式。

#### Scenario: 提交计划时有排队 steer
- **WHEN** 模型提交计划的同一工具轮之后，队列中的 steer 被放入上下文
- **THEN** 该输入由模型在 plan 模式下处理，写工具仍不可用，待批准计划被取代，用户需等新计划

#### Scenario: 提交计划后有排队 followUp
- **WHEN** 计划提交、本轮结束后队列中仍有 followUp
- **THEN** 该输入作为下一轮在 plan 模式下处理，不视为批准，待批准计划被取代

#### Scenario: 排队项不丢失
- **WHEN** 用户批准计划时队列中仍有尚未处理的输入（例如上一轮失败后遗留）
- **THEN** 执行输入入队后这些输入保留并按原顺序处理，不被丢弃，也不被提前到批准之前

### Requirement: 运行中不受理计划决定
会话有运行中的回答时，批准与要求修改 MUST 被明确拒绝并说明需等待本轮结束；被拒绝的决定不改变计划状态，也不进入队列。

#### Scenario: steer 使本轮继续
- **WHEN** 计划已提交，但排队的 steer 使本轮继续运行，此时用户点击批准
- **THEN** 请求被拒绝并提示运行仍在进行，计划状态不变，运行结束后可再次决定
