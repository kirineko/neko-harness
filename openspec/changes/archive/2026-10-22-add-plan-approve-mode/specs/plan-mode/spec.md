# Spec Delta

## Purpose

为会话提供只读的规划模式：agent 先在只读环境中调研并提交结构化计划，用户批准后才获得写权限并自动开始执行，使大改动在动手前可被审阅、修改或否决，并在多端、重启与停止时保持一致的授权边界。

## ADDED Requirements

### Requirement: 会话级规划模式
系统 SHALL 为每个会话维护 `normal` 或 `plan` 模式，缺省 `normal`。用户 SHALL 可在会话空闲时进入或退出 plan 模式；模式 MUST 持久保存，重启后保持，且只影响所属会话，不影响其他会话或子 agent 的独立配置。会话有运行中的回答时切换请求 MUST 被明确拒绝，不得改变当前运行的工具集。

#### Scenario: 进入与退出
- **WHEN** 用户在空闲会话中进入 plan 模式，之后手动退出
- **THEN** 进入后模型只看到只读工具与 `submit_plan`，退出后恢复进入前的完整工具集，且不留下未决计划

#### Scenario: 运行中切换
- **WHEN** 会话正在回答时用户请求进入或退出 plan 模式
- **THEN** 请求被拒绝并说明需先等待或停止当前运行，工具集与模式不变

#### Scenario: 重启保持
- **WHEN** 处于 plan 模式的会话在 gateway 重启后重新打开
- **THEN** 会话仍为 plan 模式，只读边界与待批准计划保持不变

### Requirement: 取消并退出计划模式
系统 SHALL 允许用户在会话空闲时一步「取消并退出 plan 模式」：当前待批准计划置为 cancelled，会话回到 normal 模式并恢复完整工具集，不提交任何执行输入，也不产生要求修改输入。该操作复用模式切换的语义：会话运行中 MUST 被拒绝；会话已处于 normal 且无待批准计划时重复调用 MUST 成功且不改变状态；与批准、要求修改并发时以首次有效结算为准。

#### Scenario: 待批准时取消并退出
- **WHEN** 会话有待批准计划，用户选择取消并退出 plan 模式
- **THEN** 计划变为已取消，会话回到 normal 模式，没有任何执行或修改输入被提交，所有端展示相同结果

#### Scenario: 已被其他端决定
- **WHEN** 用户取消并退出时该计划已被另一端批准
- **THEN** 以已结算的批准为准，不撤销执行，界面展示真实状态

### Requirement: 只读工具边界
plan 模式下系统 SHALL 不向模型提供 `edit`、`write` 与 `job`，并 MUST 在调用执行前拒绝这些工具，包括经其他工具嵌套发起的调用。`read`、文件搜索、联网搜索、`todo`、`ask_user`、受限 `bash` 与只读子 agent 角色 SHALL 保持可用。退出 plan 模式 MUST 恢复被移除的工具。

#### Scenario: 写工具被拒绝
- **WHEN** plan 模式下模型或嵌套脚本尝试调用 `edit`、`write` 或 `job`
- **THEN** 调用不产生任何文件或进程副作用，模型得到说明当前处于只读规划模式的错误结果

#### Scenario: 调研工具可用
- **WHEN** plan 模式下模型读取文件、搜索代码、联网搜索或向用户提问
- **THEN** 这些调用与 normal 模式行为一致

### Requirement: 只读 bash 白名单
plan 模式下 `bash` SHALL 只执行被判定为只读的命令。命令 MUST 先按 `;`、`&&`、`||`、`|` 与换行切段，每一段都命中只读白名单且不命中危险模式才放行；含命令替换（`$(`、反引号、`<(`）的命令 MUST 拒绝。白名单 SHALL 覆盖常见的文件查看、搜索、目录、系统信息、git 只读、包管理器只读与联网读取命令，并 MUST 排除会卡住终端的交互式命令（`top`、`htop`、`less`、`more`）。白名单之外的命令一律拒绝；白名单内程序的写入、上传与执行类参数（如 `find -delete|-exec`、`sed -i`、`sort -o`、`--output`、`curl` 的 `-o -O -d -X -T -F`、`awk` 的 `system(`）、输出重定向、heredoc 与后台 `&` 同样拒绝，引号内的文字不触发误判。拒绝时 MUST 把原因与命令回给模型，提示改用只读工具或向用户提问。

#### Scenario: 只读调研命令
- **WHEN** plan 模式下模型执行 `git log --oneline -20`、`rg "foo" src` 或 `ls | wc -l`
- **THEN** 命令按普通 bash 执行并返回结果

#### Scenario: 串联写入被拒绝
- **WHEN** 模型执行 `ls; rm -rf build`、`cat a > b` 或 `echo $(touch x)`
- **THEN** 整条命令不启动，模型得到被拒绝的原因

#### Scenario: 判定边界是护栏
- **WHEN** 命令不在白名单中，例如 `bun run test`
- **THEN** 命令不启动，模型被告知改用只读工具或在批准计划后再运行

### Requirement: 结构化提交计划
plan 模式下系统 SHALL 向主 agent 提供 `submit_plan` 工具，参数为标题、有序步骤列表与可选说明；normal 模式下 MUST NOT 向模型提供该工具，子 agent 也不得拥有。每次提交 SHALL 生成新的计划版本并持久保存，状态为待批准，同一会话上一版未结算计划置为 superseded，并结束本轮回答而不再请求模型。标题 ≤ 120 字符、步骤 1–30 条且每条 ≤ 500 字符、说明 ≤ 4000 字符，超限提交 MUST 作为工具错误返回模型，不产生计划版本。

#### Scenario: 提交并等待
- **WHEN** 模型在 plan 模式下调用 `submit_plan`
- **THEN** 产生一个待批准的新版本，本轮结束，会话进入"等待批准"而不是继续运行

#### Scenario: 修订产生新版本
- **WHEN** 上一版计划未批准时模型再次提交
- **THEN** 新版本成为当前待批准计划，旧版本显示为已被取代，旧版本上的决定被拒绝

#### Scenario: 超限与非法参数
- **WHEN** 提交的步骤为空、超过 30 条或某条超长
- **THEN** 返回工具错误，当前待批准计划与会话状态不变

### Requirement: 批准后自动执行
用户批准计划 SHALL 绑定计划版本，且只有当前待批准版本可被批准。批准 MUST 使会话退出 plan 模式、恢复完整工具集，并自动提交一条要求按已批准计划执行的输入，输入中 SHALL 包含已批准计划的完整步骤，使会话立即开始执行。相同版本的重复批准或重启后的恢复 MUST NOT 产生第二条执行输入。

#### Scenario: 批准并执行
- **WHEN** 用户批准当前待批准计划
- **THEN** 会话退出 plan 模式，并以已批准计划为依据开始新一轮执行，工具集包含写工具

#### Scenario: 批准中途重启
- **WHEN** 批准已保存但执行输入提交前 gateway 重启
- **THEN** 恢复后会话仍然退出 plan 模式，且执行输入恰好提交一次

#### Scenario: 过期版本被批准
- **WHEN** 客户端对已被取代的版本提交批准
- **THEN** 请求被拒绝并返回该版本的最终状态，不退出 plan 模式、不启动执行

### Requirement: 要求修改
用户 SHALL 可对当前待批准计划选择要求修改并给出文字反馈（1–2000 字符）。要求修改 MUST 使计划置为 revision_requested，会话保持 plan 模式，并把反馈作为输入提交让模型修订；同一版本的重复请求 MUST 幂等。

#### Scenario: 反馈驱动修订
- **WHEN** 用户对待批准计划提交"第 2 步拆开"并要求修改
- **THEN** 会话仍为 plan 模式，模型收到该反馈并可再次调研与提交新版本

#### Scenario: 空反馈
- **WHEN** 要求修改时反馈为空或超长
- **THEN** 请求被拒绝，计划仍为待批准

### Requirement: 结算竞争与失效
对同一计划版本的决定 SHALL 原子结算，首次有效决定生效，重复或冲突提交返回已结算记录。停止会话、归档会话或重启对账发现待批准计划所属会话已停止时，计划 MUST 置为 cancelled，迟到的批准或修改 MUST NOT 启动任何执行。

#### Scenario: 双端同时决定
- **WHEN** Web 批准与 TUI 要求修改同时到达同一版本
- **THEN** 只有一个决定生效，两端最终展示相同结果

#### Scenario: 停止后迟到批准
- **WHEN** 用户停止会话后另一端才提交批准
- **THEN** 返回 cancelled 状态，不退出 plan 模式、不提交执行输入

### Requirement: 普通输入取代待批准计划
会话处于待批准时，用户直接发送的普通输入 SHALL 被正常受理并取代待批准计划，不视为批准；会话保持 plan 模式，模型据此继续调研。

#### Scenario: 用户直接补充需求
- **WHEN** 待批准期间用户在输入框发送新的文字
- **THEN** 当前计划置为 superseded，不退出 plan 模式，模型在 plan 模式下继续回答

### Requirement: 规划模式提示
进入 plan 模式 SHALL 向模型呈现模式说明：处于只读规划、可用工具范围、需通过 `submit_plan` 提交计划且不得自行开始修改。该说明随模式切换进入或移出模型上下文，不写入用户可见的普通消息。

#### Scenario: 模式切换对模型可见
- **WHEN** 进入或退出 plan 模式后下一次请求
- **THEN** 模型上下文反映工具集与模式说明的变化，不残留旧模式的指令

### Requirement: 计划资源上限
计划相关的数值上限 SHALL 集中在单一纯模块并与本 spec 保持一致：标题 120、步骤数 30、单步 500、说明 4000、反馈 2000 字符。网关、移动端与前端 MUST 使用同一份上限，不单独硬编码。

#### Scenario: 上限一致
- **WHEN** 任一端展示或校验计划与反馈长度
- **THEN** 使用的上限与本 spec 一致
