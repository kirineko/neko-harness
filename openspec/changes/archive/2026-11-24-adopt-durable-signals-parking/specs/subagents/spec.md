# Spec Delta

## MODIFIED Requirements

### Requirement: 委派取消与恢复
委派及子会话 SHALL 持久关联，恢复同一次调用 MUST 复用原子会话与已受理输入。在并发配额排队、主会话等待子任务结算或子会话等待人工审批期间，即使宿主进程连续多次异常退出并重开，等待状态 SHALL 持久保持而不消耗任务重启上限。停止主会话 SHALL 级联停止本轮全部子任务；单独停止 SHALL 精确取消当前轮，不停止兄弟任务，主 agent 获得取消结果。取消清理结束且当前轮任务终态后，子 agent 身份和上下文 SHALL 保留并可接续。浏览或断开前端 MUST NOT 取消执行。取消 MUST NOT 被宣称回滚已发生的文件修改。

#### Scenario: 重启时任务未完成
- **WHEN** gateway 在派发后、结果回传前重启
- **THEN** 沿原生任务恢复语义继续或报告中断，不重复创建子会话、重复提交任务或无条件重放有副作用的工具

#### Scenario: 等待期连续异常重启
- **WHEN** 委派轮次处于并发配额排队或等待子任务完成期间，宿主进程连续异常退出并重开超过任务重启上限次数
- **THEN** 主会话的委派等待与排队中的轮次均不被计为任务崩溃中断，配额释放或子任务正常结算后按原委派返回最终结果

#### Scenario: 单独停止和全局停止
- **WHEN** 用户停止一个子任务或停止正在等待的主会话
- **THEN** 前者仅停止目标并保留兄弟任务，后者停止所属子任务并保留可查看的已产生记录

#### Scenario: 接续轮停止后再使用
- **WHEN** 子 agent 第二轮被停止，随后同一主会话向它提交第三轮
- **THEN** 第二轮的实际执行与审批等待均已停止，第三轮使用保留上下文；旧停止请求不得停止第三轮

#### Scenario: 清理期间重启
- **WHEN** 停止接续轮的过程中 gateway 重启
- **THEN** 恢复取消清理，直到该轮终态和子会话空闲前不开放新轮，不能仅因主 agent 的等待结束而留下脱离归属的工作
