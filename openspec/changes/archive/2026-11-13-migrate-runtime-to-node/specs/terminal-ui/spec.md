# Spec Delta

## MODIFIED Requirements

### Requirement: TUI 升级感知与版本查看

TUI SHALL 提供简洁英语升级提示及 `/version` 查看入口，区分可安装更新、需重启 TUI 和需重启 gateway。提示 SHALL 给出实际可执行的下一步，同一状态不重复打扰。界面 MUST NOT 执行安装或自动重启，不将更新提示写入对话或发送给模型；输入、任务与常驻状态栏保持可用。版本概览 SHALL 默认只显示当前 TUI 版本、准确状态与必要操作；内部组件版本 SHALL 经独立详情入口按需查看。

#### Scenario: 新版本可用
- **WHEN** 后台确认稳定渠道有高于已安装版本的新版本
- **THEN** 显示简短版本提示；Windows 给出 `npm install -g neko-harness@latest`，macOS/Linux 给出 `neko update`，用户在另一个终端或退出界面后自行执行，不将命令作为聊天输入代为运行

#### Scenario: 网关仍旧
- **WHEN** 安装已升级，当前连接的 gateway 仍旧
- **THEN** 提示重新启动本地 neko，并经版本查看入口说明需关闭网关拥有者；复用方不暗示仅重启自己即可更新网关

#### Scenario: TUI 仍旧
- **WHEN** gateway 或已安装版本更新，TUI 仍运行旧构建且协议兼容
- **THEN** 提示退出后运行 `neko tui`，继续保留当前编辑与任务，不因单纯版本差异中断使用

#### Scenario: 查看与检查失败
- **WHEN** 用户输入 `/version` 并查看版本或主动检查更新
- **THEN** 默认查看当前版本及状态，经独立详情入口可查看 TUI、gateway、安装与渠道版本，支持退出查看返回原编辑流程；检查失败显示简短重试说明，不宣称已最新

#### Scenario: 窄窗口与提示去重
- **WHEN** 界面在 80x24 或 60x16 下收到重复状态广播，或用户切换会话
- **THEN** 提示不挤出输入和状态栏，不为每个会话重复弹出；版本状态改变后更新提示并移除已解决提醒

#### Scenario: 默认概览与条件提示
- **WHEN** 用户查看版本概览
- **THEN** 不平铺安装、网关和渠道版本，不固定展示安装命令与整段重启说明；仅有可安装更新时显示目标版本和平台对应命令，仅有待重启状态时显示所需重启操作，多种差异仍优先解决旧运行组件

#### Scenario: 未知和开发状态
- **WHEN** 尚未完成更新检查、安装或网关信息缺失、检查失败或运行开发构建
- **THEN** 分别显示简洁英语的未检查、不可用、失败或开发状态，不将缺失信息解释为 Up to date；仍允许返回编辑和在适用时重试检查

#### Scenario: 详情返回
- **WHEN** 用户进入版本详情并按 Esc 返回或关闭面板
- **THEN** 逐层返回概览选择流程及原编辑器，保留草稿和当前会话，不触发聊天、安装或重启
