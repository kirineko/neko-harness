# terminal-ui Specification

## Purpose

终端交互前端：在 TUI 中与持久会话对话，支持流式渲染、steer/follow-up 与会话管理。

## Requirements

### Requirement: 交互式对话

系统 SHALL 提供终端交互界面，用户可提交输入并看到流式回答、工具调用及其输出。

#### Scenario: 流式渲染

- **WHEN** 用户提交输入
- **THEN** 回答文本与工具输出随到达即时渲染，而非等待整轮结束

### Requirement: 消息插话

系统 SHALL 支持在 agent 工作中提交消息：忙时提交一律排队（follow-up，等待当前 run 结束），与 Web、移动端一致；已排队的消息可再被改为 steer（插入当前工具轮之后）或撤回。提交时 MUST NOT 要求预先选择 steer。

#### Scenario: steer 打断

- **WHEN** agent 执行中用户提交消息，随后把该排队消息改为 steer
- **THEN** 该消息在当前工具轮结束后加入进行中的工作

#### Scenario: 默认排队

- **WHEN** agent 执行中用户按 Enter 提交消息
- **THEN** 该消息排队，在当前回答结束后开始下一轮

### Requirement: 会话管理
系统 SHALL 支持在终端中列出、切换、fork 当前工作区会话，并显示当前会话的模型、用量与忙碌状态。工作区 SHALL 由显式 `--cwd` 或 TUI 启动目录确定，不自动扩大到 Git 根目录。启动 SHALL 恢复当前工作区最近使用的非归档会话，无匹配则新建；新建与 fork SHALL 保持工作区。

#### Scenario: 切换会话
- **WHEN** 用户从会话列表选择另一会话
- **THEN** 界面切换到该会话的完整记录与当前状态，列表仅包含当前工作区会话

#### Scenario: 不同目录启动
- **WHEN** 从 B 启动 TUI，但网关已有 A 的会话
- **THEN** 恢复 B 最近使用的会话或新建 B 会话，不自动 attach A 的会话

#### Scenario: 显式目录
- **WHEN** 从 A 启动并指定 `--cwd B`
- **THEN** B 成为规范化的工作区，文件补全和工具默认目录与状态栏一致

#### Scenario: 归档最后一个会话
- **WHEN** 当前工作区最后一个会话被归档
- **THEN** 在同一工作区新建会话，不切换到其他工作区

### Requirement: 常驻状态栏
TUI SHALL 在正常可用尺寸下持续显示工作区、模型、thinking 与运行状态，并提供紧凑用量和上下文快捷键信息。输入、流式输出、补全和选择面板 MUST NOT 将状态栏挤出屏幕；窄屏 SHALL 优先保留工作区和运行状态。

#### Scenario: 空闲与流式显示
- **WHEN** TUI 启动、输入普通文本或斜杠命令、接收长回答或工具输出
- **THEN** 状态栏持续可见并更新，不依赖命令菜单触发

#### Scenario: 窗口调整
- **WHEN** 窗口在 120x40、80x24 和 60x16 之间切换
- **THEN** 状态栏与输入保持可见，无越界或重叠，低优先级信息按空间隐藏

#### Scenario: 极小窗口
- **WHEN** 窗口小于 40 列或 10 行
- **THEN** 显示简短英语尺寸提示并保留退出能力，恢复尺寸后恢复界面与草稿

### Requirement: 一致的终端显示语言
TUI 自有命令说明、状态、操作提示、选择面板与错误上下文 SHALL 使用英语；用户内容、模型回答及原始工具输出 MUST 保留原文。明暗主题 SHALL 使用一致的语义角色，焦点和选中状态不能仅靠颜色识别；快捷键提示 MUST 对应实际行为。

#### Scenario: 忙碌快捷键
- **WHEN** agent 正在运行
- **THEN** 提示 Enter Queue、Esc Stop，Ctrl+C 若中止运行则不得标为退出；有排队消息时排队区提示 Alt+↑ 可选择

#### Scenario: 非英语内容与主题切换
- **WHEN** 用户提交中文并切换明暗主题
- **THEN** 用户内容保持中文，产品控件保持英语，选中项有可见标记且文本可读

### Requirement: 统一选择面板
模型与会话选择 SHALL 使用一致的面板，限制在聊天区域，保留输入与状态栏。面板 SHALL 支持搜索、可滚动列表、明确的当前项与选中项、固定可见的操作提示，并随窗口调整保证选中项可见。斜杠补全 SHALL 靠近输入区展示。

#### Scenario: 长列表与小窗口
- **WHEN** 选项超过可用行数或终端缩小
- **THEN** 列表滚动而非裁掉面板尾部，当前选中项与 Enter/Esc 提示保持可见，长标签不溢出

#### Scenario: 取消与选择
- **WHEN** 用户取消或确认选择
- **THEN** 面板关闭并恢复输入焦点和原有草稿；仅确认后执行选择操作

#### Scenario: 加载与失败
- **WHEN** 模型列表加载缓慢、加载失败或搜索无结果
- **THEN** 面板分别显示 Loading、可理解的错误或 No results，用户均可取消；失败可重试

#### Scenario: 快速重复触发
- **WHEN** 用户重复打开面板或取消后异步列表返回
- **THEN** 至多存在一个面板，过期结果不重新打开面板、不夺取焦点

### Requirement: 可辨识的会话列表

TUI `/sessions` 与 `/session` SHALL 使用相同的当前工作区会话列表，按最近消息时间倒序排列，无消息时使用创建时间，同时间按 ID 稳定倒序。行内 SHALL 展示生成标题或首问摘要、相对时间及当前会话标记；选中项详情 SHALL 提供模型、运行状态与准确时间，MUST NOT 展示内部会话 ID。搜索 SHALL 匹配标题、首问摘要及 ID，产品标签保持英语，标题保留对话语言。

#### Scenario: 浏览与搜索

- **WHEN** 用户打开会话面板并输入标题关键词或会话 ID
- **THEN** 仅筛选当前工作区会话，保留当前项与键盘选中项的明确区分；只查看会话不改变消息排序

#### Scenario: 后台更新

- **WHEN** 面板打开期间标题、状态或消息时间更新导致重排
- **THEN** 以会话 ID 保持原选中项和可见位置，不因下标变化误选其他会话；选中项消失时选择有效邻项，过期结果不重开已关闭面板

#### Scenario: 小窗口与长标题

- **WHEN** 在 120x40、80x24 和 60x16 的终端显示长标题及大量会话
- **THEN** 优先保留标题、相对时间和当前标记，详情按可用空间收缩，选中项、操作提示、输入和状态栏保持可见

#### Scenario: 相对时间刷新

- **WHEN** 面板保持打开且时间经过
- **THEN** 时间文字自动刷新但不移动选中项；关闭面板后停止其定时刷新

### Requirement: 登录配置

TUI SHALL 提供 `/login` 面板，以两级结构管理凭据：第一级为 provider 列表，覆盖内置模型 provider 目录与单独分组的联网搜索凭据（Tavily 与 DeepSeek），以英语显示每项的启用状态、生效来源（含 keyless 等受限来源）与环境变量配置状态，支持过滤；第二级为所选 provider 的遮罩密钥输入、保存、移除保存值及对应申请链接引导入口。DeepSeek SHALL 同时出现在「Model providers」与「Web search」分组，两处是同一份凭据：来源与状态一致，任一处保存或移除后另一处同步，进入后是同一个密钥输入。模型 provider SHALL 可在列表中切换启用（DeepSeek 始终启用且不可取消），启用状态与 Web 同步；「Web search」分组中的项没有启用开关。密钥 MUST 通过独立输入收集，不作为命令参数或聊天内容。面板 SHALL 保留输入和状态栏，取消后恢复聊天草稿与焦点。

第二级输入非空时 ←/→ SHALL 执行光标移动；返回 provider 列表（Esc 或 Tab）MUST NOT 丢弃未保存的输入。遮罩显示 SHALL 提供可确认粘贴完整性的信息（如已输入字符数），不只渲染星号。面板持有焦点时，密钥输入行 SHALL 在插入点显示与编辑器一致的硬件光标（终端不支持时回退为反色软件光标），遮罩 MUST NOT 因光标泄露密钥内容。保存前 SHALL 自动去除首尾空白；含内部控制字符的密钥 SHALL 以具体原因拒绝。保存或移除失败 SHALL 显示服务端具体错误（不含密钥）；保存或移除成功 SHALL 短暂确认后自动关闭面板并恢复聊天焦点。移除已保存密钥 MUST 经面板内联确认后才执行。

#### Scenario: 首次配置

- **WHEN** 未配置 Key 的用户启动 TUI 并执行 /login，选择 DeepSeek
- **THEN** 可输入并保存 Key，成功后清除敏感输入、短暂显示确认并自动关闭面板，无需重启即可对话

#### Scenario: 启用并配置其他 provider

- **WHEN** 用户在 /login 列表中启用 OpenRouter，进入其输入并保存 Key
- **THEN** OpenRouter 模型出现在 `/model` 列表中且可选；取消启用后其模型从列表消失，已保存 Key 保留

#### Scenario: 锁定 DeepSeek

- **WHEN** 用户尝试取消启用 DeepSeek
- **THEN** 面板拒绝并说明 DeepSeek 始终启用，状态不变

#### Scenario: 切换 provider

- **WHEN** 用户在输入部分内容后返回列表并选择 Tavily
- **THEN** 面板显示 Tavily 的环境变量状态与生效来源（未配置时为 keyless 受限），未保存的输入保留

#### Scenario: 搜索分组中的 DeepSeek

- **WHEN** 用户打开 /login，在「Web search」分组选中 DeepSeek 并按 Enter
- **THEN** 进入 DeepSeek 的密钥输入，保存后「Model providers」分组中的 DeepSeek 同步显示已保存；在该分组按 Space 不切换任何状态并提示它共用 DeepSeek 凭据

#### Scenario: 过滤同时匹配两个分组

- **WHEN** 用户在过滤框输入 deepseek
- **THEN** 列表中 DeepSeek 在两个分组各出现一次，高亮与 Enter 作用于当前高亮的那一行

#### Scenario: 方向键光标移动

- **WHEN** 用户粘贴 Key 后按 ←/→
- **THEN** 光标在输入内移动，内容与当前 provider 均不变化

#### Scenario: 粘贴确认与清洗

- **WHEN** 用户粘贴带首尾空白的长 Key，或粘贴内容含换行等内部控制字符
- **THEN** 前者自动去除首尾空白后可保存；后者以具体原因（如包含换行）拒绝且不改动原凭据；遮罩行始终显示已输入字符数供确认完整性

#### Scenario: 取消和失败

- **WHEN** 用户取消面板或保存失败
- **THEN** 取消不改变凭据并清空敏感输入；失败保留原凭据并显示服务端具体错误与可重试提示，错误不含密钥

#### Scenario: 移除需确认

- **WHEN** 用户对已保存 Key 的 provider 触发移除
- **THEN** 面板先显示内联确认，确认后才移除；取消确认不改变凭据

#### Scenario: 聚焦时显示输入光标

- **WHEN** 用户打开 /login 面板且面板持有焦点
- **THEN** 密钥输入行在插入点显示与编辑器一致的闪烁光标；面板失焦或关闭后光标回到聊天编辑器，渲染输出与文字提取不泄露光标标记或密钥内容

#### Scenario: 小窗口与关闭

- **WHEN** 用户在 80x24 或 60x16 下打开面板、粘贴长 Key，或关闭后异步结果到达
- **THEN** 输入保持遮罩且无越界，操作和状态栏可访问，关闭后的响应不重开面板或夺取焦点

### Requirement: 基于模型能力的思考选择

TUI SHALL 使用网关提供的 Pi 1.2.0 能力列表显示当前模型的思考选项。`/think` SHALL 打开选择面板，`/think <level>` SHALL 仅接受当前列表内的值；无效值提供有效选项提示。模型切换造成的强度调整 SHALL 与 Web 一致，状态栏显示服务端确认的实际值。

#### Scenario: Pro 强度选择

- **WHEN** Pi 1.2.0 下当前模型为 Pro，用户打开 /think 或输入 /think low
- **THEN** 面板仅列 off/high/max；low 命令被拒绝并提示有效选项，不伪装为已设置 low

#### Scenario: 切换与同步

- **WHEN** Flash low 切为 Pro，或 Web 改变同一会话强度
- **THEN** TUI 展示服务端确认的配置，模型切换按 Pi 调整为 high，取消选择保留原配置与草稿

### Requirement: 终端手动压缩与状态

TUI SHALL 支持精确的 `/compact` 命令及可选附加要求，将其作为会话操作而非消息。状态栏 SHALL 使用英语区分压缩、等待压缩和重试，最终结果以服务端确认为准，不显示虚假百分比。编辑器保持可用，发送、中止和排队遵循 pi-durable，而非复制其他客户端的会话引擎。

#### Scenario: 命令与继续输入

- **WHEN** 用户在空闲或运行中执行 /compact，随后继续编辑或提交消息
- **THEN** 压缩命令不进入聊天或改变消息排序，输入不被清空覆盖，后续消息沿用已有 steer/follow-up 语义

#### Scenario: 中止和小窗口

- **WHEN** 压缩期间用户按 Esc，或将终端缩小至 80x24、60x16
- **THEN** 无弹层时按原生会话中止范围操作并显示准确提示；有弹层时先关闭弹层；输入、状态栏和有效操作保持可见

### Requirement: Pi 风格图片输入

TUI SHALL 提供 macOS/Linux Ctrl+V、Windows Alt+V 的剪贴板入口，依次尝试支持的文件路径、图片和文本，并支持拖入图片路径及路径补全。被识别的待发图片 SHALL 在编辑器中有明确可编辑引用，删除引用即移除附件；普通路径文字不能未经识别确认就作为图片发送。读取失败 MUST 保留草稿。Windows 下路径解析 MUST NOT 把 `\` 当作转义符。

#### Scenario: 粘贴与路径

- **WHEN** 粘贴截图、复制的图片文件或拖入带空格及引号的图片路径
- **THEN** 显示已识别引用并允许继续输入文字；纯文本粘贴仍为文字，图片内容与文字一并提交

#### Scenario: Windows 反斜杠路径

- **WHEN** Windows 用户输入或拖入 `D:\code\img.png` 形式的反斜杠路径
- **THEN** 路径被完整识别为图片引用，反斜杠不被吞掉或破坏

#### Scenario: 终端能力不足

- **WHEN** 系统剪贴板不可用或终端不支持图片渲染
- **THEN** 剪贴板失败提供路径方式提示；历史图片回退为文件名、格式与尺寸，仍可正常对话

#### Scenario: 发送确认与会话切换

- **WHEN** 发送失败、仅发图片或读取期间切换会话
- **THEN** 仅图片可发送，失败保留引用；确认受理后清除对应草稿，迟到读取不串入新会话

### Requirement: 终端图片展示与临时资源

TUI SHALL 按终端能力展示图片预览或文字回退，保持常驻输入与状态栏；统一 read 工具的图片卡 SHALL 显示路径、格式、实际保存尺寸及原生处理诊断，能力占位符或失败不得伪装为模型已看见图片。剪贴板临时资源 MUST 由应用独立管理，发送重试期间保留，草稿取消或受理后清理，不能删除用户原文件。

#### Scenario: 历史预览与清理

- **WHEN** 图片消息已持久化、用户取消图片草稿或终端恢复 Pi 1.2.0 创建的会话
- **THEN** 释放应用拥有且无草稿引用的临时资源（内存实现不生成文件）；历史从持久数据恢复，预览不挤出输入区或打印 base64

#### Scenario: read 图片与无图片终端

- **WHEN** read 返回经过缩放或转换的图片，或终端不支持图片渲染
- **THEN** 工具卡显示实际处理结果；支持时展示图片，不支持时以名称、格式、尺寸回退，输入与状态栏仍可见

### Requirement: 终端工作区引用补全

TUI SHALL 在输入 @ 时展示工作区文件候选，沿用 Pi 的上下选择、Tab/Enter 接受、Esc 关闭；接受 MUST NOT 同时发送，目录保留尾斜杠。补全 MUST 保留撤销、光标、图片转换和常驻状态栏，自有提示使用英语。正常安装后无需 fd；枚举不完整、候选过多和文件发现失败 SHALL 分别反馈，不误报无匹配或要求安装 fd。失败保留草稿，不阻塞普通消息、斜杠命令或手动路径。

#### Scenario: 文件与目录选择

- **WHEN** 用户输入 @ 并以 Tab 或 Enter 选择文件或目录
- **THEN** 文件被补全且可继续编辑，目录可继续定位或作为引用发送；带空格路径及已有后缀文字不被破坏

#### Scenario: 目录连续定位

- **WHEN** 用户以 Tab 或 Enter 接受 @ 目录候选
- **THEN** 自动查询该目录的下一级路径，无需删除或重新输入尾斜杠；保留路径引号、光标及已有后缀，接受操作不发送消息，取消或切换会话后迟到结果不重开面板

#### Scenario: 取消优先级

- **WHEN** 候选打开且回答正在运行，用户按 Esc
- **THEN** 本次按键仅关闭候选，不停止运行、不清空草稿；候选关闭后的停止和空闲双击清空行为保持可用

#### Scenario: 依赖缺失

- **WHEN** 随包文件发现组件缺失、不可执行或启动失败时触发 @ 补全
- **THEN** 显示可重试的文件发现不可用提示，不指导安装 fd，不阻塞普通消息、斜杠命令或手动路径

#### Scenario: 小窗口和图片

- **WHEN** 在 120x40、80x24、60x16 中浏览长路径候选，或选择带空格的图片路径后切换会话
- **THEN** 输入和状态栏始终可见，选中候选可见；图片仅进入原会话草稿，失败保留原输入且可重试

#### Scenario: 不完整与恢复

- **WHEN** 枚举截断而没有匹配，或故障恢复后重新查询
- **THEN** 截断时提示范围过大并引导指定子目录，恢复后可得到新候选，迟到响应不重开已关闭面板

### Requirement: 技能命令补全

TUI SHALL 在输入 `/skill:` 前缀时提供当前会话技能的动态补全，条目为 `skill:<name>` 并展示技能 description；技能列表在会话切换后刷新。提交 `/skill:...` 输入时 MUST 原样发送，展开由 core 完成。

#### Scenario: 补全技能名

- **WHEN** 用户输入 `/skill:p`
- **THEN** 补全候选包含名称以 p 匹配的技能，附描述

#### Scenario: 原样提交

- **THEN** TUI 把原文发送给 gateway，不在本地展开

#### Scenario: 切换会话

- **WHEN** 用户切换到另一个工作区的会话
- **THEN** 补全候选反映新会话的技能列表

### Requirement: TUI 技能调用消息展示

TUI SHALL 依据服务端投影的结构化技能元数据将成功展开的技能调用折叠为单行标记：技能图标、`skill:<name>`、单行截断的参数预览与来源路径提示，不铺开正文。无参数时只显示技能行；无技能元数据的输入 MUST 原样渲染，不从 XML 文本反向识别，不丢失内容。标记文本 SHALL 使用英语（TUI 语言约定）。

#### Scenario: 单行折叠

- **WHEN** 用户提交 `/skill:pdf 总结它` 且技能命中展开
- **THEN** 消息流中该用户消息显示为单行技能标记（含参数预览），正文不出现

#### Scenario: 无参数调用

- **WHEN** 用户提交 `/skill:pdf`
- **THEN** 只显示技能行，无参数预览

#### Scenario: 解析失败回退

- **WHEN** 用户消息以 `<skill` 开头但没有成功展开的结构化技能元数据
- **THEN** 按原样渲染，内容完整可见，即使 XML 外观符合技能块也不解析为调用

#### Scenario: 元数据恢复

- **WHEN** TUI 打开重启或分叉后的 Pi 1.2.0 会话，技能正文及参数含有 XML 标记
- **THEN** 直接从持久展示数据恢复技能行及参数预览，正文和参数边界不受 XML 内容影响

### Requirement: TUI 技能市场面板

TUI SHALL 提供 `/skills` 命令打开技能市场面板：沿用统一选择面板的搜索与滚动交互，按分类分组展示市场技能（组头为不可选中行），条目右栏显示来源、版本与项目级/用户级/内置状态标记。面板加载、失败与空结果 SHALL 各有明确反馈，失败可重试。面板文本 SHALL 使用英语（TUI 语言约定），技能名称与描述保留原文。

#### Scenario: 打开市场面板

- **THEN** 打开市场面板，按分类分组列出技能，可输入过滤

#### Scenario: 状态标记

- **WHEN** 某技能已安装到用户级或为内置技能
- **THEN** 条目右栏显示对应标记

#### Scenario: 加载失败

- **WHEN** 市场请求失败
- **THEN** 面板显示错误与重试提示，不静默消失

### Requirement: TUI 市场详情与安装交互

市场面板中选中技能进入详情视图：显示完整描述、元数据与两级安装状态，并提供键位安装到用户级、安装到项目级、卸载与预览 SKILL.md 正文（Markdown 渲染的滚动视图）。覆盖与卸载 SHALL 在面板内联确认后才执行；内置技能不提供安装/卸载键位。详情、预览与确认视图的操作提示 SHALL 以配色区分键位与说明文字，键位可辨识。Esc 逐层返回列表与关闭面板。

#### Scenario: 查看详情

- **WHEN** 用户在列表中选中技能并确认
- **THEN** 面板切换为详情视图，显示描述、元数据与安装状态

#### Scenario: 键位安装

- **WHEN** 用户在详情视图按安装到用户级的键位
- **THEN** 执行对应安装；目标已存在时先内联确认覆盖

#### Scenario: 预览正文

- **WHEN** 用户在详情视图按预览键位
- **THEN** 面板以 Markdown 渲染 SKILL.md 正文（标题、列表等有样式），可滚动，Esc 返回详情

#### Scenario: 键位可辨识

- **WHEN** 详情、预览或确认视图显示操作提示
- **THEN** 键位字母与说明文字配色不同，键位一眼可辨

#### Scenario: 逐层退出

- **WHEN** 用户在详情或预览视图按 Esc
- **THEN** 返回上一层，列表视图再按 Esc 关闭面板

### Requirement: 终端编辑光标

TUI SHALL 遵循已安装 Pi 1.2.0 的编辑器和输入组件光标行为。启用硬件光标时 MUST 不重复绘制反色软件光标；屏幕渲染和用于断言的文字提取 MUST 不泄露内部光标标记，保持输入、选择面板与登录面板可操作。

#### Scenario: 硬件光标与软件光标

- **WHEN** 用户在硬件光标开启或关闭的 TUI 中编辑输入并打开选择或登录面板
- **THEN** 焦点处只有所选模式的光标，光标位置正确，内部标记不作为文字或可见宽度出现

### Requirement: 品牌终端主题

TUI SHALL 保留 auto/light/dark 三种偏好。浅色 SHALL 保持现有 sakura/tianyi/ink 蓝粉白配色；深色 SHALL 使用独立的冷灰蓝配色与清晰文字层级，不要求与浅色同源。语义槽位 SHALL 覆盖文本、表面、强调、状态、边框、diff 与语法高亮；组件 SHALL 只引用语义槽位。`--theme`、环境变量、配置及自动检测入口保持兼容；`/theme` SHALL 即时切换，auto 恢复跟随终端。选中与焦点 MUST NOT 仅靠颜色辨识，切换 MUST 保留用户交互状态。

#### Scenario: 明暗主题同源

- **WHEN** 在深色与浅色终端分别以 auto 启动 TUI 或收到终端明暗变化通知
- **THEN** 浅色使用原蓝粉白配色，深色使用优化后的冷灰蓝主题；仍只有 auto/light/dark，不增加主题选项；无法检测时沿用现有浅色回退

#### Scenario: 槽位一致性

- **WHEN** 渲染用户气泡、工具卡、选择面板、编辑器边框、通知与代码块
- **THEN** 颜色均来自语义槽位，切换主题后全部组件随之变化，无残留硬编码颜色

#### Scenario: 选中不只靠颜色

- **WHEN** 用户在任意明暗主题下浏览选择面板
- **THEN** 选中项同时具有符号前缀与底色，去除颜色后仍可辨识

#### Scenario: /theme 进程内选择

- **WHEN** 用户执行 /theme 并选择 auto、light 或 dark
- **THEN** 主题立即套用且面板标注当前项；选择 auto 恢复终端背景检测与跟随，选择明确明暗停止跟随；不写出任何配置文件

#### Scenario: 深色文字与表面可读性

- **WHEN** 在 truecolor 深色主题下查看自绘面板、用户消息、工具卡和代码块
- **THEN** 默认前景与背景成对定义；正文、工具输出、可操作提示、辅助说明和代码注释在实际配对背景上对比度不低于 4.5:1；装饰边框不作为正文验收；工具状态仍以文字或图标辨识

#### Scenario: 深色代码分类

- **WHEN** 深色主题显示包含关键字、函数、字符串、数字及类型的已支持语言代码
- **THEN** 使用可辨识的紫、蓝、绿、橙及青色语法层级；普通代码为中性浅色，注释可读，diff 增删保留明确标记与状态色

#### Scenario: 终端背景与颜色降级

- **WHEN** 用户在纯黑、灰黑或深蓝终端背景中使用 dark，或终端只支持 256 色
- **THEN** 主画布保持终端背景，不改写终端全局配色；文字、选中项和状态仍可辨识，256 色沿现有能力降级，不要求与 truecolor 精确同色

#### Scenario: 已显示内容切换

- **WHEN** 已有历史消息、展开的 Thinking 或工具卡、面板内容、草稿和滚动位置时切换主题
- **THEN** 已着色文字、代码与背景完整更新，不残留旧主题；草稿、光标、展开状态、面板上下文和滚动位置保持，不触发模型请求或重新提交

#### Scenario: 迟到的自动检测

- **WHEN** auto 检测尚未结束时用户选择明确的 light 或 dark，或切换后旧检测结果才返回
- **THEN** 旧结果不得覆盖当前手动选择；重新选择 auto 后仅接受当前有效检测与通知

### Requirement: Markdown 语法高亮

TUI SHALL 对所有 Markdown 渲染处的围栏代码块按语言进行语法高亮,高亮色来自语法槽位并与主题联动。无语言标识或语言未识别 SHALL 回退为单色平涂;非常用语言 SHALL 后台懒加载,不阻塞首帧渲染。代码块底色 SHALL 铺满 Markdown 内容宽度(不足处补齐,空行同样铺底),而非仅覆盖文字宽度。

#### Scenario: 常见语言高亮

- **WHEN** 助手回答包含带语言标识的代码块(如 ```ts)
- **THEN** 关键字、字符串、注释、数字等元素以语法槽位颜色区分,主题切换后颜色随主题更新

#### Scenario: 未知语言回退

- **WHEN** 代码块无语言标识或标识不在支持列表
- **THEN** 代码块以单色代码样式渲染,不报错、不缺失内容

#### Scenario: 懒加载不阻塞

- **WHEN** 启动后首条回答立即包含非常用语言代码块
- **THEN** 界面先以可用方式渲染,语言注册完成后不晚于下次渲染生效,启动与首帧不被高亮加载阻塞

#### Scenario: 底色铺满

- **WHEN** 代码块含长短不一的行或空行(高亮或平涂路径)
- **THEN** 每行底色铺满 Markdown 内容宽度,空行同样铺底,视觉为整幅色块而非碎条

### Requirement: 排版节奏与状态字形

TUI SHALL 使用统一的排版节奏:顶层消息块之间有固定空行,工具卡色块内有水平内边距且与助手正文左缘对齐。工具与通知状态 SHALL 使用统一字形表:待执行 `…`、运行中动画帧、成功 `✓`、失败 `✗`,运行动画仅在存在运行中工具时推进。流式块让位给正式条目时 MUST NOT 遗留多余空行。工具卡 SHALL 默认折叠为单行标题(有输出时附行数提示),点击展开参数详情与输出原文全文。

#### Scenario: 块间节奏

- **WHEN** 转录渲染连续的用户消息、助手回答与工具卡
- **THEN** 相邻顶层块之间有一行空行(首条除外),工具卡内容不贴色块边缘,且与助手正文左缘对齐

#### Scenario: 工具状态字形

- **WHEN** 工具调用经历待执行、运行中、成功与失败
- **THEN** 各相位显示字形表对应符号与语义色,失败使用 `✗` 而非 ASCII 替代字符

#### Scenario: 运行动画按需推进

- **WHEN** 存在运行中工具卡,或全部工具结束
- **THEN** 运行中卡片的动画帧在工具运行期间推进,全部结束后无后台定时器继续驱动重绘

#### Scenario: 流式块让位

- **WHEN** 流式回答块被正式 assistant 条目替换
- **THEN** 流式块连同其间距一并移除,用户消息与正式条目之间恰为一行空行,无双倍空行

#### Scenario: 工具卡单行折叠

- **WHEN** 任意工具(含 web_search)执行完成且输出多行
- **THEN** 卡片默认仅占一行,附 `+N lines` 弱化提示;点击后展开参数详情与输出原文全文,再次点击收起

### Requirement: 忙碌动画行与通知分级

TUI SHALL 在转录与输入区之间提供仅忙碌时可见的动画状态行,显示 spinner 与当前状态文案,且不挤出输入区与状态栏。通知 SHALL 分信息、警告、错误三级,以各自语义色与符号前缀区分,自动消失行为不变。

#### Scenario: 忙碌行可见性

- **WHEN** agent 开始与结束工作(含压缩)
- **THEN** 忙碌时状态行出现并动画,结束后消失;输入区与常驻状态栏始终可见

#### Scenario: 三级通知

- **WHEN** 触发提示性、警示性与失败类通知(如能力提示、模型不含图片输入、网关断开)
- **THEN** 分别呈现信息/警告/错误三级样式,错误含 `✗` 前缀,均在超时后自动消失

### Requirement: 空会话品牌欢迎屏

TUI SHALL 在转录为空且不忙碌时显示品牌欢迎块:ASCII 标志、产品名、当前模型与 thinking 档位、基本入口提示;首条消息到达后 SHALL 移除,模型信息随会话配置实时更新。

#### Scenario: 新会话欢迎

- **WHEN** 打开一个无任何消息的新会话
- **THEN** 显示品牌标志、当前模型行与输入/命令/文件/会话入口提示,产品文字为英语

#### Scenario: 让位于内容

- **WHEN** 用户发送首条消息或切换到有内容的会话
- **THEN** 欢迎块消失,转录从头渲染消息条目,欢迎块不占据条目序列

#### Scenario: 配置联动

- **WHEN** 欢迎块显示期间切换模型或 thinking 档位
- **THEN** 欢迎块中的模型行同步更新为服务端确认值

### Requirement: TUI 默认图片提示查看

TUI SHALL 根据服务端投影的默认图片提示元数据显示来源标记与查看入口，默认收起提示正文并保留图片预览或文字回退，不将自动提示渲染为用户手写内容。查看 SHALL 展示该消息实际保存的完整默认提示，支持收起；操作标记和说明 SHALL 使用英语，正文保留原文，不从普通文字反向识别默认提示。

#### Scenario: 纯图片消息
- **WHEN** TUI 显示带有默认提示元数据的图片用户消息
- **THEN** 显示图片及 Default image prompt 来源标记，默认不铺开提示正文，用户可点击标记查看完整正文并再次点击收起，不提供额外查看命令

#### Scenario: 小窗口与输入保留
- **WHEN** 用户在 80x24 或 60x16 终端查看较长默认提示，再点击收起内容
- **THEN** 正文可换行或滚动查看，输入、草稿及状态栏保持可用；收起后继续原编辑流程，不发送消息或改变会话

#### Scenario: 恢复与普通文字
- **WHEN** TUI 重启、切换或打开分叉会话，或用户手写了相同的默认提示正文
- **THEN** 有来源标记的消息可查看原持久正文，无标记消息保持原用户文字展示，不因正文相同而隐藏或标记

### Requirement: TUI 升级感知与版本查看

TUI SHALL 提供简洁英语升级提示及 `/version` 查看入口，区分可安装更新、需重启 TUI 和需重启 gateway。提示 SHALL 给出实际可执行的下一步，同一状态不重复打扰。界面 MUST NOT 执行安装或自动重启，不将更新提示写入对话或发送给模型；输入、任务与常驻状态栏保持可用。版本概览 SHALL 默认只显示当前 TUI 版本、准确状态与必要操作；内部组件版本 SHALL 经独立详情入口按需查看。

#### Scenario: 新版本可用
- **WHEN** 后台确认稳定渠道有高于已安装版本的新版本
- **THEN** 显示简短版本提示；Windows 给出 `bun add --global neko-harness@latest`，macOS/Linux 给出 `neko update`，用户在另一个终端或退出界面后自行执行，不将命令作为聊天输入代为运行

#### Scenario: 网关仍旧
- **WHEN** 安装已升级，当前连接的 gateway 仍旧
- **THEN** 提示重新启动本地 neko，并经版本查看入口说明需关闭网关拥有者；复用方不暗示仅重启自己即可更新网关

#### Scenario: TUI 仍旧
- **WHEN** gateway 或已安装版本更新，TUI 仍运行旧构建且协议兼容
- **THEN** 提示退出后运行 `neko tui`，继续保留当前编辑与任务，不因单纯版本差异中断使用

#### Scenario: 查看与检查失败
- **WHEN** 用户输入 `/version` 并查看版本或主动检查更新
- **THEN** 默认查看当前版本及状态，经独立详情入口可查看 TUI、gateway、安装与渠道版本，支持退出查看返回原编辑流程；检查失败显示简短重试说明，不宣称已最新

#### Scenario: 窄窗口与提示去重
- **WHEN** 界面在 80x24 或 60x16 下收到重复状态广播，或用户切换会话
- **THEN** 提示不挤出输入和状态栏，不为每个会话重复弹出；版本状态改变后更新提示并移除已解决提醒

#### Scenario: 默认概览与条件提示
- **WHEN** 用户查看版本概览
- **THEN** 不平铺安装、网关和渠道版本，不固定展示安装命令与整段重启说明；仅有可安装更新时显示目标版本和平台对应命令，仅有待重启状态时显示所需重启操作，多种差异仍优先解决旧运行组件

#### Scenario: 未知和开发状态
- **WHEN** 尚未完成更新检查、安装或网关信息缺失、检查失败或运行开发构建
- **THEN** 分别显示简洁英语的未检查、不可用、失败或开发状态，不将缺失信息解释为 Up to date；仍允许返回编辑和在适用时重试检查

#### Scenario: 详情返回
- **WHEN** 用户进入版本详情并按 Esc 返回或关闭面板
- **THEN** 逐层返回概览选择流程及原编辑器，保留草稿和当前会话，不触发聊天、安装或重启

### Requirement: TUI 委派摘要与导航
TUI SHALL 在主 transcript 中显示每轮独立的简短委派卡片，并在有运行任务时显示有界活动摘要；提供鼠标与键盘入口打开子 agent 列表，选择条目进入详情。列表 SHALL 按稳定子 agent 身份去重，包含角色、当前或最近任务摘要及 Idle/Queued/Running 状态；完成/失败/停止与耗时 SHALL 属于各轮，旧轮卡片可定位对应轮次。详情 Esc SHALL 返回上一层，停止 SHALL 使用独立明确操作，绑定当前活动轮，不删除身份或上下文。

#### Scenario: 浏览与停止
- **WHEN** 用户通过点击或键盘选择运行中的子任务，进入详情后按 Esc
- **THEN** 返回列表或主视图而不停止任务；选择停止才取消该任务，兄弟任务不受影响

#### Scenario: 同一子 agent 两轮
- **WHEN** 同一子 agent 第一轮完成后开始第二轮
- **THEN** 列表保留一个条目并显示当前活动状态，主 transcript 保留两张独立任务卡，旧卡状态不被改为第二轮状态

### Requirement: TUI 子 agent 完整可见流程
详情面板 SHALL 展示与主 agent 同类的完整可见调用流程：各轮任务输入与简短分隔、助手文字、已保存的模型思考内容、工具参数、流式输出和最终结果、错误、图片入口及最终报告。SHALL 支持滚动、展开与历史恢复，沿用现有输出截断和终端图片能力，不以最后一条状态替代完整记录。同一子 agent 的各轮 SHALL 沿一条连续历史呈现；详情显示累计用量，各轮摘要可查看本轮增量。

#### Scenario: 多轮工具历史
- **WHEN** 子 agent 搜索、读取、修改并执行验证，随后结束或失败
- **THEN** 每轮可见消息与工具记录均可回看，折叠条目可展开，失败和截断仍可辨识

#### Scenario: 可见思考内容
- **WHEN** 模型返回可展示的思考内容，或未提供思考内容
- **THEN** 前者沿用主会话的折叠展示，后者不伪造思考正文

#### Scenario: 旧轮定位与接续输出
- **WHEN** 用户从第一轮卡片打开详情，随后第二轮产生新输出
- **THEN** 加载并定位第一轮内容，保留回看位置与展开状态；用户主动回到底部后可看到第二轮，主草稿与附件不变

#### Scenario: 用量显示
- **WHEN** 同一子 agent 有两轮已结算及一轮运行中
- **THEN** 累计统计该子会话，各轮摘要分别显示固定值或已记录增量，未知旧值标注未记录，英文提示与当前主题风格一致

### Requirement: TUI 子 agent 主题与交互状态
子 agent 列表和详情 SHALL 复用当前 auto/light/dark 主题、消息组件及面板布局，不默认左右分屏。切换子任务、返回主视图或切换主题 SHALL 保留主输入草稿、光标、附件及滚动位置，并保留各详情的浏览位置；新输出不得强制拉回正在回看的用户。

#### Scenario: 窄终端与主题
- **WHEN** 用户在 80x24 或 60x16 终端查看长任务，并在浅色和深色之间切换
- **THEN** 内容不越界，导航和停止入口可见，已有内容按当前主题重绘且展开状态不丢失

#### Scenario: 草稿与回看
- **WHEN** 用户带着未发送草稿查看子任务历史，收到新输出后返回主视图
- **THEN** 草稿、光标、附件和主视图滚动位置恢复，用户能主动回到底部查看新消息

### Requirement: TUI 子 agent 快捷浏览
详情 SHALL 支持滚轮/触控板及 PageUp/PageDown 翻页。主输入为空且未显示补全时，右键 SHALL 打开子 agent 列表；列表右键进入详情，列表或详情左键直接返回主视图。草稿非空时 SHALL 保留左右键编辑语义。当前会话存在子任务时，状态栏 SHALL 保留可点击入口和快捷键提示，包括全部结束的任务。

#### Scenario: 快捷往返与长日志
- **WHEN** 用户在有已完成子任务的会话中点击状态栏或按右键，进入详情后滚动并按左键返回
- **THEN** 可以快速回看长日志，主草稿与子详情浏览位置不丢失，且不取消任务

### Requirement: 自动补齐较早记录
子 agent 详情 SHALL 在用户向上滚动到已加载内容顶部时自动分页补齐较早记录并保持已有内容的浏览位置；SHALL 不提供单独的“查看历史”按钮或 H 快捷键。

#### Scenario: 向上浏览长记录
- **WHEN** 用户向上滚动至已加载记录的顶部且仍有较早条目
- **THEN** 自动加载并去重合并较早条目，保留正在阅读的内容位置，无需额外历史操作

### Requirement: TUI 操作帮助与技能预览
TUI SHALL 提供 /help，集中展示聊天控制、菜单、智能体、技能操作、编辑、主转录搜索和斜杠命令。帮助和技能预览 SHALL 支持滚轮、方向键和翻页，帮助 Esc SHALL 直接关闭返回主视图。技能安装提示 SHALL 明确写出 Install user 和 Install project，窄屏自动换行以保留操作含义。

#### Scenario: 查看快捷键与技能正文
- **WHEN** 用户打开 /help 或技能预览，并滚轮滚动或按 PageDown
- **THEN** 当前详情滚动且主视图位置不变，帮助 Esc 关闭、技能预览 Esc 返回技能详情，安装提示完整可见

### Requirement: TUI 子 agent 命令审批
TUI SHALL 在主视图 Agents 入口和子任务列表显示待审批提示与数量，在输入框附近独立展示完整命令、工作目录和显式超时，主视图或子视图均可处理；决定后移除审批区，仅在对应命令旁保留结果。操作 SHALL 使用英文 Allow once / Deny，沿用当前主题和统一快捷键样式，支持键盘与鼠标。长内容 SHALL 支持滚轮与翻页，窄屏操作可达；审批出现后 SHALL 自动进入选项交互，上下选择 Allow once / Deny，Enter 确认选项；关闭详情、Esc、左右导航和普通字母 MUST NOT 隐式授权。新增操作 SHALL 纳入 /help。

#### Scenario: 主视图进入审批
- **WHEN** 子 agent 等待审批而用户在主视图编辑草稿
- **THEN** 输入区附近自动显示并聚焦 Pi 选择组件，用户上下选择、Enter 明确允许或拒绝，草稿、附件与浏览位置保留

#### Scenario: 窄屏长命令
- **WHEN** 用户在 60x16 或 80x24 终端、浅色或深色主题下查看多行命令
- **THEN** 可滚动查看完整内容并操作允许或拒绝，Esc 和普通字母不决定请求，操作提示完整且风格统一

#### Scenario: 决定已失效
- **WHEN** 另一端已决定请求或任务被停止
- **THEN** 待审批区移除该请求，对应命令附上最终审批状态，旧控件不重复发起执行，允许状态不被显示为命令成功

### Requirement: TUI 复制最后回答
TUI SHALL 提供 `/copy` 命令，把"最后一条回答"（不含 thinking）写入系统剪贴板并显示成功提示及字符数。无可复制内容时 MUST 显示提示且不改动剪贴板；命令 MUST NOT 发送给模型，也不改变草稿与运行状态，忙碌时亦可使用。

#### Scenario: 复制回答
- **WHEN** 会话已有回答，用户提交 `/copy`
- **THEN** 最后一条回答的正文进入剪贴板，不含 thinking，并显示已复制提示

#### Scenario: 没有回答
- **WHEN** 会话尚无 assistant 正文时提交 `/copy`
- **THEN** 显示无内容可复制的提示，剪贴板保持原样

#### Scenario: 运行中使用
- **WHEN** agent 正在生成时提交 `/copy`
- **THEN** 复制已提交的最后一条回答，当前运行不受影响

### Requirement: TUI 剪贴板写入与降级
TUI 写入剪贴板 SHALL 优先使用平台原生方式（macOS、Windows 与 Linux 的 Wayland/X11 常用命令），原生方式不可用或失败时 MUST 降级到 OSC 52 终端序列；通过 SSH 等远程会话运行时 MUST 额外发出 OSC 52。所有方式均失败或内容超出 OSC 52 上限时 MUST 显示具体错误，不得谎报已复制。

#### Scenario: 原生命令可用
- **WHEN** 平台剪贴板命令可用
- **THEN** 内容经原生方式写入，成功提示出现

#### Scenario: 无图形环境
- **WHEN** Linux 无 Wayland/X11 剪贴板工具且内容在 OSC 52 上限内
- **THEN** 通过 OSC 52 写入并提示已发送到终端剪贴板

#### Scenario: 全部失败
- **WHEN** 原生方式失败且内容超出 OSC 52 上限
- **THEN** 显示无法写入剪贴板的错误及原因，并建议使用 `/export`

### Requirement: TUI 导出命令
TUI SHALL 提供 `/export [path] [--thinking]`，把当前会话导出为文件并显示最终写入路径。格式由路径扩展名决定：`.md`、`.html`、`.json`；缺省路径时生成 Markdown 的默认文件名并写入 TUI 工作区目录。路径 MAY 用引号包裹含空格的内容，支持 `~/` 前缀（Windows 上同时支持 `~\`），相对路径相对工作区目录解析。`--thinking` 选择包含思考过程。

#### Scenario: 默认导出
- **WHEN** 用户提交 `/export`
- **THEN** 在工作区目录生成带默认名称的 `.md` 文件并显示其完整路径

#### Scenario: 按扩展名选格式
- **WHEN** 用户提交 `/export out/chat.html`
- **THEN** 生成 HTML 文件，图片内嵌，完成时提示路径及未能内嵌的图片数量（若有）

#### Scenario: 包含思考过程
- **WHEN** 用户提交 `/export notes.md --thinking`
- **THEN** 导出的 Markdown 包含每条回答的思考过程

#### Scenario: 路径含空格
- **WHEN** 用户提交 `/export "my chats/a.json"`
- **THEN** 引号内整体作为路径，导出 JSON 到该文件

#### Scenario: Windows 主目录前缀
- **WHEN** Windows 上用户提交 `/export ~\Desktop\chat.md`
- **THEN** 文件写入当前用户主目录下的 `Desktop\chat.md`

### Requirement: TUI 导出的安全与错误
TUI 导出 MUST NOT 覆盖已存在的文件；不支持的扩展名、父目录不存在、无写入权限或空会话 MUST 以明确原因提示失败，且不留下部分文件。导出为异步执行，期间 TUI SHALL 保持可用；导出的内容 MUST 是发起命令时刻的会话转录，即使期间切换了会话也不混入其他会话。

#### Scenario: 目标文件已存在
- **WHEN** 目标路径已有同名文件
- **THEN** 导出失败并提示换一个路径，原文件内容不变

#### Scenario: 不支持的扩展名
- **WHEN** 用户提交 `/export chat.txt`
- **THEN** 提示仅支持 `.md`、`.html`、`.json`，不生成文件

#### Scenario: 导出期间切换会话
- **WHEN** 含图片的 HTML 导出进行中用户切换到另一会话
- **THEN** 文件内容仍属于发起导出的会话，完成提示指明该会话

### Requirement: TUI 复制与导出命令可发现
`/copy` 与 `/export` SHALL 出现在斜杠命令补全中并附简短说明，也 SHALL 出现在 `/help` 的命令列表里。

#### Scenario: 命令补全
- **WHEN** 用户输入 `/c` 或 `/ex`
- **THEN** 补全候选分别包含 `/copy` 与 `/export` 及其说明

### Requirement: TUI 输入历史浏览

TUI 输入框 SHALL 支持用 ↑/↓ 浏览当前会话的输入历史（条目规则见 `input-history`）：光标位于首行且输入为空、已处于浏览态或光标在行首时，↑ 回填更早一条并将光标置于开头；处于浏览态且光标位于末行时，↓ 回填更新一条并将光标置于末尾；越过最新一条后 SHALL 还原进入浏览前的草稿。除上述条件外 ↑/↓ 保持原有光标移动行为。用户在回填文字上编辑、提交或程序性替换输入后 MUST 退出浏览态。

#### Scenario: 空输入按 ↑ 回填最近输入

- **WHEN** 输入框为空且会话有历史，用户按 ↑
- **THEN** 输入框回填最近一条已发送输入，再按 ↑ 依次回填更早的输入，到最早一条后停止，不循环

#### Scenario: ↓ 返回并还原草稿

- **WHEN** 用户先输入未发送草稿，光标移到行首后按 ↑ 进入历史，再按 ↓ 直至越过最新一条
- **THEN** 输入框还原为进入历史前的草稿内容

#### Scenario: 多行内容内的光标移动优先

- **WHEN** 输入框含多行文字且光标不在首行（或浏览态下不在末行）
- **THEN** ↑/↓ 仍按行移动光标，不触发历史切换

#### Scenario: 补全面板优先

- **WHEN** `@` 文件补全或 `/` 技能补全面板正在显示
- **THEN** ↑/↓ 用于选择候选，不触发历史切换

#### Scenario: 编辑后退出浏览态

- **WHEN** 用户回填某条历史后修改其中文字
- **THEN** 该文字成为当前草稿，随后按 ↓ 不会覆盖它

#### Scenario: 空历史无变化

- **WHEN** 当前会话没有历史时用户按 ↑ 或 ↓
- **THEN** 输入框内容与光标行为与现状一致

### Requirement: TUI 输入历史的会话切换与同步

TUI SHALL 在切换会话时用新会话的历史替换输入历史，并丢弃上一会话的浏览态；会话 transcript 出现新的已提交输入时 SHALL 更新历史，使新输入成为 ↑ 的第一条。正在浏览历史时 MUST NOT 因后台更新改变用户当前看到的回填内容或浏览位置，更新 SHALL 在退出浏览态后生效。

#### Scenario: 切换会话后历史隔离

- **WHEN** 用户在会话 A 浏览历史后通过会话列表切换到会话 B
- **THEN** 会话 B 输入框按 ↑ 回填的是会话 B 的最近输入，且不显示会话 A 的内容

#### Scenario: 发送后立即可回填

- **WHEN** 用户发送一条输入并在其进入 transcript 后清空输入框
- **THEN** 按 ↑ 回填刚发送的那一条

#### Scenario: 浏览中收到更新

- **WHEN** 用户正在浏览历史时，其他前端向同一会话提交了新输入
- **THEN** 当前回填内容与浏览位置不变，退出浏览态后按 ↑ 的第一条为新输入

#### Scenario: 与图片引用共存

- **WHEN** 输入框含图片引用占位的草稿，用户通过 ↑ 进入历史后再回到草稿
- **THEN** 草稿中的图片引用与其附件关联保持不变

### Requirement: TUI 工具卡代码变更 diff 展示

TUI 工具卡 SHALL 对 `edit` 与 `write` 工具调用展示代码变更 diff:折叠摘要行显示增删行数计数(如 `edit path (+18/-3)`、`write path (+142)`),点击展开后渲染 diff,默认折叠。展开的 diff SHALL 叠加两层着色:按目标文件语言的语法高亮与新增/删除行着色;语言不可识别时回退为仅增删着色。`write` 调用 SHALL 一律呈现为全新增 diff,不区分目标文件是否已存在。diff 数据 SHALL 来自服务端投影;无 diff 数据的工具调用保持原有摘要与展开行为。

#### Scenario: 语法高亮与回退

- **WHEN** 展开的 diff 目标文件语言可识别(如 `.ts`)
- **THEN** diff 行内代码按语言语法着色,新增/删除行另有明确着色区分;跨行字符串或块注释的语法着色保持连续;语言不可识别时仅按增删着色,不报错、不缺失内容

#### Scenario: edit 调用折叠与展开

- **WHEN** `edit` 工具调用完成,卡片默认折叠
- **THEN** 摘要行显示路径与增删行数计数;点击展开后 diff 以新增/删除高亮渲染,再次点击收起

#### Scenario: write 调用全新增呈现

- **WHEN** `write` 工具调用完成(无论新建或覆盖已有文件)
- **THEN** 摘要行显示预览的新增行数计数,展开区将展示的写入内容以新增高亮渲染

#### Scenario: write 内容原样保留

- **WHEN** 写入内容含代码缩进、前导数字或空行
- **THEN** diff 保留每行原始内容,不把缩进或数字识别为 edit 行号

#### Scenario: write 投影预览受限

- **WHEN** 写入内容超过服务端 diff 的行数或 UTF-8 字节预算
- **THEN** 服务端仅投影预算内的完整行并标记截断,不复制超长单行到 diff;展开卡片明确提示预览不完整,参数详情仍可预览

#### Scenario: 超长 diff 截断

- **WHEN** 展开的 diff 行数超过显示上限
- **THEN** 仅渲染前若干行并提示剩余行数,不撑爆滚动区

#### Scenario: 历史会话恢复

- **WHEN** TUI 打开包含历史 `edit` 调用的已持久会话
- **THEN** 从持久数据恢复 diff 并照常显示;无持久 diff 的历史 `write` 调用保持原有显示

#### Scenario: 其他工具不受影响

- **WHEN** 非 `edit`/`write` 工具调用完成
- **THEN** 卡片摘要与展开行为与现状一致,不出现 diff 计数或 diff 视图

### Requirement: TUI 后台任务面板
TUI SHALL 提供 `/jobs` 命令，在当前会话内打开后台任务面板：列表按启动时间倒序显示标题或命令、状态、已运行时长或退出码；进入详情后显示命令、工作目录、状态及输出尾部，运行中的任务自动跟随新输出，用户向上滚动后停止跟随并可回到底部。运行中任务 SHALL 可用 `S` 停止，`←` 返回列表或主界面。面板 MUST NOT 提供启动任务的入口，打开与关闭不改变主草稿、附件与输入历史浏览状态。`/jobs` SHALL 出现在命令补全与帮助中，且无任务时显示空状态而非错误。

#### Scenario: 查看运行中服务
- **WHEN** 会话有一个运行中的 `npm run dev`，用户输入 `/jobs` 并进入详情
- **THEN** 看到命令与实时输出尾部，输出追加时自动跟随；上滚后保持位置并提供回到底部操作

#### Scenario: 停止任务
- **WHEN** 用户在运行中任务的详情或列表按 `S`
- **THEN** 任务停止并显示 stopped，已终止任务不再提供停止操作

#### Scenario: 无任务与保留草稿
- **WHEN** 会话没有任何 job 时执行 `/jobs`，且输入框已有草稿
- **THEN** 显示空状态，关闭面板后草稿、附件与历史浏览状态保持不变

#### Scenario: 切换会话
- **WHEN** 面板打开时用户切换到另一会话，或旧会话的输出响应迟到
- **THEN** 面板关闭或切换到新会话的任务，迟到响应不覆盖当前内容

### Requirement: TUI 后台任务状态指示与回报呈现
TUI 状态栏 SHALL 在当前会话存在运行中 job 时显示其数量，数量归零后移除；job 到达终态时 SHALL 以与现有主题一致的系统提示呈现状态与退出码。job 回报输入 MUST 以系统提示而不是用户消息气泡呈现，并折叠输出尾部。

#### Scenario: 运行数指示
- **WHEN** 会话先后有 2 个 job 运行，其中 1 个结束
- **THEN** 状态栏数量由 2 变为 1，全部结束后不再显示

#### Scenario: 回报呈现
- **WHEN** 后台服务崩溃并向会话回投回报
- **THEN** transcript 中显示一条系统提示（含 jobId、状态与退出码），随后按常规显示模型的新一轮回答，不出现伪造的用户消息

### Requirement: TUI 搜索 provider 面板

TUI SHALL 提供 `/search` 命令，打开与统一选择面板风格一致的搜索 provider 面板，以英语列出 tavily、deepseek，标出当前选择，并始终显示各 provider 的凭据状态（已保存、环境变量、keyless、无 Key 等）。面板 SHALL 提供 `k` 快捷键（过滤框为空时），对高亮的 provider 关闭本面板并打开 `/login` 的该 provider 密钥输入；DeepSeek 缺少 Key 时的提示 SHALL 指向该快捷键与 `/login`。Enter SHALL 确认选择，Esc SHALL 取消；确认后面板自动关闭并短暂提示结果。面板自身 MUST NOT 收集或显示密钥，打开与关闭不改变主草稿、附件与输入历史浏览状态。`/search` SHALL 出现在命令补全与 `/help` 中，`/help` SHALL 提及 `k`。

#### Scenario: 查看与切换

- **WHEN** 用户输入 `/search`，选中 deepseek 并按 Enter
- **THEN** 选择保存为 deepseek，面板关闭并提示结果，后续联网工具调用使用 DeepSeek；输入框草稿保持不变

#### Scenario: 默认选择

- **WHEN** 从未选择过 provider 时打开 `/search`
- **THEN** 面板标出 tavily 为当前选择，不存在 auto 选项

#### Scenario: DeepSeek 缺少 Key

- **WHEN** DeepSeek 未配置 Key 时查看 deepseek 项
- **THEN** 面板提示按 `k` 或通过 `/login` 配置 DeepSeek Key，不声称搜索可用

#### Scenario: 直达密钥输入

- **WHEN** 用户在 `/search` 高亮 deepseek 并按 `k`
- **THEN** 搜索面板关闭，`/login` 面板打开并直接进入 DeepSeek 的密钥输入；Esc 返回 `/login` 列表，主草稿保持不变

#### Scenario: 保存失败

- **WHEN** 保存选择失败
- **THEN** 面板显示不含密钥的错误并保持原选择，可重试或取消

#### Scenario: 多端同步

- **WHEN** 面板打开期间另一端更改了选择或 DeepSeek Key
- **THEN** 面板更新为最新选择与凭据状态，未确认的高亮项保留
- **THEN** 时间文字自动刷新但不移动选中项；关闭面板后停止其定时刷新

### Requirement: TUI 公式渲染

TUI SHALL 在所有 Markdown 渲染处（助手回答、已保存思考、用户消息、技能预览）把 `$..$`、`$$..$$`、`\(..\)`、`\[..\]` 中的 LaTeX 渲染为终端可读的 Unicode 文本：常见希腊字母、运算符、上下标、根号、分式与求和/积分等多行排版可读，块级公式独占行。代码块与行内代码中的 `$` MUST NOT 被当作公式；货币与变量写法（如 `$5 and $10`、`$HOME`）MUST 保持原文。

#### Scenario: 行内与块级公式

- **WHEN** 助手回答包含 `$E=mc^2$` 与独占一段的 `$$\frac{a+b}{c}$$`
- **THEN** 前者在句中显示为 `E = mc²`，后者以带分数线的多行文本显示，界面不出现 `$` 定界符与原始 LaTeX 源码

#### Scenario: 括号定界符

- **WHEN** 回答使用 `\(\alpha+\beta\)` 与 `\[x^2\]`
- **THEN** 两者按公式渲染，与 `$` 写法效果一致

#### Scenario: 表格与列表中的公式

- **WHEN** 公式出现在 Markdown 表格单元格、列表项或引用中
- **THEN** 公式正常渲染，表格对齐与列表缩进不被破坏

#### Scenario: 货币、变量与代码

- **WHEN** 回答包含 `价格 $5 到 $10，变量 $HOME`、行内代码 `$x$` 或围栏代码块中的 `$x$`
- **THEN** 这些内容按原文显示，不被渲染为公式

### Requirement: TUI 公式降级

TUI SHALL 在公式不受支持或无法解析时按原文（含定界符）显示，不得使整条消息渲染失败或丢失其他内容。流式输出中尚未闭合的公式 MUST 在闭合前保持原文，闭合后转为公式。

#### Scenario: 不支持的公式

- **WHEN** 回答包含 `$$\textcolor{red}{x}$$` 等渲染器不支持的公式及其他正常段落
- **THEN** 该公式按原文显示，其余段落、代码块与公式正常渲染

#### Scenario: 流式未闭合公式

- **WHEN** 流式回答已到达 `$$\frac{a+b` 但尚未收到结束定界符
- **THEN** 界面不报错且显示原文，收到结束定界符后该段转为公式

### Requirement: TUI 上下文设置面板

TUI SHALL 提供 `/context` 命令，打开与统一选择面板风格一致的上下文设置面板，以英语列出压缩与裁剪各项及其生效值与来源（Default、Config、Saved），并提供 Reset to defaults。选中某项并按 Enter SHALL 进入该项的预设选择（开关为 On/Off，数值为预设档位加 Default），确认后保存并返回列表；Esc 返回上一级或关闭面板。面板 MUST 保持主草稿、附件与输入历史浏览状态不变，`/context` SHALL 出现在命令补全与 `/help` 中。

#### Scenario: 查看与修改

- **WHEN** 用户输入 `/context`，选中压缩触发百分比并选择 50
- **THEN** 该项保存为 50 且来源显示 Saved，列表刷新，后续压缩检查使用新阈值；输入框草稿保持不变

#### Scenario: 恢复默认

- **WHEN** 用户在面板中选择 Reset to defaults
- **THEN** 已保存值被清除，各项回落为配置文件值或内置默认并更新来源

#### Scenario: 保存失败

- **WHEN** 保存失败
- **THEN** 面板显示不含内部细节的错误并保持原值，可重试或取消

#### Scenario: 多端同步

- **WHEN** 面板打开期间另一端修改了上下文设置
- **THEN** 面板更新为最新生效值与来源，未确认的高亮项保留

### Requirement: TUI 排队消息选择、引导与撤回

TUI SHALL 在编辑器上方显示当前会话排队输入（最新的靠近编辑器，每项以英语标注 Steer 或 Queued 并显示截断到单行的文字预览，更多项以数量摘要提示），并在同一区域给出按键提示；无排队项时不占位。用户 SHALL 能用 Alt+↑ 直接选中排队区的最新一项，↑/↓ 在排队消息间移动（↓ 越过最新一项即离开选择）；选中后 Enter 把 Queued 项改为 Steer，Esc 只撤回该条并把文字取回编辑器（编辑器非空时追加到新行），其他按键离开选择并照常作用于编辑器。选择期间的 Esc MUST NOT 停止运行或撤回其他排队项；不在选择状态时 Esc 保持停止运行并撤回全部排队项。图片引用不恢复，并以英语提示。

#### Scenario: 发送后可见

- **WHEN** 运行中用户按 Enter 发送一条消息
- **THEN** 编辑器清空，排队区显示 Queued 及该消息预览，消息进入 transcript 后消失

#### Scenario: 选中并引导

- **WHEN** 用户按 Alt+↑ 选中排队区一项并按 Enter
- **THEN** 该项变为 Steer 并仍处于选中，当前运行与其他排队项不变，已是 Steer 的项按 Enter 只提示无需重复引导

#### Scenario: 选中并撤回

- **WHEN** 用户选中排队区一项并按 Esc
- **THEN** 仅该项被撤回，文字回到编辑器，当前运行继续，其余排队项不变

#### Scenario: 离开选择

- **WHEN** 用户在选择状态下输入普通字符或按 ↓ 越过最新一项
- **THEN** 选择结束，普通字符进入编辑器，排队项不变

#### Scenario: 已被放入

- **WHEN** 引导或撤回时该消息刚进入 transcript
- **THEN** 显示英语提示说明该消息已发送，编辑器内容不变

#### Scenario: 旧网关与窄终端

- **WHEN** TUI 连接不提供排队列表的旧网关，或窗口很窄
- **THEN** 旧网关下不显示排队区、Alt+↑ 无作用，窄窗口下排队行截断而不换行溢出，发送与停止照常

### Requirement: TUI 模型选择列表

TUI SHALL 提供按 provider 分组、可过滤的 `/model` 选择列表，只列出已启用 provider 的模型，以英语显示。列表 SHALL 按 provider 分组，输入即过滤（匹配模型名、模型 id 与 provider 名），每项显示 `provider/modelId`、上下文窗口、是否支持 Thinking 与图片，并标出当前模型。已启用但缺少 Key 的 provider 项 SHALL 标注 needs key 且不可选，提示通过 `/login` 配置。Enter 确认、Esc 取消，取消不改变会话与草稿。状态栏与页脚的模型名 SHALL 保留厂商前缀以区分不同厂商的同名模型（如 `anthropic/claude-haiku-4.5`）。

#### Scenario: 过滤与选择

- **WHEN** 用户启用 OpenRouter 后输入 `/model`，键入 `haiku` 并按 Enter 选中某项
- **THEN** 列表仅显示匹配模型并保持分组，确认后会话模型更新，状态栏显示服务端确认的 `provider/modelId`

#### Scenario: 缺 Key 的 provider

- **WHEN** OpenRouter 已启用但未配置 Key
- **THEN** 其模型项标注 needs key 且无法被确认，并提示使用 `/login` 配置

#### Scenario: 同名模型区分

- **WHEN** 两个不同厂商的模型短名相同
- **THEN** 列表与页脚保留厂商前缀，用户可区分

#### Scenario: 小窗口

- **WHEN** 在 80x24 或 60x16 下打开列表
- **THEN** 列表滚动且不越界，当前项与过滤输入可见，操作提示可访问

### Requirement: TUI 默认模型设置

TUI `/model` 列表 SHALL 标识当前默认模型，并对高亮的可选模型提供「设为默认」按键；已是默认的模型可用同一按键取消默认。未配置 Key 而不可选的模型 MUST NOT 响应该操作。操作结果 SHALL 即时反映在列表标识上；默认模型 SHALL 只影响新建会话，不改变当前会话模型。

#### Scenario: 设为默认与取消

- **WHEN** 用户在 `/model` 列表中对可选模型按设为默认键，随后对默认模型再按一次
- **THEN** 第一次后该模型显示默认标识，新建会话默认使用它；第二次后标识消失，新建会话回落为配置文件或内置默认

#### Scenario: 无 Key 模型

- **WHEN** 高亮停在已启用但未配置 Key 的模型上按设为默认键
- **THEN** 不产生任何更改，默认模型保持不变

#### Scenario: 跨端一致

- **WHEN** Web 修改默认模型后用户在 TUI 打开 `/model`
- **THEN** 列表显示同一默认模型标识

### Requirement: TUI Git Bash 缺失提示

TUI 连接的网关在应用信息中报告 Windows shell 缺失时，TUI SHALL 显示一条英语警告通知，说明 bash 与后台任务不可用，并给出下一步：安装 Git for Windows，或在配置中设置 `shell.path`；配置无效时 SHALL 说明配置路径的问题。同一缺失状态在一次 TUI 运行中 MUST NOT 重复提示，状态变为可用后不再提示。该提示 MUST NOT 写入对话或发送给模型，MUST NOT 阻断输入。网关未提供该字段时 MUST NOT 显示提示。

#### Scenario: 启动时缺少 Git Bash

- **WHEN** Windows 上 TUI 连接的网关报告 shell 缺失（未找到）
- **THEN** TUI 显示一次英语警告，包含安装 Git for Windows 与 `shell.path` 的指引，输入保持可用

#### Scenario: 重连不重复

- **WHEN** 网关重连后仍报告相同的缺失状态
- **THEN** 不再重复显示该警告

#### Scenario: 非 Windows 网关

- **WHEN** TUI 连接 macOS 网关
- **THEN** 不显示任何 shell 提示

### Requirement: TUI 计划模式命令与状态
TUI SHALL 提供 `/plan` 命令与对应补全、帮助说明，在 plan 模式与 normal 模式间切换；会话运行中给出明确提示且不切换。状态栏 SHALL 在 plan 模式下显示模式标识，待批准时显示计划提示并带打开方式。命令不发送给模型，网关不支持计划能力时命令说明该能力不可用。

#### Scenario: 切换
- **WHEN** 用户在空闲会话输入 `/plan`
- **THEN** 进入 plan 模式，状态栏显示模式标识；再次输入退出

#### Scenario: 运行中切换
- **WHEN** 会话回答中输入 `/plan`
- **THEN** 提示需先等待或停止，模式不变

### Requirement: TUI 计划面板
TUI SHALL 在会话有待批准计划时提供计划面板，展示标题、步骤、说明并支持批准、带文字反馈的要求修改、取消并退出计划模式、关闭（关闭不改变计划与模式）。面板打开时 MUST 独占按键，关闭后焦点回到输入框；与排队区选择共存时，面板的 Enter 与 Esc MUST NOT 被排队操作吞掉或同时触发。已结算计划或被其他端抢先时 MUST 展示真实状态。

#### Scenario: 计划到达时自动打开
- **WHEN** 会话提交了新的待批准计划，且编辑器为空、无补全、无选择器/登录/审批、无排队选择、终端可用
- **THEN** 计划面板自动打开，用户无需输入 `/plan` 即可直接批准、要求修改或取消并退出；同一计划版本只自动打开一次，Esc 关闭后不会再次弹出，新版本（修改后重新提交）再次自动打开

#### Scenario: 忙碌时不抢占
- **WHEN** 计划到达时用户正在输入草稿或有其他面板持有按键
- **THEN** 面板不自动打开，只在页脚显示待批准提示，`/plan` 可随时打开

#### Scenario: Markdown 渲染
- **WHEN** 计划的步骤或说明包含行内代码、加粗、列表或标题
- **THEN** 面板按 Markdown 渲染这些内容，不显示原始标记；标题保持纯文本，控制字符与转义序列先被剥离

#### Scenario: 面板批准
- **WHEN** 待批准时用户打开面板并批准
- **THEN** 面板关闭，状态栏退出 plan 标识，会话开始执行

#### Scenario: 选项列表与间距
- **WHEN** 计划面板打开
- **THEN** 选项列表依次为「批准并执行」「要求修改」「取消并退出计划模式」，可用方向键、Enter、数字键或 A / R / X 选择；面板与上方转录之间保留一个空行；Esc 只关闭面板，不改变计划与模式

#### Scenario: 取消并退出
- **WHEN** 待批准时用户在面板中选择取消并退出计划模式
- **THEN** 面板关闭，状态栏退出 plan 标识，计划变为已取消，没有执行输入被提交

#### Scenario: 反馈输入中不误触
- **WHEN** 用户在填写修改反馈时输入取消并退出所用的按键字符
- **THEN** 字符作为反馈文字输入，不触发取消

#### Scenario: 与排队选择共存
- **WHEN** 排队区处于选择状态时计划面板打开并按 Enter
- **THEN** 按键只作用于计划面板，排队项不被引导或撤回

#### Scenario: 其他端抢先
- **WHEN** 面板打开期间另一端要求修改该计划
- **THEN** 面板切换为已结算状态，不能再提交决定
