# session-gateway Specification

## Purpose

本地会话网关：托管持久会话并向多个前端提供统一的连接、attach 与服务路由，使终端和 Web 可同时对同一会话工作。

## Requirements

### Requirement: 会话目录
系统 SHALL 维护会话目录（创建、列出、删除会话），目录变化 MUST 实时推送给已连接的前端。每个条目 SHALL 包含持久化的工作区、标题、首问摘要、创建时间、最近消息时间与最近使用信息，并提供会话模型和运行状态，以支持前端展示、筛选和恢复。目录保持全局可见，工作区筛选不构成权限隔离。子 agent 会话 SHALL 仅通过所属主会话的委派记录访问，不出现在普通会话目录。

#### Scenario: 新会话广播
- **WHEN** 任一前端创建会话
- **THEN** 所有已连接前端在目录更新中收到该会话及其工作区

#### Scenario: 最近使用更新
- **WHEN** 会话被成功激活或接受用户输入
- **THEN** 最近使用信息被持久更新并推送，网关重启后仍可据此排序；仅后台输出不改变最近使用顺序；最近使用时间与最近消息时间分别维护

#### Scenario: 子会话不进入目录
- **WHEN** 主 agent 创建子会话并持续运行或结束后重连
- **THEN** 普通会话目录不新增该子会话，原有普通会话与用户分叉仍正常展示

### Requirement: 多前端 attach

系统 SHALL 允许多个前端同时 attach 同一会话，每个 attachment 有服务端分配的标识；重复 attach MUST 幂等。attach 成功 SHALL 表示当前会话首个完整视图已可用；切换或 detach 后旧 attachment MUST 不再接受新会话操作。连接私有的未提交图片与请求资源 MUST 与其他 attachment 隔离，共享会话运行不随前端释放而终止。

#### Scenario: 双前端同步

- **WHEN** 终端和 Web 同时 attach 同一会话，终端提交一条输入
- **THEN** 两个前端都收到该输入及后续的流式回答

#### Scenario: 断连释放

- **WHEN** 某前端连接断开
- **THEN** 其 attachment 在已受理调用结算后释放，会话本身与其他 attachment 不受影响；未使用图片资源被回收，可取消的查询停止

#### Scenario: 首次状态与重复 attach

- **WHEN** 客户端 attach 到一个会话，或在同一连接重复 attach 同一会话
- **THEN** 成功返回时首个视图已可读取；重复 attach 保持相同 attachment 标识，不重复创建共享会话观察资源

#### Scenario: 旧会话引用失效

- **WHEN** 客户端切换会话、detach，或原会话已归档后仍使用旧引用提交输入、修改配置或操作图片
- **THEN** 操作明确失败，不发送到旧会话或新会话，迟到状态不覆盖新选择

#### Scenario: 上传隔离

- **WHEN** 两个客户端 attach 同一会话，一端尝试使用另一端尚未提交的图片上传引用
- **THEN** 引用被拒绝；关闭或切换其中一端不会回收另一端的上传或停止共享会话回答

### Requirement: 传输支持

网关 SHALL 按平台提供本地 Chord 传输：macOS/Linux 同时提供 Unix socket（供终端等本地客户端）与 WebSocket（供浏览器）；Windows 不提供 Unix socket，仅提供 WebSocket。所有平台上已启用的本地 Chord 传输 MUST 提供完全相同的服务契约、输入输出校验和取消语义。新版客户端 SHALL 校验目标网关身份，不支持旧版协议回退；协议版本不同的对端 MUST 被明确拒绝并给出可识别原因，且不影响其他连接。无效帧与超限缓冲 MUST 有界处理而不影响其他连接。可选移动入口 SHALL 使用独立认证与版本化 API，不直接公开本地 Chord 服务，其开放业务保持相同的持久会话语义。

#### Scenario: 浏览器连接

- **WHEN** Web 前端通过 WebSocket 连接网关
- **THEN** 可完成握手、会话列表查询与会话 attach

#### Scenario: Windows 本地客户端连接

- **WHEN** TUI 在 Windows 上连接网关
- **THEN** 通过 WebSocket 完成握手与会话 attach，不尝试 Unix socket

#### Scenario: POSIX 双传输不变

- **WHEN** 网关运行于 macOS/Linux
- **THEN** Unix socket 与 WebSocket 同时可用，已有客户端业务操作保持一致

#### Scenario: 网关身份不匹配

- **WHEN** 客户端连接到身份与发现结果不同的网关
- **THEN** 连接被明确拒绝，不读取或提交该网关的会话内容

#### Scenario: 协议版本不匹配

- **WHEN** 仍运行 Pi 1.2 的网关进程被新版 TUI/Web 连接（握手无法识别或协议版本不同），或旧版客户端连接新网关
- **THEN** 连接被拒绝并报告协议不兼容、提示更新后重启 TUI/Web 或网关，前端不无限重试、TUI 不再启动竞争实例；同一网关上其他兼容连接继续正常工作

#### Scenario: 无效帧与慢连接

- **WHEN** 某连接发送无法解析的帧、超过单帧限制，或发送缓冲超过上限
- **THEN** 只关闭该连接并释放相关资源，不无限累积字节或阻塞其他客户端

#### Scenario: 活跃实例与遗留 socket

- **WHEN** 新网关尝试使用已占用的 Unix socket 或端口，或遇到已无监听者的遗留 socket
- **THEN** 活跃实例占用时拒绝启动并给出可操作提示，仅对确认已无监听者的遗留 socket 接管

#### Scenario: 独立移动连接

- **WHEN** 用户开启局域网移动入口
- **THEN** 手机只经认证的移动 API 访问已开放业务，本地 Chord 地址与现有客户端契约保持不变

### Requirement: 多工作区目录一致性
网关 SHALL 在同一存储中托管多个工作区会话。会话投影的工作目录 MUST 来自该会话保存的工作区，不能使用网关进程目录覆盖。新建会话省略目录时 SHALL 使用网关启动时确定的默认工作区。

#### Scenario: 复用另一目录的网关
- **WHEN** 从工作区 B 启动的 TUI 连接启动于 A 的网关并指定 B 创建会话
- **THEN** 新会话的工具默认目录、目录条目与聊天投影均为 B，A 中会话保持不变

#### Scenario: Web 同时连接
- **WHEN** Web 与 TUI attach 同一会话
- **THEN** 两者收到相同工作区与会话状态，Web 仍可浏览全局会话目录

### Requirement: 最近消息时间与目录更新

系统 SHALL 在接受新的用户输入或成功提交完整回答时持久更新最近消息时间。打开会话、重复请求、流式片段、工具输出、标题生成和配置修改 MUST NOT 更新该时间。会话创建但无消息时 SHALL 使用创建时间作为列表排序回退；时间相同按会话 ID 稳定倒序。目录 SHALL 同步标题、消息时间、模型与运行状态变化，不依赖会话保持前端连接。

#### Scenario: 查看旧会话

- **WHEN** 用户打开较早的会话但没有发送新输入
- **THEN** 最近使用时间更新，最近消息时间保持原值，按消息时间排列的列表顺序不变

#### Scenario: 后台回答完成

- **WHEN** 用户切到其他会话后，原会话成功完成回答
- **THEN** 原会话最近消息时间更新并广播；流式期间不逐片段更新排序

#### Scenario: 重复提交与失败

- **WHEN** 相同请求标识被重复提交，或回答失败、取消
- **THEN** 重复输入不重复更新时间，失败或取消不伪造成功回答时间；已接受的新输入时间保留

#### Scenario: 空会话与时间相同

- **WHEN** 列表包含没有消息的新会话或消息时间相同的会话
- **THEN** 空会话按创建时间参与排序，同时间会话按 ID 稳定倒序，两端顺序一致

### Requirement: 凭据配置与同步

网关 SHALL 为 TUI/Web 提供服务器级凭据状态订阅、保存和移除能力，按 provider 分别管理且无需 attach 会话。状态 SHALL 以 provider 标识为键，覆盖目录内全部模型 provider 与 Tavily；每个 provider 的状态 SHALL 包含已保存凭据是否存在、网关环境变量是否配置、生效来源，模型 provider 另含启用状态。任一 provider 变更持久化成功后 SHALL 通知所有已连接前端，断线重连 SHALL 恢复最新状态；响应和广播 MUST NOT 包含密钥。凭据与启用状态的契约变更 SHALL 递增链路协议版本，沿用"协议版本不同即被明确拒绝"的既有约束，不提供回退。

#### Scenario: 双端配置

- **WHEN** Web 保存或移除某 provider 的 Key 且 TUI 已连接
- **THEN** 两端收到相同新状态，后续请求使用同一凭据来源，无需重启或切换会话

#### Scenario: 无会话与重连

- **WHEN** 未 attach 会话的客户端打开设置，或配置期间断线后重连
- **THEN** 可读取并管理各 provider 凭据，重连显示服务端最终状态，不因旧响应覆盖新状态

#### Scenario: 并发和失败

- **WHEN** 两端同时修改凭据，或某次持久化失败
- **THEN** 修改按服务端顺序处理并发布一致状态；失败操作不发布成功状态，错误不回显提交的 Key

#### Scenario: 未知 provider

- **WHEN** 客户端对目录之外的 provider 保存或移除凭据
- **THEN** 操作被拒绝并返回不含密钥的错误，其他 provider 状态不变

#### Scenario: 协议版本递增

- **WHEN** 仍运行协议版本 6 的网关被新版 TUI/Web 连接，或旧版客户端连接新网关
- **THEN** 连接以可识别的协议不兼容原因被拒绝，不进入部分可用状态

### Requirement: 会话压缩控制与同步

网关 SHALL 提供会话级手动压缩及可恢复的压缩状态，独立表达回答运行与压缩运行，包含触发原因、是否阻塞、重试及实际结果。同一会话已有压缩时 SHALL 避免重复手动启动。客户端断开 MUST 不导致任务重复或丢失；状态和结果必须绑定原会话。

#### Scenario: 双端并发与重连

- **WHEN** TUI 与 Web 同时请求同一会话压缩，随后一端重连
- **THEN** 不创建重复的手动任务，两端恢复相同实际状态；后台压缩不被错误表示为回答已停止

#### Scenario: 失败和迟到结果

- **WHEN** 压缩失败、中止、无需执行或摘要过期，且前端已切换会话
- **THEN** 原会话保留准确结果，不将任务结束统一解释为成功，不污染新会话状态

### Requirement: 有界图片传输与预览

网关 SHALL 在所有已启用的本地 Chord 传输上提供相同的图片提交与按需读取能力；图片与文字合为一次会话输入。状态投影 SHALL 仅携带有界附件描述，图片数据按需取得，不随流式增量重复广播。图片读取 MUST 校验会话、条目和内容位置，不允许将预览请求用作任意宿主路径读取。移动 API SHALL 独立声明媒体能力，首版提供历史图片读取而不开放手机上传。

#### Scenario: 大图与慢客户端

- **WHEN** 用户提交多张图片或慢客户端查看图片历史
- **THEN** 传输按已公布限制分块并限制并发，不通过无限增大帧或缓冲上限规避问题，文字流和其他客户端仍可工作

#### Scenario: 未完成上传与断线

- **WHEN** 上传后尚未提交就断线，或提交确认丢失后重试
- **THEN** 未使用的临时数据可回收，已受理消息通过请求标识恢复；不出现半条消息或重复消息

#### Scenario: 非当前会话与失效引用

- **WHEN** 读取合法历史附件或请求不属于指定会话的附件
- **THEN** 前者返回原图片，后者明确失败；错误不泄露无关文件内容

#### Scenario: 手机媒体能力

- **WHEN** 手机读取历史图片或尝试调用上传
- **THEN** 合法历史图片可有界读取，上传明确不支持，不改变 TUI/Web 已有图片提交能力

### Requirement: 工作区文件查询服务

网关 SHALL 提供工作区文件候选查询，以已登记的工作区身份解析根目录，只返回名称、相对路径、类型及查询状态，不返回文件正文。查询 MUST 与添加工作区的宿主目录浏览分离，支持无会话的工作区，并遵循工作区文件候选规则。取消或客户端断连 SHALL 停止对应查询，不影响其他客户端与会话任务。

#### Scenario: 根目录解析

- **WHEN** Web 在 B 查询文件而网关启动于 A，或 B 尚无会话
- **THEN** 查询只使用已登记的 B；未知工作区、越界输入和失效目录明确失败，不采用 A 作为回退

#### Scenario: 取消与隔离

- **WHEN** 用户继续输入、关闭候选或切换工作区，旧查询尚未完成
- **THEN** 客户端取消旧请求并忽略晚到结果，服务端终止该查询资源，其他客户端的查询和回答继续运行

#### Scenario: 服务能力与错误

- **WHEN** 宿主缺少文件发现依赖、查询超时或候选达到上限
- **THEN** 返回可区分的不可用、超时或有界结果状态，前端提供安装提示、重试或缩小范围指引，不将失败显示为无匹配

### Requirement: 会话技能列表服务

会话级聊天服务 SHALL 提供 `skills()` 方法，返回当前会话可用的技能列表（name、description、SKILL.md 绝对路径），供前端补全使用；该列表 MUST 包含禁用模型调用的技能，并随技能文件变化更新。

#### Scenario: 前端拉取技能

- **WHEN** 已 attach 会话的前端调用 `skills()`
- **THEN** 返回该会话工作区与用户级目录合并的技能列表

#### Scenario: 技能文件变化

- **WHEN** 会话进行中技能文件新增或修改，前端再次调用 `skills()`
- **THEN** 返回更新后的列表

### Requirement: Windows 网关地址发现

Windows 上网关 SHALL 以随机 WebSocket 端口启动，并将实际 ws 地址写入 `<数据目录>/<serverId>.port` 端口文件，供本机前端发现连接；端口文件 MUST 与 serverId 文件同属数据目录并随网关关闭清理。macOS/Linux MUST NOT 产生端口文件，地址发现机制保持现状。

#### Scenario: Windows 启动与发现

- **WHEN** 网关或前端在 Windows 上拉起新网关
- **THEN** 网关监听随机端口、写出端口文件，前端读文件后以 ws 地址连接

#### Scenario: 端口文件清理

- **WHEN** Windows 上的网关正常关闭，或被强杀导致其清理逻辑未执行
- **THEN** 正常关闭时端口文件被移除；强杀残留由拉起方在终止网关进程后补删，仍残留的过期文件以前端连接失败按无活跃网关兜底

#### Scenario: POSIX 无端口文件

- **WHEN** 网关运行于 macOS/Linux
- **THEN** 数据目录中不出现端口文件，前端沿用 Unix socket 发现

### Requirement: 服务边界校验与就绪

网关 SHALL 在远程服务边界校验请求参数、响应和订阅状态，并向 TUI/Web 提供一致的错误语义。服务器级目录、工作区与凭据的初始状态未到达前，客户端 MUST NOT 宣称管理操作已就绪；无效输入 SHALL 在执行业务修改之前拒绝。凭据及工具内部数据 MUST NOT 因错误或状态校验泄露到客户端。

#### Scenario: 无效参数

- **WHEN** 客户端向创建、配置、图片上传或文件查询方法发送类型错误的参数
- **THEN** 请求被明确拒绝，不创建会话、不修改配置、不留下部分上传，连接仍能处理后续有效请求

#### Scenario: 首个订阅状态迟到

- **WHEN** 服务连接建立成功，但目录、工作区或凭据快照仍未到达
- **THEN** 客户端保持加载状态并等待实际快照；超时或断连返回明确错误，不把未到达状态当成空目录或无凭据

### Requirement: 前端自动启动与跨前端复用

默认配置下，TUI 与 Web SHALL 按任意顺序启动并连接同一数据目录的同一 gateway，后启动的前端 MUST 复用活跃实例。POSIX 上自动启动的默认 gateway SHALL 同时提供 Unix socket 与 WebSocket；Windows SHALL 保持随机 WS 端口及端口文件发现。复用方关闭 MUST NOT 终止已有 gateway。

#### Scenario: TUI 先启动
- **WHEN** 默认配置下 TUI 自动启动 gateway，随后 Web 使用同一数据目录启动
- **THEN** Web 复用该 gateway，浏览器完成 WS 握手、会话列表查询及与 TUI 相同会话的 attach，TUI 保持可用

#### Scenario: Web 先启动
- **WHEN** 默认配置下 Web 自动启动 gateway，随后 TUI 使用同一数据目录启动
- **THEN** TUI 复用该 gateway，两端可以 attach 同一会话，关闭复用方不影响原前端

#### Scenario: Windows 跨前端发现
- **WHEN** Windows 上任一前端自动启动 gateway 后另一前端启动
- **THEN** 后启动的前端通过端口文件发现实际随机 WS 地址并校验身份后复用，不使用 Unix socket

### Requirement: Web 启动验证所需传输

Web SHALL 在启动成功并向浏览器发布连接地址前，对将发布的 WS 地址完成有界的握手及目标 gateway 身份验证，不得仅凭 Unix socket 存活宣称 WS 可用。已有活跃 Unix gateway 而指定 WS 不可用或身份不匹配时，Web MUST 明确失败并提供检查地址配置或重新启动双传输 gateway 的提示，不启动竞争实例、不停止已有 gateway；探测资源 MUST 释放。

#### Scenario: 旧的仅 Unix gateway
- **WHEN** 已有活跃 Unix gateway 未启用 WS，Web 尝试复用
- **THEN** Web 在有界时间内报错，不发布不可用连接地址，已有 TUI 连接与会话仍可用

#### Scenario: 自定义地址
- **WHEN** Web 使用与已有 gateway 一致的自定义 host 与端口
- **THEN** 验证该地址成功后发布该地址；地址无法连接时明确失败，不返回默认端口作为成功结果

#### Scenario: WS 身份不匹配
- **WHEN** 指定 WS 地址连接到另一 serverId 的 gateway
- **THEN** Web 拒绝该地址，不读取或修改另一 gateway 的会话，原 Unix gateway 保持可用

#### Scenario: 新网关 WS 未就绪
- **WHEN** Web 拉起的子进程已有 Unix socket，但 WS 尚未完成握手
- **THEN** Web 继续在启动期限内等待 WS 验证；超时或子进程退出时明确失败并清理自己拉起的子进程和探测连接

### Requirement: 网关版本与更新状态

网关 SHALL 提供无需 attach 会话的服务器级版本与更新状态，包含运行版本、可确认的安装版本、稳定渠道检查结果和独立的协议兼容信息。已连接 TUI/Web SHALL 得到一致状态；安装变化和重新连接后 SHALL 重新计算，不因网关仍旧而隐瞒安装已升级。服务 MUST NOT 提供远程安装或重启操作。

#### Scenario: 双端感知安装变化
- **WHEN** 用户执行升级后仍有 TUI/Web 连接旧 gateway
- **THEN** 两端在有界的本地检查周期后获知安装已新、网关仍旧，并提示重启，不自动关闭原任务

#### Scenario: 无会话与重连
- **WHEN** 尚未 attach 的客户端查看版本，或客户端连接到重启后的 gateway
- **THEN** 可取得当前网关状态，重连不会沿用旧连接的版本和更新提示

#### Scenario: 查询失败与资源释放
- **WHEN** 更新来源不可达、客户端断开或网关关闭
- **THEN** 网络查询失败不使会话服务失败；订阅、轮询和未完成检查可释放，不重复广播相同状态

### Requirement: 应用协议兼容检查

客户端 SHALL 在业务服务绑定和会话操作前校验独立于发布版本的应用协议兼容信息。协议兼容而发布版本不同 SHALL 保留正常使用并提示版本差异；协议不兼容 SHALL 有界地失败并给出更新或重新启动操作。拒绝连接 MUST NOT 被当成可重新拉起网关的陈旧地址，不停止活跃实例或启动竞争实例。

#### Scenario: 新界面与旧网关兼容
- **WHEN** 新 TUI/Web 连接旧发布版本 gateway，但双方应用协议兼容
- **THEN** 身份校验成功后可继续使用，明确提示应更新或重新启动的组件

#### Scenario: 协议不兼容
- **WHEN** gateway 身份正确但应用协议与客户端不兼容
- **THEN** 在业务就绪前拒绝该连接，提示更新本地 neko 或重新启动旧网关，不无限重复连接或自动启动另一实例

#### Scenario: 复用方与拥有者
- **WHEN** 复用旧 gateway 的前端显示重启提示或被用户关闭
- **THEN** 提示要求重新启动启动网关的 TUI/Web 或独立 serve；复用方退出仍不停止该 gateway

### Requirement: 子 agent 观察与停止服务
网关 SHALL 提供绑定主会话、按稳定身份去重的子 agent 列表及每轮委派引用、按需连续子会话详情订阅、轮次定位、历史读取、图片读取及绑定当前轮的单独停止能力。详情 SHALL 包含与主会话同类的持久消息和实时调用数据，保留原有错误、截断及图片传输规则；同一子会话在总用量中 SHALL 只汇总一次，详情 SHALL 区分累计与各轮增量。接口 MUST 校验主子归属和目标轮次，不允许借详情句柄提交输入、修改配置或启动新子任务。

#### Scenario: 双端观察
- **WHEN** Web 与 TUI 同时查看同一子 agent，一端停止它
- **THEN** 两端获得相同最终状态及已产生历史，主会话与其他子任务继续按原生语义运行

#### Scenario: 旧引用与越界
- **WHEN** 客户端切换主会话后旧详情返回，或请求不属于该主会话的子会话与图片
- **THEN** 旧响应不覆盖新选择，非法读取或停止被拒绝，不触及无关会话

#### Scenario: 重连与资源释放
- **WHEN** 用户关闭详情、断线或重新连接
- **THEN** 未使用的详情订阅及读取资源释放，执行不中断；重连恢复真实记录而不重新派发任务

#### Scenario: 大量历史
- **WHEN** 子 agent 产生很长工具日志或多个子 agent 同时流式运行
- **THEN** 列表仅推送摘要，详细历史按需有界加载，不每次把所有子会话完整历史广播给所有客户端

#### Scenario: 旧轮停止请求
- **WHEN** 一轮结束后同一子 agent 已开始新轮，而旧客户端提交上一轮停止请求
- **THEN** 返回已结束或失效状态，不把请求重定向到最新轮，不停止新的任务

#### Scenario: 一身份多轮详情
- **WHEN** 两条主委派卡指向同一子 agent 的不同轮次
- **THEN** 可读取同一连续历史并定位各自轮次，列表只有一条身份摘要，总用量不重复累加

### Requirement: 主会话归档与分叉的委派边界
归档主会话 SHALL 先停止所属未完成委派，再隐藏其访问入口；用户分叉主会话 MUST NOT 复制正在执行的委派。分叉历史中的委派卡 SHALL 可只读查看分叉点之前已有的记录，不授予控制原任务的能力，也不把原任务后续活动或成本计为新分叉任务。历史引用 SHALL 按唯一子会话冻结内容与用量；分叉的可接续身份列表不得包含原会话子 agent。

#### Scenario: 归档运行中主会话
- **WHEN** 用户归档仍有运行或排队子任务的主会话
- **THEN** 所属任务结束取消流程后主会话隐藏，不留下继续执行却无法查看的子任务

#### Scenario: 分叉已有委派
- **WHEN** 用户从含委派卡的主会话创建分叉
- **THEN** 历史卡标识为原会话记录，查看仅限分叉点已有内容，不能停止原任务或复制派发

#### Scenario: 原子 agent 接续不污染分叉
- **WHEN** 用户分叉主会话后，原会话继续向既有子 agent 派发后续任务
- **THEN** 分叉历史仍显示冻结内容和费用，不能接续或停止原子 agent；分叉可创建自己的新子 agent

### Requirement: 子 agent 审批服务
网关 SHALL 提供绑定主会话和子任务的待审批摘要、按需完整审批详情以及允许本次或拒绝接口。决定 SHALL 校验请求身份、操作版本、主子归属和任务可操作状态；不得通过审批接口提交新命令、输入或配置。完整命令 SHALL 有界传输而可完整读取，列表不广播完整命令。状态变化 SHALL 同步到 Web/TUI，即使子详情未打开。

#### Scenario: 双端审批同步
- **WHEN** 一端决定请求而另一端停留在主视图
- **THEN** 两端待审批数和子任务提示同步更新；重复提交返回已决定状态而不重复执行

#### Scenario: 越界、过期和分叉
- **WHEN** 客户端提交其他主会话的请求、改变的操作版本、已取消请求或分叉历史中的审批
- **THEN** 网关拒绝非法或失效决定，不触及其他任务；分叉记录不授予原任务审批能力

#### Scenario: 重连和大命令
- **WHEN** 客户端重连并查看含长命令的待审批请求
- **THEN** 恢复持久状态，通过有界详情读取完整命令，不把省略摘要作为唯一审批依据

### Requirement: 后台任务观察与停止服务
网关 SHALL 在会话视图中提供该会话后台任务的摘要列表（jobId、标题、命令、状态、启动与结束时间、退出码，至多包含运行中任务及最近 20 个已终止任务），并提供按需读取输出与停止单个任务的接口。摘要 MUST NOT 包含输出正文；输出读取 SHALL 有界并支持从偏移继续；停止 MUST 绑定 `jobId`，校验其属于该会话，且只作用于当次运行。状态变化 SHALL 同步到所有已连接前端。

#### Scenario: 双端观察与停止
- **WHEN** Web 与 TUI 同时查看同一会话，一端停止某 job
- **THEN** 两端最终显示相同的 stopped 状态，进程只被终止一次

#### Scenario: 大量输出不广播
- **WHEN** 某 job 持续产生大量输出
- **THEN** 视图推送仅含摘要与状态变化，输出只在客户端按需读取时传输，且每次读取有上限

#### Scenario: 越界与过期请求
- **WHEN** 客户端对不属于该会话的 jobId、已结束 job 或切换会话后的旧引用请求输出或停止
- **THEN** 越界请求被拒绝，已结束的返回现有终态，旧响应不覆盖新选择，不触及无关进程

#### Scenario: 重连
- **WHEN** 前端断线后重新连接
- **THEN** 恢复真实的 job 摘要，不重新启动任何命令，未读完的输出可从偏移继续读取

### Requirement: 后台任务接口的向后兼容
`jobs` 摘要与输出/停止接口 SHALL 作为可选扩展加入，不得使既有客户端失去原有功能。旧客户端连接新网关时 MUST 忽略这些字段而正常工作；新客户端连接不含该能力的旧网关时 SHALL 隐藏或禁用 job 入口并说明需要重新启动网关，MUST NOT 因缺少字段而报错或判定应用协议不兼容。

#### Scenario: 新界面连接旧网关
- **WHEN** 新 TUI/Web 连接尚不支持 job 的旧网关
- **THEN** 会话照常使用，job 面板入口显示不可用及更新提示，不触发协议不兼容的阻断

#### Scenario: 旧界面连接新网关
- **WHEN** 旧版客户端连接新网关并进入有 running job 的会话
- **THEN** 会话照常显示，客户端忽略 job 字段；job 回报按系统消息显示而非报错

### Requirement: 移动入口共用持久运行时

移动入口 SHALL 由当前 gateway 管理并共用同一个持久运行时与会话目录，支持在 TUI、Web 或独立 serve 启动的 gateway 上按需启停，不重启或另开存储。多个前端对同一会话 SHALL 观察同一输入、回答、委派、用量与审批结果；移动资源释放不导致已受理业务终止。

#### Scenario: 复用 TUI 网关
- **WHEN** 先启动 TUI，后启动 Web 并在设置中开启手机访问
- **THEN** 手机连接同一 gateway，已有主/子会话和用量一致，不出现第二个 Harness 或存储占用错误

#### Scenario: 前端和入口关闭
- **WHEN** 复用已有 gateway 的 Web 页面或手机关闭，或手机入口被关闭
- **THEN** gateway 继续持有会话；只释放对应客户端/移动监听资源，不终止 TUI、独立 serve 或已受理任务

#### Scenario: 拉起 gateway 的前端退出
- **WHEN** 手机入口所在的 gateway 由某个前端进程拉起，该前端退出导致 gateway 停止
- **THEN** 手机连接断开并显示电脑不可达；之后任一前端或 serve 再次启动 gateway 时按已保存配置恢复手机入口，已配对设备无需重新扫码

### Requirement: 网关关闭时释放全部移动资源

gateway 收到终止信号或被拉起方关停时 SHALL 在有界时间内关闭：断开移动连接、停止移动监听、关停 WSL Windows 侧中继、释放 WebSocket 与 Unix socket 后退出，Windows 端口文件 MUST 被清除。关闭失败或超时 MUST 以非零状态强制退出，不遗留监听端口或 Windows 侧中继。拉起方对自己拉起的 gateway SHALL 在其未按时退出时强制终止，并在 Windows 补删端口文件。

#### Scenario: 拉起方与网关同时收到信号
- **WHEN** 终端 Ctrl+C 使 web（或 TUI）与其拉起的 gateway 同时收到信号
- **THEN** gateway 完成自身清理，拉起方不重复关停也不因其已退出而报错，两进程均退出且无端口残留

#### Scenario: 网关强制关停
- **WHEN** gateway 在 3 秒宽限内未退出
- **THEN** 拉起方强制终止它；移动监听与中继随进程消失或由中继自身探测断连后退出，下次启动不被占用端口阻塞

#### Scenario: 复用方不终止网关
- **WHEN** 复用已有 gateway 的前端退出
- **THEN** 该 gateway、手机入口与中继保持不变

### Requirement: 搜索设置同步

网关 SHALL 为 TUI/Web 提供服务器级搜索设置的状态订阅与修改能力，无需 attach 会话。状态 SHALL 包含当前选择（tavily、deepseek），凭据的保存或移除 MUST NOT 改变它。修改持久化成功后 SHALL 通知所有已连接前端，断线重连 SHALL 恢复最新状态；响应和广播 MUST NOT 包含密钥。新增该服务 SHALL 递增链路协议版本，沿用"协议版本不同即被明确拒绝"的既有约束，不提供回退。

#### Scenario: 双端同步

- **WHEN** Web 将搜索 provider 改为 tavily 且 TUI 已连接
- **THEN** 两端收到相同的新选择，后续工具调用使用 Tavily，无需重启或切换会话

#### Scenario: 凭据变化不影响选择

- **WHEN** 选择为 deepseek，某前端保存或移除 DeepSeek Key
- **THEN** 所有前端的搜索选择保持 deepseek 不变

#### Scenario: 无会话与重连

- **WHEN** 未 attach 会话的客户端打开搜索设置，或修改期间断线后重连
- **THEN** 可读取并修改设置，重连显示服务端最终状态，不因旧响应覆盖新状态

#### Scenario: 持久化失败与无效取值

- **WHEN** 搜索设置持久化失败，或提交未知 provider 取值
- **THEN** 操作被拒绝并返回不含密钥的错误，不发布成功状态，原选择保持不变

#### Scenario: 协议版本递增

- **WHEN** 仍运行上一协议版本的网关被新版 TUI/Web 连接，或旧版客户端连接新网关
- **THEN** 连接以可识别的协议不兼容原因被拒绝，不进入部分可用状态

### Requirement: 上下文设置同步

网关 SHALL 为 TUI/Web 提供服务器级上下文设置的状态订阅、修改与恢复默认能力，无需 attach 会话。状态 SHALL 包含压缩与裁剪各项的生效值及其来源（默认、配置文件、已保存）。修改 SHALL 先校验再持久化，成功后通知所有已连接前端；断线重连 SHALL 恢复最新状态。新增该服务 SHALL 递增链路协议版本，沿用“协议版本不同即被明确拒绝”的既有约束，不提供回退。

#### Scenario: 多端同步

- **WHEN** Web 修改了压缩触发百分比且 TUI 已连接
- **THEN** TUI 收到新的生效值与来源“已保存”，下一次压缩检查使用新值

#### Scenario: 未 attach 会话与重连

- **WHEN** 未 attach 会话的客户端打开上下文设置，或修改期间断线后重连
- **THEN** 客户端取得最新状态，不会把未到达的状态当作默认值

#### Scenario: 逐项恢复默认

- **WHEN** 客户端清除某项已保存值，或对全部设置恢复默认
- **THEN** 该项生效值回落为配置文件值，无则回落内置默认，来源随之更新并广播

#### Scenario: 非法提交与持久化失败

- **WHEN** 提交未知字段、越界取值，或持久化失败
- **THEN** 修改被拒绝并返回不含内部细节的错误，已保存状态与已广播状态保持不变

#### Scenario: 协议版本递增

- **WHEN** 旧版本客户端连接包含该服务的新网关，或反向连接
- **THEN** 连接被明确拒绝并提示更新后重启

### Requirement: 排队输入观察与撤回服务

网关 SHALL 在会话视图中提供该会话的用户排队输入列表（提交标识、投递方式、有界文字预览、图片数量、技能标记），并提供按提交标识把单条排队输入改为引导、或撤回它的接口。预览 MUST 有长度上限，列表 MUST NOT 含图片数据；两个操作 MUST 校验提交属于该会话，并返回明确结果（已引导、已撤回、已放入、已结束或未知）。引导改变投递方式后提交标识可能变化，前端 SHALL 以视图中的列表为准。列表变化 SHALL 同步到所有已连接前端。

#### Scenario: 多端同步

- **WHEN** Web 与 TUI 同时查看同一会话，一端提交排队消息，另一端把它改为引导或撤回
- **THEN** 两端最终都显示相同的结果，transcript 中不出现重复输入，且只发生一次操作

#### Scenario: 超长输入预览

- **WHEN** 用户排队一条数万字的消息
- **THEN** 视图广播中只含有界预览，完整内容在放入 transcript 后按既有方式读取

#### Scenario: 重连

- **WHEN** 前端断线后重新连接
- **THEN** 恢复真实的排队列表，不重复提交也不自动撤回任何项

### Requirement: 排队接口的向后兼容

排队列表、引导与撤回接口 SHALL 作为可选扩展加入，不提升应用协议版本，不得使既有客户端失去原有功能。旧客户端连接新网关时 MUST 忽略新增字段而正常工作；新客户端连接不含该能力的旧网关时 SHALL 隐藏排队列表、引导与撤回入口，仍允许发送，MUST NOT 因缺少字段而报错或判定应用协议不兼容。

#### Scenario: 新界面连接旧网关

- **WHEN** 新 TUI/Web 连接尚不支持排队列表的旧网关
- **THEN** 会话照常使用，忙时仍可发送，排队列表与撤回入口不显示，不触发协议不兼容的阻断

#### Scenario: 旧界面连接新网关

- **WHEN** 旧版客户端连接新网关并在运行中发送消息
- **THEN** 发送与停止照常工作，客户端忽略排队字段，不报错

### Requirement: 会话目录等待回答标记
会话目录条目 SHALL 可选携带“等待回答”标记，在该会话存在未决的 `ask_user` 问题时为真；标记 SHALL 随问题的建立、结算、取消、停止与会话归档实时更新并推送给已连接前端，不依赖会话 attach。该标记 MUST NOT 改变既有运行状态枚举（会话在等待期间仍为运行中），缺省 SHALL 表示网关不支持而非“无未决问题”，旧会话与旧客户端按缺省处理。分叉会话 MUST 按其自身问题索引计算，不继承父会话的标记。

#### Scenario: 标记随问题生命周期变化
- **WHEN** 会话中的主 agent 提出问题，随后用户回答、跳过或停止运行
- **THEN** 目录广播先将该条目标记为等待回答，结算或取消后清除标记，各前端收到一致的最新目录

#### Scenario: 旧客户端与旧会话
- **WHEN** 旧客户端读取含该字段的目录，或网关加载在此变更前创建、没有问题记录的会话
- **THEN** 旧客户端忽略可选字段、继续显示原有状态；旧会话缺省为不等待，目录不因缺少新文档而报错

#### Scenario: 分叉不继承
- **WHEN** 从有未决问题的会话创建分叉
- **THEN** 分叉的目录条目不携带等待回答标记，父会话的标记保持不变

### Requirement: 工作区文件浏览服务
网关 SHALL 为已附着的会话提供只读文件浏览方法：目录子项查询与文本文件内容读取。路径 SHALL 解析于该会话的工作区，由服务端而非客户端决定工作区根；方法 MUST NOT 接受绝对路径或越界路径，MUST NOT 提供任何写入能力。目录结果 SHALL 含条目名称、相对路径、类型及不完整标记；文件结果 SHALL 含内容、总大小、是否截断、是否二进制，以及受保护文件的说明而非内容。

#### Scenario: 会话工作区解析
- **WHEN** 客户端为会话 A 请求目录 `src`
- **THEN** 结果来自会话 A 的工作区，而非网关启动目录或其他会话的工作区

#### Scenario: 越界与保护
- **WHEN** 客户端请求越界路径或凭据类文件
- **THEN** 越界路径返回明确错误，凭据类文件返回受保护标记且不含内容

### Requirement: 会话改动观察服务
网关 SHALL 提供改动列表与单文件改动详情方法，并在 `ChatView` 中提供可选的改动摘要（文件数、增删行数、revision）。revision SHALL 在改动集合变化时变化，客户端据此按需重新拉取列表；详情 SHALL 有体量上限并标明截断。摘要缺省表示旧网关，空摘要表示支持且尚无改动。改动 MUST 覆盖主 agent 及其子 agent 的 edit/write 成功调用。

#### Scenario: 按 revision 刷新
- **WHEN** agent 修改了新文件，`ChatView` 的改动 revision 变化
- **THEN** 客户端重新拉取列表即可得到新文件，revision 未变时无需重复拉取

#### Scenario: 旧网关识别
- **WHEN** 客户端连接不返回改动摘要的旧网关
- **THEN** 客户端将其视为不支持并隐藏相关入口，而不是显示为「无改动」

### Requirement: 工作区浏览接口的向后兼容
文件浏览与改动接口 SHALL 作为可选扩展加入，沿用既有可选扩展的探测方式，MUST NOT 提升应用协议版本；新客户端连接旧网关、旧客户端连接新网关均 SHALL 正常工作，新增字段对不识别它们的客户端无影响。

#### Scenario: 协议版本不变
- **WHEN** 新版 Web 与新版网关握手
- **THEN** 应用协议版本与此前一致，握手成功且不触发协议不兼容错误

#### Scenario: 旧客户端
- **WHEN** 不识别改动摘要的旧客户端连接新网关
- **THEN** 聊天、审批、提问等既有能力不受影响

### Requirement: provider 启用同步

网关 SHALL 为 TUI/Web 提供服务器级 provider 启用状态的订阅与修改能力，无需 attach 会话。启用状态 SHALL 随各 provider 的凭据状态一并发布；修改持久化成功后 SHALL 通知所有已连接前端，断线重连 SHALL 恢复最新状态。网关 MUST 拒绝未知 provider、取消启用 DeepSeek 以及提交非布尔取值的请求，且不发布成功状态。启用变更 SHALL 同步更新模型列表，响应和广播 MUST NOT 包含密钥。

#### Scenario: 双端同步

- **WHEN** Web 启用 OpenRouter 且 TUI 已连接
- **THEN** 两端收到相同的新启用状态，模型列表包含 OpenRouter 模型，无需重启或切换会话

#### Scenario: 无效请求

- **WHEN** 客户端提交未知 provider、取消启用 DeepSeek，或持久化失败
- **THEN** 请求被拒绝并返回不含密钥的错误，原启用状态保持且不向其他前端发布成功状态

#### Scenario: 无会话与重连

- **WHEN** 未 attach 会话的客户端打开模型服务设置，或修改期间断线后重连
- **THEN** 可读取并修改启用状态，重连显示服务端最终状态，不因旧响应覆盖新状态

### Requirement: provider 拒绝错误码

网关 SHALL 将缺少凭据与 provider 未启用两类受理失败分别以 `PROVIDER_KEY_REQUIRED` 与 `PROVIDER_DISABLED` 返回给客户端，消息包含 provider 名称与可操作指引且不含密钥。该错误码 SHALL 对所有目录内 provider 一致，取代 DeepSeek 专属的错误码。

#### Scenario: 缺少凭据

- **WHEN** 会话模型所属 provider 已启用但没有凭据，客户端提交输入
- **THEN** 客户端收到 `PROVIDER_KEY_REQUIRED` 与 provider 名称，输入不被接受

#### Scenario: provider 未启用

- **WHEN** 会话模型所属 provider 未启用，客户端提交输入或手动压缩
- **THEN** 客户端收到 `PROVIDER_DISABLED`，会话状态与历史不变

### Requirement: 默认模型同步

网关 SHALL 为 TUI/Web 提供服务器级默认模型的状态订阅、设置与清除能力，无需 attach 会话。状态 SHALL 包含生效的默认模型及其来源（命令行、已保存、配置文件、内置默认）。设置 SHALL 先校验再持久化：只接受目录内已启用 provider 的已知模型，不要求已具备凭据；持久化成功后 SHALL 通知所有已连接前端，断线重连 SHALL 恢复最新状态。新增该服务 SHALL 递增链路协议版本，沿用"协议版本不同即被明确拒绝"的既有约束，不提供回退。

#### Scenario: 双端同步

- **WHEN** Web 把某模型设为默认且 TUI 已连接
- **THEN** 两端收到相同的新默认模型与来源"已保存"，之后任一端新建的会话使用该模型，无需重启

#### Scenario: 逐项来源与清除回退

- **WHEN** 保存值存在时清除它，或从未保存时读取状态
- **THEN** 清除后来源回落为命令行、配置文件或内置默认并广播；未保存时来源如实反映命令行、配置文件或内置默认

#### Scenario: 无会话与重连

- **WHEN** 未 attach 会话的客户端读取默认模型，或修改期间断线后重连
- **THEN** 可读取并修改设置，重连显示服务端最终状态，不因旧响应覆盖新状态

#### Scenario: 非法提交与持久化失败

- **WHEN** 提交未知模型、未启用 provider 的模型，或持久化失败
- **THEN** 操作被拒绝并返回可识别错误，不发布成功状态，原默认模型保持不变

#### Scenario: 协议版本递增

- **WHEN** 仍运行上一协议版本的网关被新版 TUI/Web 连接，或旧版客户端连接新网关
- **THEN** 连接以可识别的协议不兼容原因被拒绝，不进入部分可用状态

### Requirement: 运行环境状态

网关 SHALL 在无需 attach 会话的服务器级应用信息中，以可选字段发布 Windows 命令 shell 的状态：可用时给出所选 bash 的路径及来源（配置、自动探测），不可用时给出缺失状态及简短原因（未找到、配置无效）。该字段仅在 Windows 网关上出现，非 Windows 网关 MUST 省略它。状态 SHALL 在网关启动时确定并在每次应用信息检查时重新计算。该字段 MUST NOT 提升应用协议版本：旧客户端忽略它，新客户端在字段缺失时 MUST NOT 显示 shell 提示。

#### Scenario: Windows 上 Git Bash 可用

- **WHEN** 客户端连接已找到 Git Bash 的 Windows 网关
- **THEN** 应用信息包含 shell 可用状态、bash 路径与来源

#### Scenario: Windows 上缺少 Git Bash

- **WHEN** 客户端连接找不到 Git Bash 的 Windows 网关
- **THEN** 应用信息包含 shell 缺失状态与原因

#### Scenario: 非 Windows 或旧网关

- **WHEN** 客户端连接 macOS 网关或不含该字段的旧网关
- **THEN** 应用信息不含 shell 字段，客户端不显示 shell 提示且其他功能正常

#### Scenario: 安装后重新检查

- **WHEN** 用户在网关运行期间安装 Git for Windows，随后客户端触发应用信息检查
- **THEN** 检查结果中的 shell 状态变为可用

### Requirement: Windows 拉起方优雅关停

在 Windows 上，TUI 与 Web 自动拉起网关时 SHALL 以显式参数启用「stdin 关停」，并保持与子进程 stdin 的管道。拉起方关停自己拉起的网关时 SHALL 先关闭该管道，网关收到 stdin 结束后 MUST 执行与终止信号相同的有界清理（停止任务、关闭存储、释放传输、删除端口文件）并退出；未在时限内退出时拉起方 SHALL 强制结束进程并补删端口文件。未启用该参数的网关（独立 `neko serve`、POSIX 拉起）MUST NOT 因 stdin 结束而退出，POSIX 拉起方的停止流程 MUST 保持不变。

#### Scenario: 正常关停

- **WHEN** Windows 上 TUI 退出并关停它拉起的网关
- **THEN** 网关执行清理并以零退出码退出，端口文件被删除，运行中的 job 被正常结算

#### Scenario: 清理超时

- **WHEN** 网关在关闭 stdin 后未在时限内退出
- **THEN** 拉起方强制结束网关进程并删除端口文件

#### Scenario: 拉起方崩溃

- **WHEN** Windows 上拉起网关的 TUI 进程意外终止，stdin 管道随之关闭
- **THEN** 网关执行同样的有界清理后退出

#### Scenario: 独立网关不受影响

- **WHEN** 用户以 `neko serve` 启动网关，其 stdin 被关闭
- **THEN** 网关继续运行

### Requirement: 计划模式视图与决定接口
网关 SHALL 在会话视图中以可选字段发布规划状态（当前模式、当前计划版本、步骤、状态与修订序号），并提供读取计划、批准、要求修改与进入/退出 plan 模式的接口。字段缺省表示网关不支持，不得被解释为"无计划"；支持但无计划时字段存在且计划为空。接口 MUST 校验会话归属、计划版本与反馈长度，错误身份、过期版本与越界输入明确拒绝且不泄漏其他会话内容。该能力 MUST NOT 提升应用协议版本。

#### Scenario: 支持与旧网关
- **WHEN** 新客户端连接支持计划的网关与不支持的旧网关
- **THEN** 前者发布计划字段（可为空），后者字段缺省，客户端据此隐藏计划入口且不调用相关接口

#### Scenario: 多客户端共享
- **WHEN** 两个客户端观察同一会话，其中一个批准计划
- **THEN** 两端视图都更新为已批准，会话模式与工具集一致变化

#### Scenario: 错误版本或会话
- **WHEN** 客户端提交过期版本、未知版本或属于其他会话的计划决定
- **THEN** 请求被拒绝，不改变任何会话的模式或计划状态

### Requirement: 会话目录等待批准标记
会话摘要 SHALL 以可选字段标明会话是否有待批准计划，缺省表示网关不能判断。该标记 MUST 与等待回答标记独立：待批准期间会话不处于运行中，批准、要求修改、取消或取代后标记清除。

#### Scenario: 待批准可发现
- **WHEN** 用户在另一个会话中查看会话列表
- **THEN** 有待批准计划的会话带有明确标记，用户无需进入会话即可发现

#### Scenario: 决定后清除
- **WHEN** 该计划被批准、要求修改或取消
- **THEN** 标记在下一次列表快照中清除

### Requirement: 工作区移除接口

网关 SHALL 在工作区服务上提供移除接口，入参为已登记工作区的路径，成功后 SHALL 把变更后的工作区目录发布给所有订阅者（包括移动 API 的工作区变更通知）。接口 MUST 在网关侧执行移除限制（最后一个工作区、存在活动会话、未登记路径）并串行化与添加的并发修改；被拒绝的请求 MUST NOT 改变目录。该接口 SHALL 随工作区服务契约版本与应用协议版本一并升级，不提供对缺少该接口的旧网关的降级；版本不匹配的连接 SHALL 按应用协议兼容检查被拒绝。

#### Scenario: 移除并广播

- **WHEN** 一个客户端移除某工作区
- **THEN** 其他已连接的 Web 与移动客户端收到更新后的工作区目录，会话目录中属于该工作区的会话不再出现在任一工作区的列表中

#### Scenario: 被拒绝的移除

- **WHEN** 请求移除最后一个工作区、存在活动会话的工作区或未登记的路径
- **THEN** 返回带错误码前缀的错误，工作区目录与会话状态保持不变，不发布目录变更

#### Scenario: 与添加并发

- **WHEN** 一个客户端移除目录 B 的同时另一个客户端添加 B
- **THEN** 两个操作按服务端顺序生效，最终目录与最后一个成功操作一致，不出现重复项或半移除状态

#### Scenario: 协议版本升级

- **WHEN** 运行较低应用协议版本的网关被新版 TUI/Web 连接，或旧版客户端连接新网关
- **THEN** 连接以可识别的协议不兼容原因被拒绝，不进入部分可用状态
