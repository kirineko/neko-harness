# mobile-api Specification

## Purpose
为原生手机客户端提供独立版本、经过设备认证且有界的会话控制接口，复用电脑侧现有持久运行和前端数据语义，支持流式查看与可靠操作而不要求手机实现电脑内部远程对象协议。

## Requirements

### Requirement: 移动 API 认证与兼容

移动 API SHALL 在返回工作区、会话或内容前验证设备授权，并在开放业务操作前校验独立于产品发布版本的 API 兼容性。握手 SHALL 返回电脑身份、运行版本、API 版本、能力及传输限制。不兼容 MUST 明确指出需更新电脑或 App，不无限重连；无效或已撤销凭据不得得到业务数据。

#### Scenario: 不同发布版本
- **WHEN** App 与电脑发布版本不同但移动 API 兼容
- **THEN** 可继续使用已支持的功能，不要求双方产品版本号完全一致

#### Scenario: 未授权或协议不兼容
- **WHEN** 手机未配对、授权已撤销或 API 不兼容
- **THEN** 业务读取和控制均不就绪，返回可区分的授权或升级提示，不泄露会话内容

### Requirement: 移动控制能力边界

移动 API SHALL 只开放已登记工作区列表、会话列表/创建/查看、文字提交、显式停止、子 agent 查看/停止、待决命令审批、会话历史媒体读取、主会话待办读取、主会话问题查询/回答/跳过及主会话计划查询/批准/要求修改/取消并退出。接口 MUST 校验所有参数及对象归属，不提供任意内部服务调用、宿主路径读取、直接 Bash 执行、凭据修改、模型配置、plan 模式进入、会话归档/分叉、后台任务、技能安装、配对管理、远程升级、待办直接修改或手机附件上传能力。新增移动 API MUST NOT 破坏现有桌面客户端使用的服务契约。

#### Scenario: 已登记工作区使用
- **WHEN** 手机在已登记工作区 B 中创建并选择主会话
- **THEN** 与 TUI/Web 使用同一目录、模型默认配置和持久会话，工具默认目录来自 B；工作区选择不声称构成工具文件访问沙箱

#### Scenario: 越权方法与引用
- **WHEN** 手机调用未开放方法、使用未知工作区或读取不属于目标会话的图片/子 agent
- **THEN** 在副作用或内容读取前明确拒绝，不落回网关启动目录，不解析为任意宿主路径

#### Scenario: 新增交互不扩大任意控制
- **WHEN** 手机读取待办、回答一个主会话问题或对计划做出决定
- **THEN** 仅访问当前有效订阅会话的相应对象，不获得待办写入、子 agent 提问、plan 模式进入、普通工具执行或其他内部服务访问权限

### Requirement: 移动快照与观察资源

连接及 attach SHALL 以首个有效快照到达作为对应操作就绪条件。状态更新 MUST 绑定连接代次、订阅及会话身份；切换、detach 或重连后旧响应不得覆盖新视图或继续操作旧 attachment。断开 SHALL 释放该客户端订阅、查询和引用，不停止共享会话或其他客户端观察。

#### Scenario: 快速切换会话
- **WHEN** 手机切换会话后旧会话的订阅或控制响应迟到
- **THEN** 不覆盖新视图或误向新会话提交，旧引用调用明确失败

#### Scenario: 重连与多前端
- **WHEN** 手机断线期间电脑继续执行，随后手机重新连接
- **THEN** 取得最新快照并按需补历史，不逐事件重放，也不创建第二份 Agent 任务；其他前端持续工作

### Requirement: 移动历史与内容有界传输

主/子会话 SHALL 返回最近记录并支持稳定分页补齐较早历史，保留持久消息顺序、工具配对及轮次。过大正文和工具结果 SHALL 提供明确的按需分块读取，不静默截断。图片只在状态中携带描述，按需有界读取。协议 SHALL 公布帧、页面、请求并发和发送缓冲限制，慢连接或无效帧只影响该连接。

#### Scenario: 长历史和长工具结果
- **WHEN** 手机打开含大量主/子记录或单个超长工具结果的会话
- **THEN** 初始状态与每个传输单元遵守限制，用户可以补齐历史和完整结果，无重复或丢失已保存内容，原工具截断标记仍可辨识

#### Scenario: 持久图片
- **WHEN** 手机读取主/子历史图片且原宿主文件已经消失
- **THEN** 从会话持久附件读取；无效条目或内容位置被拒绝，不暴露任意文件

#### Scenario: 慢客户端
- **WHEN** 手机持续无法消费状态更新或发送超限帧
- **THEN** 服务端合并可合并状态或关闭该连接，不无限缓存，不阻塞本地前端或 Agent 运行

#### Scenario: 引用失效
- **WHEN** 手机使用的历史游标或长内容引用因会话内容变化而失效
- **THEN** 返回可区分的失效结果，手机重新获取最新快照或条目，不拼接新旧两个版本的内容

### Requirement: 文字提交与持久去重

文字提交 SHALL 使用绑定电脑、主会话及原始内容的稳定业务请求标识，按现有持久输入语义受理；成功回执表示输入已受理，不表示回答完成。相同请求重复或网关重启后重试 MUST 不重复输入。App SHALL 可查询受理状态，未知结果不能冒充失败或成功。忙碌时 SHALL 与 Web 相同由电脑持久排队（缺省），或在用户显式选择时作为引导（steer）插入；回执 SHALL 标明是否排队。排队由电脑服务完成，客户端不得自行缓存或延后发送。

#### Scenario: 成功回执丢失
- **WHEN** 电脑已持久受理输入但手机断线未收到回执
- **THEN** 重新连接后查询或用同一请求标识和原内容重试可确认受理，不产生第二条用户输入或第二次相同任务

#### Scenario: 忙碌时提交
- **WHEN** 主会话正在运行时手机提交文字
- **THEN** 电脑持久受理并排队（或按用户选择引导当前运行），手机显示已受理及排队状态，与 TUI/Web 观察到同一条输入

#### Scenario: 受理失败
- **WHEN** 参数无效、会话已失效或电脑缺少模型凭据
- **THEN** 返回实际拒绝原因，手机保留草稿，不显示输入已发送或自动改为其他提交策略

### Requirement: 子 agent 连续查看与用量

移动 API SHALL 通过主会话提供稳定子 agent 列表、连续历史、各轮任务及当前运行状态，按主子归属校验详情、历史和停止。详情 SHALL 包含与主会话同类的可见内容、累计及可确认的本轮用量，沿用电脑的去重汇总。停止 MUST 绑定目标活动轮；详情不得提交子会话输入或直接派发任务。

#### Scenario: 接续和用量
- **WHEN** 主 agent 多轮使用同一个子 agent，手机同时查看主/子内容
- **THEN** 列表保持同一身份并展示轮数，连续历史可查看，主总用量不因手机观察而重复累计

#### Scenario: 旧轮停止
- **WHEN** 子 agent 已进入下一轮但手机使用上一轮的停止引用
- **THEN** 返回已结束或引用失效，不停止新一轮或其他任务

### Requirement: 跨端审批一致性

移动 API SHALL 汇总提供所属主会话下各子 agent 的未决 Bash 审批及完整命令、目录、显式超时、请求身份和决定版本，并支持允许本次与拒绝。决定 MUST 复用电脑的持久审批语义，校验当前请求和委派关系；多个前端竞争只能产生一个有效决定，重连不重新弹出已结算请求，不绕过审批执行命令。

#### Scenario: 手机与电脑竞争
- **WHEN** 手机允许本次时 Web/TUI 已经拒绝同一审批
- **THEN** 手机收到最终拒绝状态，不重复执行，不因手机旧界面覆盖电脑决定

#### Scenario: 请求结束或授权撤销
- **WHEN** 子任务已停止、审批已失效或设备被撤销后手机发送决定
- **THEN** 决定被拒绝或返回实际终态，不执行命令；其他有效前端仍可处理尚未结算的请求

### Requirement: 移动会话列表排序与时间语义

移动 API 的会话列表 SHALL 按最近消息时间倒序排序，无消息的会话使用创建时间，时间相同按会话 ID 倒序，与电脑 Web 的会话排序一致。每个会话摘要 SHALL 提供最近消息时间，打开会话、重复请求、流式片段、标题生成和配置修改 MUST NOT 改变排序。该字段为新增字段，MUST NOT 提高 API 版本，缺少该字段的旧网关由客户端回退到最近使用时间。

#### Scenario: 打开不改变顺序
- **WHEN** 手机打开或 attach 某个会话但未提交消息，随后重新列出同工作区会话
- **THEN** 该会话的位置与相对顺序不变，摘要中的最近消息时间不变

#### Scenario: 发送后置顶
- **WHEN** 手机或电脑向某会话提交消息并被受理
- **THEN** 该会话的最近消息时间更新，重新列出时位于同工作区首位，并收到会话列表变化通知

#### Scenario: 无消息会话与同时间
- **WHEN** 工作区内存在从未发送消息的新会话，或多个会话时间相同
- **THEN** 新会话按创建时间参与排序，时间相同按会话 ID 倒序，分页游标下无重复、无遗漏

#### Scenario: 版本兼容
- **WHEN** 旧 App 连接新网关，或新 App 连接缺少该字段的旧网关
- **THEN** 旧 App 忽略新增字段并按服务端顺序展示；新 App 回退使用最近使用时间且不报错

### Requirement: 移动排队列表与引导、撤回接口

移动会话状态 SHALL 提供可选的排队输入列表（提交标识、投递方式、有界文字预览、图片数量），并提供按提交标识把单条排队输入改为引导（`chat.steer`）或撤回它（`chat.withdraw`）的方法，结果区分已引导、已撤回、已放入、已结束与未知；撤回成功时返回完整原文以便取回草稿。两个方法 MUST 需要已授权设备且校验提交属于该订阅会话，MUST NOT 暴露其他会话或系统生成输入。字段缺省表示电脑端不支持，客户端 SHALL 隐藏该能力而不报错。`chat.submit` 的 `mode` 参数保持可用以兼容旧客户端。

#### Scenario: 状态含排队项

- **WHEN** 手机订阅的主会话在运行中被 Web 提交了排队消息
- **THEN** 手机状态更新中带出该项，放入 transcript 后从列表消失

#### Scenario: 引导排队项

- **WHEN** 手机对一条排队项调用引导
- **THEN** 状态更新中该项投递方式变为引导，其余项与当前运行不变，桌面前端看到相同结果

#### Scenario: 撤回竞争

- **WHEN** 手机撤回或引导时该消息刚被放入上下文
- **THEN** 返回已放入，消息保留在会话中，不重复也不丢失

#### Scenario: 未授权或越界

- **WHEN** 未授权设备或旧订阅引用请求引导或撤回
- **THEN** 请求被拒绝，不改变任何会话的排队项

#### Scenario: 旧电脑端

- **WHEN** 新 App 连接不提供排队列表的旧电脑端
- **THEN** 忙时仍可排队发送，不显示排队条、引导与撤回，不判定协议不兼容

### Requirement: 移动待办与问答能力协商
移动握手 SHALL 增量声明 `todos` 和 `questions` 能力，不提高移动 API 版本。新 App 连接旧电脑时 SHALL 隐藏缺失能力；旧 App 连接新电脑时现有接口保持可用。待办版本、进度和未决问题摘要 SHALL 可在 attach 和重连后重建，随后变化可观察，不依赖客户端保留完整事件流。声明 `questions` 能力时，会话列表条目 SHALL 可选携带“等待回答”标记，缺省表示不支持，旧 App 忽略该可选字段。

#### Scenario: 新旧两端组合
- **WHEN** 新 App 连接无新增能力的电脑，或旧 App 连接具有新增能力的电脑
- **THEN** 已有会话、聊天、审批正常使用，不误报 API 不兼容，不调用未声明的新接口

#### Scenario: 快照与变化竞争
- **WHEN** 手机 attach 或重新连接时待办与问题发生变化
- **THEN** 通过带版本的最新状态及后续通知收敛到当前数据，不遗漏恰在首个查询期间建立的问题

#### Scenario: 其他会话的等待可见
- **WHEN** 手机停留在会话列表或会话 B，会话 A 出现未决问题
- **THEN** 列表条目 A 带“等待回答”标记并随结算清除；缺少该能力的电脑不带标记，App 不推测阻塞状态

### Requirement: 移动问答读取与回答
移动 API SHALL 提供当前订阅会话的待办读取、未决问题摘要、单题完整读取及回答/跳过接口，复用电脑持久结算语义。接口 MUST 在读取或副作用前校验设备授权、订阅有效性、会话归属、问题版本及答案；响应遵守已公布传输限制，完整题目和选项不得静默截断。

#### Scenario: 回答与普通提交分离
- **WHEN** 手机对未决问题提交选项（多选问题可提交多个）和/或文字
- **THEN** 同一工具调用得到答案，普通提交队列和输入历史不增加，Web/TUI 同步移除未决操作；选项与文字作为独立字段保留，非法组合（单选多个选项、既无选项也无文字）在副作用前被拒绝

#### Scenario: 撤销授权和旧订阅
- **WHEN** 设备被撤销、手机已切换会话，或问题不属于当前订阅
- **THEN** 读取及回答被明确拒绝，不显示其他会话的题目，不将迟到答案应用于当前新会话

#### Scenario: 有界完整读取
- **WHEN** 合法待办或问题包含多字节文字且接近公布上限
- **THEN** 单次完整读取仍满足移动 payload 和 frame 限制，超过输入上限的内容在建立时被明确拒绝而非在传输时丢失

#### Scenario: 回执丢失和冲突
- **WHEN** 回答已保存但回执丢失，手机重试时另一端也提交不同答案
- **THEN** 返回已持久保存的同一终态及实际答案，不产生新输入或覆盖原答案

### Requirement: 移动计划查询与决定
移动 API SHALL 提供主会话计划的查询、批准与要求修改，能力通过 hello 协商并作为增量能力 `plan`，不升级 API 版本。会话状态 SHALL 携带可选的计划摘要（修订序号与是否待批准），变化时发出通知；摘要缺省表示该电脑不支持。接口 MUST 绑定当前有效订阅与会话，校验计划版本与反馈长度（沿用桌面上限），首次有效决定生效，重复提交返回已保存记录。手机 SHALL 额外获得「取消待批准计划并退出 plan 模式」的方法 `plan.exit`（同样绑定订阅与会话，会话运行中拒绝，已是 normal 时幂等成功）；手机 MUST NOT 获得进入 plan 模式的能力。

#### Scenario: 能力协商与空状态
- **WHEN** 手机连接支持计划的电脑并 attach 会话
- **THEN** hello 声明 `plan` 能力，状态带有"支持且无待批准计划"的摘要

#### Scenario: 手机批准
- **WHEN** 手机对当前待批准版本提交批准
- **THEN** 桌面会话退出 plan 模式并开始执行，所有端展示相同结果

#### Scenario: 手机取消并退出
- **WHEN** 手机对有待批准计划的会话调用 `plan.exit`
- **THEN** 计划变为已取消，会话回到 normal 模式，状态摘要与会话列表的待批准标记清除并发出通知，没有执行输入被提交

#### Scenario: 不能进入模式
- **WHEN** 手机尝试进入 plan 模式或调用其他模式切换方法
- **THEN** 该方法不存在，请求被明确拒绝，模式不变

#### Scenario: 旧订阅或越权
- **WHEN** 手机在切换会话或设备撤销后提交计划决定
- **THEN** 在副作用前被拒绝

### Requirement: 移动 codemode 调用数据

移动 API 的工具项 SHALL 以可选字段提供 codemode 调用的嵌套调用列表与完整输出文件路径，内容与上限同桌面会话视图一致。该字段为新增字段，MUST NOT 提高移动 API 版本；缺少该字段时 App SHALL 按普通工具项显示。移动 API MUST NOT 因此获得修改 codemode 设置的能力。

#### Scenario: 新 App 连接旧电脑
- **WHEN** App 连接不提供该字段的电脑
- **THEN** codemode 调用按普通工具项显示，连接与其他功能正常

#### Scenario: 运行中的脚本
- **WHEN** 手机打开的会话里有正在运行的 codemode 脚本
- **THEN** 工具项随嵌套调用的开始和结束更新，与电脑端看到的一致
