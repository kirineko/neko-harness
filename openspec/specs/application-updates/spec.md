# application-updates Specification

## Purpose

管理 neko 的发布版本识别、稳定渠道更新检查与用户主动执行的安装升级，使用户能够区分可安装的新版本和各运行组件尚未生效的版本，并获得明确的下一步操作。

## Requirements

### Requirement: 安装与运行版本区分

系统 SHALL 分别识别当前安装版本、运行中的 gateway 版本、TUI 或 Web 静态服务版本及浏览器页面版本。版本未知或开发模式 MUST NOT 被解释为最新版本；运行版本 MUST 反映实际加载的构建，不随安装文件更新而伪装成新版。面向用户的版本概览 SHALL 默认呈现单项主要生效版本与当前状态（如已是最新），仅在存在更新或组件未生效时呈现对应目标版本与操作建议，不向用户平铺罗列内部各组件独立版本与多重已安装状态。

#### Scenario: 安装更新但网关未重启
- **WHEN** 安装版本已更新，gateway 仍运行更新前的构建
- **THEN** 状态明确表示网关需要重启，不继续要求安装同一个版本，也不宣称升级已全部生效

#### Scenario: 页面与静态服务不同步
- **WHEN** 浏览器页面仍为旧构建，静态服务已为新版，或静态服务也仍为旧构建
- **THEN** 前者要求刷新页面，后者要求先重启 Web 服务，不将两者都解释为刷新即可解决

#### Scenario: 未知与开发版本
- **WHEN** 无法读取安装信息或运行的是开发构建
- **THEN** 显示未知或开发状态，不伪造“已是最新版”；开发构建不自动查询发布渠道

#### Scenario: 版本概览与降噪
- **WHEN** 用户查看系统版本概览且各运行组件版本一致且为最新
- **THEN** 界面呈现单个当前版本与已是最新状态，不平铺罗列各组件运行与已安装重复版本

### Requirement: 非阻塞稳定渠道检查

系统 SHALL 有界地检查 npm 稳定渠道，并缓存、合并重复查询。后台检查 MUST NOT 延迟界面就绪、阻塞聊天或因失败反复报错；只有经过验证且高于已安装版本的稳定版本才 SHALL 触发可安装更新提示。显式检查 SHALL 返回准确结果或简短的可重试错误。

#### Scenario: 多端并发与缓存
- **WHEN** TUI 和多个 Web 页面同时查看更新状态
- **THEN** 不为每个页面独立访问 npm，有效缓存复用，同一进程的并发检查共享结果

#### Scenario: 离线与异常响应
- **WHEN** 网络超时、npm 不可达、响应超限或版本信息无效
- **THEN** 聊天继续可用，不显示虚假的已最新；主动检查显示“检查失败，请重试”或对应英语提示

#### Scenario: 本地版本更高
- **WHEN** 已安装版本等于或高于稳定渠道版本
- **THEN** 不提示可安装更新，不执行降级

### Requirement: 用户执行 CLI 升级

在 macOS/Linux 上，`neko update` SHALL 检查并升级当前受支持的 npm 全局安装，成功后验证实际安装版本，再输出新版本和重新启动提示。已最新 SHALL 成功退出且不执行安装；查询、安装或验证失败 SHALL 非零退出。命令 MUST NOT 自动停止、重启 gateway 或界面，也 MUST NOT 修改会话和凭据。

#### Scenario: 正常升级
- **WHEN** 用户在受支持的安装中执行命令，稳定渠道有较新版本且安装验证成功
- **THEN** 输出已升级版本和重新启动 neko 的简短说明，不把仍运行的旧进程视为已重启

#### Scenario: 安装失败或验证不一致
- **WHEN** 安装命令失败，或退出成功但实际安装版本未达到目标
- **THEN** 返回失败和简短恢复操作，不输出升级成功，不承诺自动回滚安装文件

#### Scenario: 全局安装目录不可写
- **WHEN** 当前用户对 npm 全局安装目录没有写权限
- **THEN** 返回失败并给出手动命令 `npm install -g neko-harness@latest`，不自行提升权限，不输出升级成功

#### Scenario: 不受支持的安装
- **WHEN** macOS/Linux 上命令运行于源码、项目局部安装、链接安装、Bun 或其他包管理器的全局安装，或无法确认的安装位置
- **THEN** 不隐式新增或修改另一份全局安装；说明当前方式不支持自升级，并指引按原安装方式更新或改用 `npm install -g neko-harness` 安装

#### Scenario: 并发升级
- **WHEN** 同一安装已存在进行中的升级命令
- **THEN** 第二个命令不重复安装，简短提示稍后重试，结束或失败后释放升级占用

#### Scenario: Windows 手动升级指引
- **WHEN** 用户在 Windows 执行有效的 `neko update`
- **THEN** 输出先退出 neko、运行 `npm install -g neko-harness@latest` 并重新启动的简短指引，正常退出；不声称已升级或已最新，不进行安装识别、联网检查、升级占用或包安装，也不修改会话及凭据

#### Scenario: Windows 帮助和参数
- **WHEN** Windows 用户请求 `neko update --help` 或提供无效参数
- **THEN** 帮助说明手动更新命令；无效参数仍按用法错误非零退出，不输出升级成功

### Requirement: 明确的下一步状态

系统 SHALL 将可安装更新、需重启网关、需重启界面或静态服务、需刷新页面及协议不兼容作为不同状态。可兼容的版本差异 SHALL 只提示，不中断任务；提示 MUST 给出与实际状态相符的下一步，不因提示出现而执行安装、刷新或重启。仅当检测到高于当前运行版本的发布版本或未重启组件时，系统才在版本信息中呈现该目标版本及对应操作引导。

#### Scenario: 多种差异并存
- **WHEN** 新版本已安装而 gateway 与 Web 静态服务仍旧，页面也旧
- **THEN** 优先提示重新启动本地 neko 服务，再判断页面刷新；不提供仅刷新即可生效的错误操作

#### Scenario: 状态修复
- **WHEN** 用户完成安装、重新启动或手动刷新，组件版本重新一致
- **THEN** 后续检查移除已解决提示，不保留过时的升级或重启建议

#### Scenario: 条件呈现目标版本
- **WHEN** 稳定渠道存在已验证的新版本
- **THEN** 界面在当前版本下方显式展示最新版本及升级引导，未检测到新版本时不常驻显示空态或重复的最新版本项
