# web-ui Specification

## Purpose

浏览器前端：经 WebSocket 连接会话网关，提供与终端对等的对话、插话与会话管理能力。

## Requirements

### Requirement: 浏览器对话

系统 SHALL 提供 Web 界面，用户可在浏览器中提交输入、查看流式回答与工具调用详情，功能与终端前端对等。

#### Scenario: 打开即用

- **WHEN** 用户在浏览器打开 Web UI 并选择会话
- **THEN** 显示该会话的完整历史，后续事件实时到达

### Requirement: 断线重连

系统 SHALL 在 WebSocket 断开后自动重连；重连后从当前视图状态恢复，不重放历史事件。重连 SHALL 保留当前工作区并优先恢复原会话；原会话已归档时仅回退到同工作区最近使用会话，无可用会话则显示该工作区空态。连接建立与实际状态就绪 MUST 分开：目录、工作区和凭据首个快照到达后才能开放管理操作，当前会话视图到达后才能开放会话操作；失效连接的迟到响应 MUST 不覆盖新连接。

#### Scenario: 网络抖动恢复

- **WHEN** WebSocket 断开 10 秒后恢复
- **THEN** 界面自动重连并展示会话最新状态，期间到达的回答完整可见，工作区不变

#### Scenario: 原会话不再可用

- **WHEN** 断线期间原会话被另一前端归档
- **THEN** 重连后选择同工作区最近使用会话或显示空态，不连接其他工作区会话

#### Scenario: 连接已建立而快照未到达

- **WHEN** 初次连接或重连的服务已绑定，但首个订阅快照仍在传输中
- **THEN** 相应管理或会话操作保持未就绪，不将旧视图或空状态当成新快照；失败时保留草稿并提供错误反馈

### Requirement: 静态托管

Web UI SHALL 构建为静态资源，由网关进程托管，无需独立前端服务器。

#### Scenario: 随网关启动

- **WHEN** 网关进程启动
- **THEN** 浏览器访问网关 HTTP 地址即可加载 Web UI

### Requirement: 二次元主题系统

系统 SHALL 使用全站统一的 design tokens，默认主题为蓝粉白「樱花」：导航（侧栏、顶栏、抽屉）、弹层（菜单、目录选择面板、对话框）、聊天内容、输入卡片（含模型入口与遥测控件）与设置页共用同一樱花粉/天依蓝/白 token 体系，滚动条、表单、焦点环和按钮全站一致。用户可在外观设置中切换到其他主题，其他主题 MUST 复用同一套 token 名而不是另建区域样式。正文与控件字号 SHALL 来自统一定义的紧凑字号阶梯；Markdown 行内代码 SHALL 采用中性浅底样式而非主题色药丸；模型输出的 Markdown 渲染前 MUST 经过消毒。

#### Scenario: 默认浅色主题

- **WHEN** 用户从未调整外观并打开 Web UI
- **THEN** 侧栏、顶栏、弹层、聊天区、输入卡片与设置页均呈统一的蓝粉白浅色主题，无中性灰导航区域，正文文本相对背景对比度达到 WCAG AA

#### Scenario: 主题色应用一致

- **WHEN** 界面渲染按钮、链接、状态徽章、聊天气泡、侧栏选中态、滚动条与各级弹层
- **THEN** 颜色、圆角、焦点环与阴影均来自同一套 design tokens，不存在第二套区域主题；切换主题时这些元素一并变化

#### Scenario: 字号与密度阶梯

- **WHEN** 渲染正文、辅助文字、标题与控件
- **THEN** 字号与间距取自统一定义的紧凑阶梯，聊天区正文默认基准为 14px 档（可由聊天排版偏好调整），无散落的一次性硬编码字号

#### Scenario: 行内代码降噪

- **WHEN** 模型回答包含大量行内代码标识符
- **THEN** 行内代码以中性浅底加等宽字体呈现，不使用高饱和主题色药丸，代码块语法高亮不受影响

#### Scenario: 模型输出消毒

- **WHEN** 模型回答中包含 HTML 标签或脚本内容
- **THEN** 界面渲染为无害文本或经消毒的标记，不执行任何脚本

### Requirement: 工作区会话导航

Web SHALL 以工作区切换器和当前工作区会话列表组织导航，显示可辨识的目录名称和完整路径。首次打开或刷新 SHALL 以 Web 启动时指定的目录或启动目录为初始工作区；进入工作区 SHALL 恢复其最近使用的非归档会话，无会话则展示新建入口。Web MUST 保留访问网关其他工作区的入口。

#### Scenario: 启动目录与共享网关

- **WHEN** Web 从 B 启动或指定 B，复用启动于 A 的网关
- **THEN** 浏览器初始进入 B；会话列表仅展示 B 的非归档会话，用户可通过工作区切换器进入 A

#### Scenario: 切换与同名目录

- **WHEN** 用户在两个同名但路径不同的工作区之间切换
- **THEN** 切换器通过父路径区分它们，可查看完整路径，并分别恢复各自最近使用会话

#### Scenario: 会话排序与搜索

- **WHEN** 当前工作区有多个会话且用户输入搜索词
- **THEN** 列表按最近消息时间降序排列，无消息时使用创建时间，同时间按会话 ID 稳定倒序；搜索匹配当前工作区的标题、首问摘要与 ID，无匹配时明确提示

### Requirement: 工作区内会话操作

Web 新建会话 SHALL 显式绑定当前工作区。归档当前会话后 SHALL 进入同工作区最近使用会话，无会话则保留工作区空态。会话切换与新建期间 MUST 防止重复提交、过期异步结果覆盖新选择或向旧会话误发输入。

#### Scenario: 创建与工具目录

- **WHEN** 用户在 B 中新建会话，而网关启动目录为 A
- **THEN** 新会话保存 B，工具默认在 B 执行，TUI 与 Web 看到相同归属

#### Scenario: 归档当前或其他会话

- **WHEN** 用户确认归档当前会话或其他会话
- **THEN** 当前会话归档后只在同工作区内回退，其他会话归档不改变当前选择；最后一个会话归档后保留工作区且不自动创建会话

#### Scenario: 快速操作与失败

- **WHEN** 用户快速切换工作区或重复点击新建，或服务请求失败
- **THEN** 操作被有序处理，界面选择与可提交输入的实际会话一致，失败有可重试反馈且不会静默切换工作区

### Requirement: 通过宿主目录面板添加工作区

Web SHALL 提供内置目录选择面板，选择 Harness 宿主上的目录。面板 SHALL 提供路径导航、上级目录、完整路径输入、名称过滤、隐藏目录开关、取消与确认。面包屑与路径拼接 MUST 按宿主平台处理分隔符与盘符，不得把 Windows 盘符路径拼接为带前导斜杠的非法形态。Windows 宿主的根层 SHALL 列出可用盘符以支持跨盘选择。只有用户确认且服务端验证成功后才添加并进入工作区；服务端 MUST 归一化带前导斜杠的盘符路径输入。

#### Scenario: 默认位置与确认

- **WHEN** 用户打开添加工作区面板并确认一个目录
- **THEN** 面板默认定位当前工作区或首次使用的 Web 启动目录，固定显示待选目录与确认操作；成功后进入对应工作区，有会话则恢复，无会话则展示新建入口

#### Scenario: 取消与重复添加

- **WHEN** 用户取消选择或选择已存在的真实目录
- **THEN** 取消不新增记录、不改变当前会话；重复选择直接进入已有工作区

#### Scenario: 加载错误与过期结果

- **WHEN** 浏览失败、请求缓慢或关闭面板后旧请求返回
- **THEN** 面板呈现加载或错误反馈并允许取消、重试或输入其他路径；旧响应不重开面板或覆盖新的目录选择

#### Scenario: Windows 盘符路径导航

- **WHEN** 宿主为 Windows，用户经面包屑或路径输入导航 `D:\code` 形式的盘符路径
- **THEN** 面包屑按盘符与双分隔符正确切分与拼回；服务端对 `/D:\code` 这类带前导斜杠的输入归一化后照常浏览，不报路径不可用

#### Scenario: Windows 盘符枚举

- **WHEN** 宿主为 Windows，用户导航到根层（`/`）
- **THEN** 面板列出可用盘符（如 `C:`、`D:`），选择盘符后进入其根目录继续浏览，可跨盘选择工作区

### Requirement: 响应式导航与可访问操作

侧栏 SHALL 采用紧凑行布局、轻量图标与明确选中状态，新建入口持续可见，会话次要操作通过菜单展示。侧栏底部 SHALL 明确提供平级的「技能市场」与「设置」独立导航入口。鼠标、键盘和触屏 MUST 均可访问操作；归档 SHALL 使用可取消的明确确认。桌面侧栏 SHALL 可折叠，移动端 SHALL 默认收起并通过抽屉打开。页面 SHALL 提供主内容 landmark 与跳转主内容的 skip-link；移动断点与消息列宽各档位 MUST 在脚本与样式间单一来源，会话悬浮提示 SHALL 与触发元素建立可访问关联。

#### Scenario: 菜单与归档确认

- **WHEN** 用户悬停、键盘聚焦或在触屏访问会话行
- **THEN** 可访问操作菜单，菜单不被列表滚动区域裁切；归档确认不依赖限时二次点击，取消保留会话

#### Scenario: 侧栏底部独立导航入口

- **WHEN** 用户查看侧栏底部区域
- **THEN** 呈现平级的技能市场入口与设置入口，点击分别导航至独立技能市场大盘页面与设置页面

#### Scenario: 焦点与抽屉

- **WHEN** 用户用键盘打开和关闭菜单、目录面板或移动端抽屉
- **THEN** 焦点进入对应界面，模态界面约束焦点，Escape 可关闭并将焦点返回触发控件，隐藏侧栏不保留可 Tab 访问的控件

#### Scenario: 键盘直达主内容

- **WHEN** 用户使用键盘首次 Tab 进入聊天页
- **THEN** 出现跳转主内容的 skip-link，激活后焦点落入主内容 landmark；会话悬浮提示可通过 aria 关联被辅助技术朗读

#### Scenario: 小屏幕与长目录

- **WHEN** 在 1440、1024、768 和 375 像素宽度下使用长目录名和长会话列表
- **THEN** 导航、滚动与操作按钮不重叠，路径可查看完整内容，抽屉可关闭且不会遮住无法访问的操作

#### Scenario: 宽屏导航

- **WHEN** 在 1920 或 2560 像素宽度下使用长目录名和长会话列表
- **THEN** 侧栏与顶栏不横向溢出，工作区切换面板与抽屉可正常操作，聊天区列宽按分档抬升

### Requirement: 会话标题与相对时间展示

Web 侧栏 SHALL 为每个会话展示统一名称、距最近消息的相对时间及必要的运行状态；标题优先使用生成结果，其次首问摘要，空会话使用新会话占位。顶栏与归档确认 SHALL 使用相同名称，MUST NOT 展示内部会话 ID（包括提示和辅助技术标签），可通过完整时间辅助区分同名会话。长标题 MUST 不遮挡时间和操作入口。

#### Scenario: 标题异步到达

- **WHEN** 当前或后台会话的标题生成完成
- **THEN** 侧栏及相关会话上下文更新名称，不切换当前会话、不影响输入草稿、不因命名改变排序

#### Scenario: 时间持续更新

- **WHEN** 页面保持打开且最近消息逐渐变旧
- **THEN** 相对时间自动更新，用户可通过鼠标或键盘查看准确时间；时钟偏差不产生负数时长

#### Scenario: 长标题与小屏幕

- **WHEN** 在桌面或移动端展示长标题和长会话列表
- **THEN** 标题适当截断但可查看完整内容，时间与菜单入口可访问，保留导航中性色和聊天区原有主题

### Requirement: 凭据设置页

Web 设置页 SHALL 以美观紧凑的「模型服务」页组织模型凭据配置，风格与全站统一的蓝粉白 design tokens 一致，侧栏菜单项名称为「模型服务」，路径保持 `/settings`。页面 SHALL 提供可键入搜索的 provider 下拉，覆盖内置 provider 目录，每项标注已启用/未启用与 Key 状态；选中某 provider 后页面只显示该 provider 的凭据卡，卡内提供启用勾选（DeepSeek 始终启用且不可取消）、生效来源、环境变量配置状态、密码输入、保存、移除保存值和对应的密钥申请链接，不要求先有 Key 才能启用。深链 `/settings#credential-<provider>` SHALL 选中并定位该 provider。页面 SHALL 保留返回入口和简短连接状态，不将 serverId、socket 路径等技术详情作为主要内容。已有 Key MUST NOT 回填，保存或离开页面后清除敏感输入。

#### Scenario: 保存和回退

- **WHEN** 用户在已有环境变量的情况下保存 Key，再移除保存值
- **THEN** 来源由环境变量变为保存值再回到环境变量，环境变量状态始终显示已配置；成功后密码框清空

#### Scenario: 启用 provider

- **WHEN** 用户在模型服务页下拉选中 OpenRouter，勾选启用并保存其 Key
- **THEN** 聊天区模型选择器的 provider 下拉出现 OpenRouter 且模型可选；取消勾选后该项消失，已保存 Key 保留

#### Scenario: 默认与锁定

- **WHEN** 新用户首次打开模型服务页
- **THEN** 默认选中 DeepSeek，其勾选不可取消并说明原因；其余 provider 在下拉中标为未启用

#### Scenario: provider 下拉与搜索

- **WHEN** 用户打开 provider 下拉并输入 `open`
- **THEN** 列表只含名称、id 或环境变量名匹配的 provider（如 OpenRouter、OpenAI、OpenCode Go/Zen），选中其一后页面只显示该 provider 的凭据卡；Tavily 不出现在本页，而在联网搜索页管理

#### Scenario: 多 provider 展示

- **WHEN** 用户打开模型服务页且仅 DeepSeek 已启用
- **THEN** 页面显示 DeepSeek 的凭据卡，其余 provider 在下拉中以同一格式列出为未启用且不要求配置 Key；不会同时堆叠多个 provider 的卡片

#### Scenario: 深链定位

- **WHEN** 用户从模型选择器、输入卡片或联网搜索页打开 `/settings#credential-openrouter`
- **THEN** 页面选中 OpenRouter 并显示其凭据卡且滚动到可见位置，无需手动查找

#### Scenario: 切换 provider 不泄露输入

- **WHEN** 用户在某 provider 的密码框输入内容后切换到另一 provider
- **THEN** 已输入的密钥被清除，不出现在另一 provider 的卡片或浏览器持久存储中

#### Scenario: 未配置与操作反馈

- **WHEN** 无 Key 时打开聊天或设置，或者保存期间请求失败
- **THEN** 用户可进入设置，发送前有配置引导；保存期间防止重复提交，失败显示可重试反馈而不宣称已保存或已验证

#### Scenario: 响应式与键盘操作

- **WHEN** 在 1440、1024、768 或 375 像素宽度下使用设置页
- **THEN** provider 下拉、凭据卡的勾选、输入和按钮无横向溢出，所有操作有可访问名称、可见焦点，下拉可仅用键盘打开、过滤、导航与选定

### Requirement: 会话模型与思考强度设置

Web SHALL 在聊天区同一配置面板内提供模型和思考强度选择，模型通过「provider 下拉 + 紧凑模型列表」且可搜索的选择器选取，选项取自与 TUI 相同的 Pi 1.3.0 能力列表，一次确认提交当前会话配置。面板 SHALL 显示当前值、切换模型后的有效强度及“从下一次请求生效”说明；输入卡片工具行展示服务端确认值。设置页的用户级凭据与会话级模型配置 MUST 清楚区分。当前会话模型所属 provider 未启用或缺 Key 时，面板与输入卡片 SHALL 明确提示并提供启用 / 配置入口。

#### Scenario: 切换和取消

- **WHEN** 用户从 Flash low 选择 Pro
- **THEN** 草稿强度按 Pi 调整为 high 并显示，确认后模型和强度一并生效；取消不改变会话

#### Scenario: 双端一致

- **WHEN** Pi 1.3.0 下选择 Flash 或 Pro，或 TUI 修改当前会话
- **THEN** Flash 提供 off/low/high/max、Pro 提供 off/high/max；Web 同步实际生效配置，不提供其他档位

#### Scenario: 切换会话与请求失败

- **WHEN** 配置面板打开期间切换会话，或提交失败、返回过期响应
- **THEN** 不向新会话误提交旧草稿，不让旧响应覆盖新会话；失败保持实际生效值并提示重试

#### Scenario: 面板访问

- **WHEN** 用户通过键盘或触屏从输入卡片工具行打开模型面板
- **THEN** 可完成选择和确认，Escape 可取消并恢复焦点，面板在小屏中不越界或遮挡无法访问的操作

#### Scenario: 当前模型 provider 不可用

- **WHEN** 会话使用的 provider 被取消启用或缺少 Key
- **THEN** 输入卡片显示对应提示与入口，发送被拦截并保留草稿；模型面板仍可打开以切换到其他可用模型

### Requirement: Web 压缩命令与状态

Web 输入框 SHALL 支持 `/compact [附加要求]`，输入斜杠时提供可用命令菜单，另提供可发现的压缩菜单入口。命令 MUST 在普通消息忙碌拦截之前解析，不发送为聊天文字。输入区 SHALL 展示独立压缩状态及真实结果，保持编辑能力，不用阻断式弹窗或虚假百分比表示后台压缩。

#### Scenario: 键盘和触屏命令

- **WHEN** 用户用方向键、Enter、Escape 或触屏选择 /compact
- **THEN** 可选择、取消并执行，输入法组字不误触发；附加要求作为操作参数，命令不更新会话排序

#### Scenario: 运行与晚到结果

- **WHEN** 会话正在回答或用户在压缩期间切换会话
- **THEN** 仍可手动压缩，后台压缩不额外阻塞正常对话；旧结果只更新原会话，不清除新草稿

### Requirement: Web 图片附件交互

Web SHALL 提供输入框附件按钮、多图选择、拖放与剪贴板粘贴。添加后 SHALL 在输入框上方显示缩略图、移除入口、处理状态与失败反馈，不自动发送。用户可发送仅图片或图文消息；普通文本粘贴保持文字。失败 MUST 保留草稿，服务端受理后才清除对应附件。

#### Scenario: 添加与重试

- **WHEN** 用户选择、拖入或粘贴图片，部分图片处理失败
- **THEN** 成功和失败项分别可见，用户可移除失败项或重试，不静默跳过失败附件发送余下内容

#### Scenario: 模型与会话变更

- **WHEN** 有附件时切换至 Pro 或其他会话
- **THEN** Pro 下保留并提示处理附件，草稿按会话隔离；异步处理、上传或发送结果不影响新会话

### Requirement: 图片预览与响应式访问

Web SHALL 在历史中显示图片缩略图，按需加载大图并提供关闭入口；统一 read 工具的图片结果 SHALL 使用相同的预览能力，展示路径名称、格式、实际保存尺寸和原生处理诊断。附件、命令菜单和预览 SHALL 遵循全站统一的蓝粉白主题，支持键盘和触屏，且在 1440、1024、768、375、1920、2560 像素宽度下可访问、不横向溢出。预览关闭后恢复焦点，移除和关闭操作有明确可访问名称。

#### Scenario: 大图与菜单

- **WHEN** 用户打开大图、滚动长附件列表或在小屏展开命令菜单
- **THEN** 操作不被遮挡，模态预览约束焦点并支持 Escape，菜单取消恢复编辑且不误发消息

#### Scenario: read 图片结果与恢复

- **WHEN** read 返回图片，随后源文件消失或浏览器重连
- **THEN** 从持久结果按需恢复预览及元数据，订阅状态不重复携带 base64，不依赖原宿主文件仍存在

#### Scenario: 图片读取失败或能力占位符

- **WHEN** read 无法处理图片，或当前非视觉模型只收到占位符
- **THEN** 工具卡可辨识地显示失败或能力诊断，不能将占位符表现为模型已看见图片

### Requirement: Web 工作区引用候选

Web SHALL 在输入框有效词边界输入 @ 时展示当前工作区文件候选，支持名称搜索、子目录定位、方向键选择、Enter/Tab 确认和触屏点击；Esc 关闭且保留输入。选择 MUST 仅替换光标所在引用片段，不误发消息、不抢走输入焦点。邮箱中的 @ 和输入法组字 MUST NOT 误触发选择或发送。Windows、macOS 和 Linux 宿主 SHALL 均支持文件、目录和嵌套路径候选，引用路径统一使用 `/`，不得因宿主分隔符差异丢弃有效候选。

#### Scenario: 选择与继续编辑

- **WHEN** 用户在一段文字中输入 @，选择带空格的文件或目录
- **THEN** 插入准确引用并保留前后文字与光标，目录可继续浏览，关闭候选后可发送目录引用；文件和目录遵循统一引用语义

#### Scenario: 输入法与普通文本

- **WHEN** 用户输入邮箱、使用中文输入法确认文字或按 Esc 关闭候选
- **THEN** 邮箱保持普通文本，组字确认不选择候选或发送消息，取消不清空草稿

#### Scenario: Windows 文件与目录

- **WHEN** Windows 宿主已安装 fd，工作区包含未被忽略的 `README.md`、`src` 目录和 `src/index.ts`，用户输入 `@`
- **THEN** 候选包含该文件和目录；选择目录插入 `@src/`，继续定位可选择 `src/index.ts`

#### Scenario: 搜索嵌套文件与空格目录

- **WHEN** 用户通过名称搜索位于多级目录或带空格目录中的文件
- **THEN** Windows、macOS 和 Linux 均返回匹配的工作区内候选，插入的路径使用 `/` 并正确引用空格

### Requirement: Web 候选呈现与生命周期

候选面板 SHALL 遵循全站统一的蓝粉白主题，显示类型、名称和父路径，区分加载、无结果、缺少依赖、失败与候选过多。面板 SHALL 限高滚动且不遮挡输入或越出视口，提供可访问名称和选中状态，支持键盘和触屏。查询、图片处理和草稿 MUST 绑定原工作区及会话；关闭或切换后旧响应不得恢复面板或修改新草稿。

#### Scenario: 响应式与焦点

- **WHEN** 用户在 1440、1024、768、375 像素宽度下浏览长路径及长列表，或移动键盘缩小可视区域
- **THEN** 面板保持可操作、无横向溢出，选中项可见且辅助技术可识别；焦点保持在编辑流程中，Tab 确认当前候选，Shift+Tab 仍可离开输入框；文件与斜杠命令弹层样式统一且宽度与输入框对齐

#### Scenario: 异步和重连

- **WHEN** 查询未完成时用户修改引用、关闭候选、切换工作区或连接断开后恢复
- **THEN** 旧查询被取消且不覆盖新状态，草稿保留；重新查询使用当前工作区，不自动重新打开已关闭面板

#### Scenario: 图片选择

- **WHEN** 用户选择宿主工作区图片
- **THEN** 通过绑定原会话的图片流程显示附件、处理状态与错误，不将浏览器本地文件选择器误作宿主文件查询；失败保留引用和草稿

### Requirement: Web 技能命令菜单

Web composer SHALL 在输入 `/`、`/skill` 或 `/skill:` 前缀时于命令菜单中列出当前会话的技能；条目 SHALL 显示名称、单行截断的简述与来源级别标记，内置级技能 MUST 显示可辨识的「内置」标记；不展示完整描述全文。选中后填入 `/skill:<name> `；提交时 MUST 原样发送，展开由 core 完成。

#### Scenario: 菜单列出技能

- **WHEN** 用户在输入框键入 `/skill` 或 `/skill:`
- **THEN** 菜单列出当前会话的技能条目，每条为名称加一行截断简述

#### Scenario: 内置技能标记

- **WHEN** 菜单中包含内置级技能
- **THEN** 该条目显示「内置」标记，与用户级/项目级技能可区分

#### Scenario: 选中填入

- **WHEN** 用户通过方向键、鼠标、Enter 或 Tab 选中某技能条目
- **THEN** 输入框变为 `/skill:<name> `，等待参数输入

#### Scenario: 原样提交

- **WHEN** 用户提交 `/skill:pdf 参数`
- **THEN** 原文发送给 gateway，不在客户端展开

#### Scenario: 加载与连接恢复

- **WHEN** 技能列表正在加载、加载失败、没有匹配项，或会话连接恢复
- **THEN** 菜单显示对应反馈而非消失；连接就绪或重新打开菜单后重新查询，旧会话响应不覆盖新会话

#### Scenario: 空工作区

- **WHEN** 当前工作区尚未建立会话且用户查询技能
- **THEN** 菜单提示先新建会话，不伪造空技能列表

### Requirement: 输入区可访问性与层级

Web 输入区 SHALL 为消息输入框提供不依赖 placeholder 的可访问名称；附件区、错误与提示行、建议弹层和操作按钮组 SHALL 在输入卡片内有清晰一致的视觉层级与间距。浮动操作入口 MUST NOT 遮挡消息或工具输出正文。触屏设备上输入卡片的操作按钮 SHALL 提供不小于 44px 的触控目标。

#### Scenario: 输入框可访问名称

- **WHEN** 辅助技术聚焦于消息输入框
- **THEN** 朗读出描述用途的名称，即使 placeholder 已因输入而消失

#### Scenario: 浮动入口不遮挡

- **WHEN** 用户向上滚动离开底部，出现回到底部浮动按钮
- **THEN** 按钮位于不遮盖消息与工具输出正文的位置，或其占位已计入布局留白

#### Scenario: 触屏目标尺寸

- **WHEN** 用户在触屏设备上操作输入卡片
- **THEN** 附件、命令菜单、发送与停止按钮的触控目标不小于 44px，相邻控件不因目标过近而误触发

### Requirement: 工具调用状态可辨识

工具调用卡片 SHALL 以图标和颜色双重手段区分进行中、成功与失败状态；失败态 MUST NOT 仅依赖细微边框色差，且无需展开即可辨识。

#### Scenario: 失败与成功并列可区分

- **WHEN** 同一会话中存在成功与失败的工具调用卡片
- **THEN** 用户在折叠状态下即可通过图标与显著色彩差异区分两者

#### Scenario: 非色彩线索

- **WHEN** 用户在灰度显示或色弱模拟条件下查看工具卡片
- **THEN** 状态仍可凭图标或文字线索区分

### Requirement: 聊天区分层宽度

聊天区消息列 SHALL 按视口宽度分档抬升列宽上限，档位与宽度值 MUST 来自脚本与样式间单一来源的布局 token。用户消息气泡 SHALL 保持有上限的紧凑宽度；助手回答气泡 SHALL 允许使用完整列宽；工具调用卡片与代码块 SHALL 与消息列同宽，左右边缘与气泡对齐。各档位下页面 MUST NOT 横向溢出。

#### Scenario: 窄屏基准

- **WHEN** 视口宽度不超过 1280px
- **THEN** 消息列保持基准列宽 48rem，用户气泡不超过列宽的 75%

#### Scenario: 宽屏抬升

- **WHEN** 视口宽度达到 1920px 或更高档位
- **THEN** 消息列宽按分档抬升，聊天区两侧留白占比随视口增大而下降

#### Scenario: 内容宽度对齐

- **WHEN** 助手回答包含工具调用卡片或代码块
- **THEN** 工具卡与代码块与消息列同宽，左右边缘与助手气泡对齐，不突破列宽

#### Scenario: 宽屏不溢出

- **WHEN** 在 1920 或 2560 像素宽度下浏览长会话
- **THEN** 页面无横向滚动，回到底部入口、遥测指示与输入卡片均可正常访问

### Requirement: 输入卡片与遥测呈现

Web 输入区 SHALL 呈现为单一浮动卡片：附件列表、消息输入框与工具行（附件、模型与思考强度入口、发送/停止）同处一个卡片容器。瞬态状态（忙碌、压缩相位、错误）SHALL 常驻可见；稳态遥测（输入/输出 token 与成本）SHALL 默认收起，悬停或聚焦时展开。忙碌时卡片 SHALL 给出环境态视觉反馈，并在 prefers-reduced-motion 下降级为静态。连接状态 SHALL 保留在顶栏。

#### Scenario: 模型入口在卡片内

- **WHEN** 用户想切换模型或思考强度
- **THEN** 从输入卡片工具行打开配置面板，入口与输入焦点相邻，提交后卡片展示服务端确认值

#### Scenario: 遥测悬停展开

- **WHEN** 用户悬停或键盘聚焦遥测指示
- **THEN** 展开输入/输出 token 与成本详情；移开或失焦后收起，不收起瞬态忙碌与压缩状态

#### Scenario: 瞬态状态常驻可见

- **WHEN** 会话正在回答或正在压缩上下文
- **THEN** 输入卡片上直接可见对应状态，不依赖悬停，失败状态以强调色呈现

#### Scenario: 动效降级

- **WHEN** 系统开启 prefers-reduced-motion
- **THEN** 忙碌环境特效呈静态提示，无位移或循环动画，状态信息不丢失

#### Scenario: 上下文用量指示

- **WHEN** 最近一次回答的上下文用量已知
- **THEN** 输入卡片显示用量占比指示，接近上限时以强调色呈现，详尽的 token 数值经悬停或聚焦查看

### Requirement: Web 技能调用消息展示

Web SHALL 依据服务端投影的结构化技能元数据将成功展开的技能调用渲染为工具卡风格的折叠卡片：技能图标、`skill:<name>` 名称与截断来源路径，默认折叠，点击展开查看正文（等宽、限高滚动）。参数 SHALL 在卡片外以普通用户文本显示。无技能元数据的输入 MUST 原样渲染，不从 XML 文本反向识别，不丢失内容。卡片 SHALL 遵循全站统一的蓝粉白 design tokens。

#### Scenario: 折叠卡片

- **WHEN** 用户通过 `/skill:pdf 总结它` 提交且技能命中展开
- **THEN** 该用户消息显示为折叠的技能卡片（图标 + `skill:pdf` + 来源路径），正文不铺开

#### Scenario: 展开正文

- **WHEN** 用户点击技能卡片
- **THEN** 卡片展开显示技能正文，再次点击折叠

#### Scenario: 参数仍可见

- **WHEN** 技能调用带有参数
- **THEN** 参数文本在卡片外以普通用户消息样式显示

#### Scenario: 解析失败回退

- **WHEN** 用户消息以 `<skill` 开头但没有成功展开的结构化技能元数据（如手工输入、未命中透传）
- **THEN** 消息按原样纯文本渲染，内容完整可见，即使 XML 外观符合技能块也不解析为调用

#### Scenario: 元数据恢复

- **WHEN** 浏览器重连或打开分叉后的 Pi 1.2.0 会话，技能正文及参数含有 XML 标记
- **THEN** 从持久展示数据恢复卡片、正文和参数，边界不受 XML 内容影响

### Requirement: Web 技能市场页与分组浏览

Web SHALL 提供独立的技能市场页，在会话侧栏底部提供一级可发现入口，并在市场页顶栏提供导航回聊天的入口。市场页 SHALL 独立占满主视图区域展现，按分类或来源对技能分组展示（用户可切换两种分组方式），提供关键词搜索；卡片 SHALL 显示名称、简述、来源、版本与大小，并以可辨识标记区分项目级/用户级已安装与内置技能。分组、搜索与卡片样式 SHALL 遵循全站统一的蓝粉白 design tokens。市场不可达 SHALL 显示错误态与重试入口。

#### Scenario: 进入市场页

- **WHEN** 用户在会话侧栏底部点击技能市场选项
- **THEN** 切换到独立市场页，显示包含返回聊天入口、分组与搜索的顶栏及市场技能卡片，无需依附设置二级侧栏

#### Scenario: 切换分组方式

- **WHEN** 用户将分组从按分类切换为按来源
- **THEN** 同一批技能按来源重新分组，各组显示数量

#### Scenario: 安装状态标记

- **WHEN** 技能已安装到用户级或项目级，或为内置技能
- **THEN** 卡片显示对应级别标记，内置技能显示「内置」

#### Scenario: 市场不可达

- **WHEN** 市场请求失败
- **THEN** 页面显示错误说明与重试按钮，不显示空分组

### Requirement: Web 技能详情与预览

市场页 SHALL 提供技能详情视图：完整描述、元数据（分类、来源、版本、大小、SHA-256 摘要、上传时间、许可证中可用项）与两级安装状态；并提供预览入口查看 SKILL.md 正文与包内文件清单。详情视图桌面端以抽屉呈现，移动端为全屏弹层；预览正文 SHALL 以站内 Markdown 渲染。

#### Scenario: 查看详情

- **WHEN** 用户点击技能卡片
- **THEN** 打开详情视图，显示完整描述、元数据与项目级/用户级安装状态

#### Scenario: 预览正文

- **WHEN** 用户在详情中打开预览
- **THEN** 显示渲染后的 SKILL.md 正文与文件清单，本地无写入

### Requirement: Web 市场安装与卸载确认

详情视图 SHALL 提供「安装到用户级」「安装到项目级」操作；目标级已有同名技能时 SHALL 先弹明确确认（说明覆盖将丢失本地版本），确认后才执行覆盖安装；项目级有同名而安装到用户级时 SHALL 提示该安装不生效。已安装技能 SHALL 提供卸载操作，卸载前弹明确确认；内置技能不显示安装/卸载操作。操作进行中 SHALL 有加载态，结果以成功/失败反馈呈现。

#### Scenario: 覆盖确认

- **WHEN** 用户级已存在某技能，用户再次安装到用户级
- **THEN** 先显示覆盖确认对话框，确认后才写入

#### Scenario: 遮蔽提示

- **WHEN** 项目级已有同名技能，用户安装到用户级
- **THEN** 安装前提示项目级优先、此安装不生效

#### Scenario: 卸载确认

- **WHEN** 用户卸载用户级技能
- **THEN** 先显示卸载确认，确认后删除并在卡片与详情中更新状态

#### Scenario: 内置技能只读

- **WHEN** 详情中的技能为内置级
- **THEN** 不提供安装与卸载按钮

### Requirement: Web 文件发现状态反馈

Web 的 @ 候选面板 SHALL 区分加载、完整无匹配、候选过多、枚举不完整和文件发现失败。正常安装后无需用户安装 fd/fdfind；辅助组件缺失或不可用 SHALL 返回可理解且可重试的错误，不指导安装 fd，也不伪装为空结果。反馈 SHALL 保留草稿，不阻止关闭候选后发送普通消息；取消或工作区切换后的旧响应 MUST NOT 重开面板。

#### Scenario: 无 fd 的安装

- **WHEN** 支持平台正常安装 neko，gateway 的 PATH 没有 fd/fdfind，用户触发 @ 补全
- **THEN** 正常展示候选，不显示安装命令；浏览器与宿主平台不同不影响该行为

#### Scenario: 不完整而没有匹配

- **WHEN** 后端目录枚举截断，返回零个匹配候选
- **THEN** 面板明确提示结果不完整并引导指定子目录，不显示普通“没有匹配”；指定子目录后可重新查询

#### Scenario: 组件故障与恢复

- **WHEN** 随包文件发现组件缺失、不可执行或启动失败，随后恢复并再次查询
- **THEN** 初次显示文件发现不可用与重试反馈，保留草稿；再次查询可恢复候选，不要求安装 fd

#### Scenario: 查询结束与取消

- **WHEN** 搜索超时、被取消，或用户关闭候选/切换工作区后旧请求结束
- **THEN** 超时可辨识且可重试，取消不显示组件安装错误；旧反馈不恢复面板或覆盖新工作区结果，普通消息仍可发送

### Requirement: Web 默认图片提示查看

Web SHALL 根据服务端投影的默认图片提示元数据，在图片用户消息中显示「默认图片提示」来源标记与折叠查看入口。默认 SHALL 收起正文，保留图片缩略图与预览，不将自动提示作为用户手写文字显示；展开 SHALL 展示该消息保存的完整提示，支持再次收起。入口 SHALL 支持键盘和触屏，具有可访问名称及展开状态，遵循现有主题与响应式布局。

#### Scenario: 展开与收起
- **WHEN** 用户浏览带有默认提示元数据的图片消息并操作查看入口
- **THEN** 默认收起的提示可展开显示完整正文，再次操作收起；图片预览、输入草稿和当前会话保持不变

#### Scenario: 窄屏与键盘
- **WHEN** 用户在 375px 或 1440px 宽度通过键盘或触屏查看较长默认提示
- **THEN** 控件有可辨识名称及展开状态，正文可完整查看且页面不横向溢出，收起后焦点保持在有效入口

#### Scenario: 重连与无标记消息
- **WHEN** 浏览器重连、刷新、切换或打开分叉会话，或显示手写的相同提示正文
- **THEN** 带标记的消息按持久正文恢复查看能力，无标记消息继续按普通用户文字显示，不从字符串内容推断来源

### Requirement: Web 升级感知与操作提示

Web SHALL 按当前界面语言以简洁文案提示可安装更新、旧 gateway、旧静态服务和旧页面，并在设置中心以专用图标（非 store 图标）提供「关于与更新」子菜单入口。关于页面 SHALL 采用卡片化布局，默认单行呈现主要运行版本与当前生效状态，仅在检测到更新或组件未重启时呈现对应版本与行动提示。可安装更新 SHALL 提供复制 `neko update` 的操作；仅页面旧时 SHALL 提供手动刷新。Web MUST NOT 执行安装或重启服务，不自动刷新，不将提示发送给模型或反复弹窗。

#### Scenario: 可安装更新
- **WHEN** 后台确认较新稳定版本尚未安装
- **THEN** 界面语言为中文时显示“发现新版本，运行 neko update”，为英文时显示等价英文提示，均含复制命令入口；远程浏览器明确在运行 neko 的电脑上执行

#### Scenario: 旧网关或旧静态服务
- **WHEN** 安装已更新，但 gateway 或提供页面的静态服务仍旧
- **THEN** 界面语言为中文时显示“已升级，请重新启动本地 neko”，为英文时显示等价英文提示，详情指引关闭同一网关的 TUI/Web 或独立 serve 后再启动，不将刷新页面作为充分解决操作

#### Scenario: 仅页面旧
- **WHEN** gateway 和静态服务已更新，当前页面仍旧且协议兼容
- **THEN** 界面语言为中文时显示“页面已更新，刷新即可”，为英文时显示等价英文提示，均含刷新入口，持续运行的页面通过检查获知变化，不依赖用户先刷新才发现更新

#### Scenario: 无法检查与关于页面
- **WHEN** 用户打开关于与更新页面，更新来源不可达或安装信息未知
- **THEN** 显示真实的组件版本与未知状态；主动检查失败时给出重试入口，聊天中的后台失败不持续打扰

#### Scenario: 状态驱动与版本卡片
- **WHEN** 用户进入关于与更新页面查看版本
- **THEN** 页面在卡片内以单行主要版本展示当前状态，无新版本时不展示冗余的 npm 最新版及内部多重已安装项，升级说明精炼呈现

### Requirement: 升级刷新与重新发现

用户触发升级刷新时，Web SHALL 保留当前会话的文字草稿及工作区/会话选择；有未发送附件、附件处理或提交正在进行时 SHALL 阻止该刷新并给出处理说明。连接重建 SHALL 重新发现并校验 gateway 地址、身份及版本，清除旧连接状态，不重复提交输入。非兼容协议错误 MUST NOT 无限自动重试。

#### Scenario: 文字草稿恢复
- **WHEN** 用户有未发送文字并点击升级提示的刷新入口
- **THEN** 页面重新加载后恢复同一工作区和会话的原文字，不自动发送；无法可靠保存时保留页面并显示提示

#### Scenario: 待发送附件
- **WHEN** 用户有未发送图片或附件处理/消息提交尚未完成，并点击刷新
- **THEN** 保持页面、草稿和附件，简短提示先完成提交或处理附件，不默默丢失文件

#### Scenario: gateway 重启换地址
- **WHEN** gateway 重启后地址变化，页面重新连接
- **THEN** 重新读取发现信息并验证当前身份，恢复原会话，使用新连接的版本状态，不持续连接旧地址

#### Scenario: 多种差异与响应式布局
- **WHEN** 页面在 375px/1440px 下同时发现网关、静态服务或页面版本差异
- **THEN** 优先展示需要先执行的操作，详细版本可在关于页面查看，按钮可键盘操作且页面无横向溢出；修复后移除过时提示

### Requirement: Web 委派卡片与侧栏
Web SHALL 在主消息流中为每轮任务独立展示角色、任务简称、状态及耗时的委派卡片，并提供右侧子 agent 列表与详情。列表 SHALL 按稳定子 agent 身份去重，单行展示角色、稳定名称和轮数；空闲、排队、运行状态在详情中展示；各轮保留完成、失败、停止状态及报告。停止入口 SHALL 绑定当前活动轮，已结束轮次仍可查看。首次委派可展开侧栏，用户主动关闭后 MUST NOT 因流式更新反复打开。

#### Scenario: 多个子任务
- **WHEN** 主 agent 并行委派多个任务
- **THEN** 主消息流与侧栏分别展示各任务，点击任一卡片定位同一子 agent 的对应轮次详情，失败与停止有文字或图标区分

#### Scenario: 接续和空闲
- **WHEN** 子 agent 第一轮完成并被再次派发任务
- **THEN** 侧栏仍只有同一个身份条目，单行显示角色、稳定名称和 2 轮，不重复显示最近任务摘要或状态行；两张主任务卡保持各自结果，详情显示当前状态，全部轮次结束后显示空闲

#### Scenario: 关闭后的接续
- **WHEN** 用户已关闭子侧栏，同一子 agent 开始接续任务
- **THEN** 只更新状态和已有审批入口，不强制打开侧栏，主输入草稿及附件保留

### Requirement: Web 子 agent 完整可见流程
子 agent 详情 SHALL 按时间顺序展示各轮任务输入、轮次分隔、助手文字、模型实际返回且系统保存的思考内容、全部可见工具调用的参数与输出/结果、图片、错误及最终报告，支持流式更新、展开和历史回看，与主会话内容类型保持一致。完整流程 MUST NOT 被仅有摘要替代；原有截断与省略须可辨识，不补造模型未提供的内容。同一子 agent SHALL 展示连续历史，详情提供累计用量，各轮摘要可查看本轮消耗；未知旧轮增量须明确标注。

#### Scenario: 工具和图片流程
- **WHEN** 子 agent 多轮调用搜索、读取图片、执行命令，期间有失败重试
- **THEN** 用户可逐项查看参数、各次可见结果、图片和失败信息，而非只看到最后一次调用或最终总结

#### Scenario: 历史和滚动
- **WHEN** 用户向上查看子会话历史后出现新输出，随后重新连接
- **THEN** 不强制滚到底部，提供回到底部入口，持久历史恢复且当前流式内容不重复

#### Scenario: 定位旧轮与浏览状态
- **WHEN** 用户点击较早轮次卡片，而同一子 agent 已执行后续轮次
- **THEN** 按需加载定位该轮，保留卡片目标而不误跳到最新任务；后续输出不强制拉回底部，主/子视图会话切换不报错

#### Scenario: 多轮响应式用量
- **WHEN** 用户在 375、768、1440、1920 像素宽度查看含多轮命令的子 agent
- **THEN** 轮次分隔、累计和本轮用量可读且无横向溢出；审批继续只显示未决请求，结果标注在对应命令旁

### Requirement: Web 子 agent 风格与浏览状态
委派 UI SHALL 延续当前蓝粉白 tokens、消息、Markdown、思考折叠、工具卡和图片预览风格。桌面端使用右侧栏，窄屏使用可关闭的抽屉或全屏详情，支持键盘、触屏和辅助技术。子会话浏览 MUST 保留主输入草稿、附件、滚动与会话选择；首版详情不提供子会话消息输入框。

#### Scenario: 响应式浏览
- **WHEN** 用户在 375、768、1440、1920 像素宽度查看长任务和工具结果
- **THEN** 页面无横向溢出，详情与停止入口可操作，关闭详情恢复有效焦点且保留主会话编辑状态

#### Scenario: 渲染一致性
- **WHEN** 相同类型的助手消息、代码、工具调用和图片分别出现在主会话与子会话
- **THEN** 两者采用一致的视觉与展开交互规则，不形成另一套日志终端风格

### Requirement: 自动补齐较早记录
子 agent 详情 SHALL 在用户向上滚动到已加载内容顶部时自动分页补齐较早记录并保持已有内容的浏览位置；SHALL 不提供单独的“查看历史”按钮或 H 快捷键。

#### Scenario: 向上浏览长记录
- **WHEN** 用户向上滚动至已加载记录的顶部且仍有较早条目
- **THEN** 自动加载并去重合并较早条目，保留正在阅读的内容位置，无需额外历史操作

### Requirement: Web 子 agent 命令审批
Web SHALL 在主会话委派卡和子任务入口显示待审批提示与数量，在输入框附近独立展示完整命令、工作目录、显式超时、允许本次和拒绝操作；窄屏子视图将同一审批区放在底部。决定后移除审批卡，仅在对应命令旁保留结果。SHALL 延续当前工具卡、主题与响应式风格，支持键盘和辅助技术。请求到来不得抢焦点或反复打开用户关闭的侧栏，关闭详情不决定审批。列表可简写命令，审批详情 MUST 可完整查看而不能静默截断。

#### Scenario: 侧栏关闭时到来
- **WHEN** 子 agent 请求审批而用户已关闭侧栏
- **THEN** 主输入区直接显示待审批操作，无需打开子任务即可决定，草稿、附件及主视图滚动状态保留

#### Scenario: 移动端与长命令
- **WHEN** 用户在 375、768、1440、1920 像素宽度查看多行命令
- **THEN** 详情可完整滚动阅读、操作可达且无页面横向溢出，关闭恢复有效焦点，不隐式授权

#### Scenario: 竞争与重连
- **WHEN** 用户提交决定时另一端已处理，或浏览器断线后重连
- **THEN** 展示服务端最终状态且不重复执行，已结算请求不再显示可生效的审批按钮

### Requirement: Web 气泡复制
Web SHALL 在已提交的用户气泡与 assistant 气泡上提供复制按钮，复制内容遵循"可复制文本规则"，assistant 气泡 MUST 不含 thinking。流式中的气泡 MUST NOT 显示复制按钮。按钮 MUST 可通过鼠标、键盘与触屏访问，且在触屏设备上无需悬停即可见；复制后 SHALL 短暂显示已复制状态并通知辅助技术。

#### Scenario: 复制回答
- **WHEN** 用户点击 assistant 气泡的复制按钮
- **THEN** 剪贴板得到该气泡的正文，不含思考过程，按钮短暂显示已复制

#### Scenario: 复制技能调用消息
- **WHEN** 用户复制一条 `/skill:` 调用产生的用户气泡
- **THEN** 复制内容为 `/skill:<name>` 加参数，不含展开后的技能正文

#### Scenario: 流式中
- **WHEN** 回答仍在流式生成
- **THEN** 流式气泡没有复制按钮，提交完成后出现

#### Scenario: 触屏与键盘
- **WHEN** 用户在触屏设备或仅用键盘浏览
- **THEN** 复制按钮可见并可聚焦，按钮具有可朗读的名称，Enter 或空格触发复制

### Requirement: Web 复制降级与失败反馈
Web 复制 SHALL 优先使用浏览器剪贴板接口；该接口不可用（如非安全上下文的局域网访问）或被拒绝时 MUST 降级到备用的选区复制方式；全部失败时 MUST 显示可见的失败提示，不得显示已复制。

#### Scenario: 非安全上下文
- **WHEN** 用户通过 http 局域网地址访问并点击复制
- **THEN** 通过备用方式完成复制并显示已复制

#### Scenario: 复制失败
- **WHEN** 剪贴板接口与备用方式都失败
- **THEN** 按钮旁显示复制失败的提示，剪贴板不被视为已更新

### Requirement: Web 会话导出
Web SHALL 在聊天页顶栏提供会话导出入口，可选择 Markdown、HTML 或 JSON，并有"包含思考过程"选项，默认关闭。选择后 MUST 通过浏览器下载保存，文件名遵循导出文件命名规则。会话无已提交条目时入口 MUST 不可用或给出原因；导出过程中 SHALL 显示进行状态并避免重复触发，完成或失败 MUST 有可见反馈。

#### Scenario: 导出 Markdown
- **WHEN** 用户在导出菜单选择 Markdown
- **THEN** 浏览器下载 `.md` 文件，内容为当前会话已提交转录，不含思考过程

#### Scenario: 导出 HTML 含图片
- **WHEN** 会话含图片，用户选择 HTML
- **THEN** 导出期间显示进行状态，完成后下载的文件内嵌图片；有图片未能内嵌时提示数量

#### Scenario: 包含思考过程
- **WHEN** 用户勾选包含思考过程并导出
- **THEN** 导出内容包含各条回答的思考过程

#### Scenario: 空会话
- **WHEN** 当前会话没有任何已提交条目
- **THEN** 导出入口不可用并说明原因

#### Scenario: 导出期间切换会话
- **WHEN** 含图片的 HTML 导出进行中用户切换到另一会话
- **THEN** 导出被取消并提示会话已切换，不下载内容不完整的文件，也不混入其他会话的内容

### Requirement: Web 导出菜单可访问性
导出入口与菜单 SHALL 可通过键盘打开与操作，Escape 关闭并把焦点还给触发控件，菜单不得被滚动区域裁切；触发控件和菜单项 MUST 具有可朗读的名称，窄屏下不得与顶栏其他内容重叠。

#### Scenario: 键盘操作
- **WHEN** 用户用键盘聚焦导出入口并按 Enter
- **THEN** 菜单打开且焦点进入菜单，方向键或 Tab 可选择格式，Escape 关闭并回到触发控件

#### Scenario: 小屏幕
- **WHEN** 在 375 像素宽度下查看顶栏
- **THEN** 导出入口可见可点，不遮挡会话标题与连接状态

### Requirement: Web 输入历史浏览

Web 输入框 SHALL 支持用 ↑/↓ 浏览当前会话的输入历史（条目规则见 `input-history`）：输入为空或光标位于输入起点且无选区时，↑ 回填更早一条并将光标置于开头；处于浏览态且光标位于输入末尾时，↓ 回填更新一条并将光标置于末尾；越过最新一条后 SHALL 还原进入浏览前的草稿。除上述条件外 ↑/↓ 保持浏览器默认光标移动。回填 MUST 作为新草稿处理，已选附件保持不变。用户编辑回填文字、发送或切换会话后 MUST 退出浏览态。

#### Scenario: 空输入按 ↑ 回填最近输入

- **WHEN** 输入框为空且会话有历史，用户按 ↑
- **THEN** 输入框回填最近一条已发送输入且光标位于开头，再按 ↑ 依次回填更早的输入，到最早一条后停止，不循环

#### Scenario: ↓ 返回并还原草稿

- **WHEN** 用户先输入未发送草稿并将光标移到起点后按 ↑ 进入历史，再按 ↓ 直至越过最新一条
- **THEN** 输入框还原为进入历史前的草稿内容

#### Scenario: 多行与折行内的光标移动优先

- **WHEN** 输入框含多行或折行文字且光标不在起点（浏览态向下时不在末尾）
- **THEN** ↑/↓ 保持浏览器默认光标移动，不触发历史切换

#### Scenario: 候选菜单与 IME 优先

- **WHEN** 命令菜单或 `@` 文件候选正在显示，或用户处于 IME 组合输入中
- **THEN** ↑/↓ 按原有行为选择候选或操作输入法，不触发历史切换

#### Scenario: 编辑后退出浏览态

- **WHEN** 用户回填某条历史后修改其中文字
- **THEN** 该文字成为当前草稿，随后按 ↓ 不会覆盖它

#### Scenario: 附件不受影响

- **WHEN** 输入框已有待发送图片附件，用户通过 ↑/↓ 回填历史文字
- **THEN** 附件保持不变，回填文字不含图片

#### Scenario: 回填内容可直接发送

- **WHEN** 用户回填一条历史后按 Enter
- **THEN** 该文字作为新消息发送，且不与此前同文字的发送共用同一请求标识

#### Scenario: 无会话或无历史

- **WHEN** 工作区尚未创建会话，或当前会话没有历史时用户按 ↑ 或 ↓
- **THEN** 输入框行为与现状一致

### Requirement: Web 输入历史的会话隔离与同步

Web SHALL 使每个会话拥有独立的历史与浏览态：切换会话时 MUST 显示新会话的历史，未发送草稿保持各会话独立；会话 transcript 出现新的已提交输入时 SHALL 更新历史，使其成为 ↑ 的第一条。正在浏览历史时 MUST NOT 因后台更新改变用户当前看到的回填内容或浏览位置，更新 SHALL 在退出浏览态后生效。

#### Scenario: 切换会话后历史隔离

- **WHEN** 用户在会话 A 浏览历史后切换到会话 B，再按 ↑
- **THEN** 回填的是会话 B 的最近输入，不含会话 A 的内容；切回会话 A 时其未发送草稿仍在

#### Scenario: 发送后立即可回填

- **WHEN** 用户发送一条输入并在其进入 transcript 后清空输入框
- **THEN** 按 ↑ 回填刚发送的那一条

#### Scenario: 浏览中收到更新

- **WHEN** 用户正在浏览历史时，其他前端向同一会话提交了新输入
- **THEN** 当前回填内容与浏览位置不变，退出浏览态后按 ↑ 的第一条为新输入

#### Scenario: 刷新后仍可浏览

- **WHEN** 用户刷新页面并重新打开该会话
- **THEN** 会话 transcript 加载完成后即可通过 ↑ 回填此前的输入

### Requirement: Web 工具卡代码变更 diff 展示

Web 工具卡 SHALL 对 `edit` 与 `write` 工具调用展示代码变更 diff,与终端前端对等:折叠摘要行显示增删行数计数,点击展开后渲染 diff,默认折叠。展开的 diff SHALL 叠加两层着色:按目标文件语言的语法高亮与新增/删除行着色;语言不可识别时回退为仅增删着色。`write` 调用 SHALL 一律呈现为全新增 diff。diff 渲染 SHALL 遵循全站统一 design tokens 与响应式布局,不横向溢出;无 diff 数据的工具调用保持原有行为。

#### Scenario: 语法高亮与回退

- **WHEN** 展开的 diff 目标文件语言可识别(如 `.ts`)
- **THEN** diff 行内代码按语言语法着色,新增/删除行另有明确着色区分;跨行字符串或块注释的语法着色保持连续;语言不可识别时仅按增删着色,不报错、不缺失内容

#### Scenario: edit 调用折叠与展开

- **WHEN** `edit` 工具调用完成,卡片默认折叠
- **THEN** 摘要行显示路径与增删行数计数;点击展开后 diff 以新增/删除高亮渲染,再次点击收起

#### Scenario: write 调用全新增呈现

- **WHEN** `write` 工具调用完成(无论新建或覆盖已有文件)
- **THEN** 摘要行显示预览的新增行数计数,展开区将展示的写入内容以新增高亮渲染

#### Scenario: write 内容原样保留

- **WHEN** 写入内容含代码缩进、前导数字或空行
- **THEN** diff 保留每行原始内容,不把缩进或数字移入不可选择的行号栏

#### Scenario: write 投影预览受限

- **WHEN** 写入内容超过服务端 diff 的行数或 UTF-8 字节预算
- **THEN** 服务端仅投影预算内的完整行并标记截断,不复制超长单行到 diff;展开卡片明确提示预览不完整,并保留完整写入内容的查看入口

#### Scenario: 折叠时延迟渲染

- **WHEN** 卡片保持折叠且流式 diff 持续更新
- **THEN** 卡片仅更新摘要与计数,不执行 diff 语法高亮与逐行 HTML 消毒;展开后才渲染 diff

#### Scenario: 超长与响应式

- **WHEN** 展开的 diff 内容较长,或在 375px 至 2560px 各档视口下查看
- **THEN** diff 限高滚动并可完整查看全部行,页面不横向溢出,展开/收起交互支持鼠标、键盘与触屏

#### Scenario: 历史会话与重连恢复

- **WHEN** 浏览器重连或打开包含历史 `edit` 调用的会话
- **THEN** 从服务端投影恢复 diff 并照常显示;无持久 diff 的历史 `write` 调用保持原有显示

#### Scenario: 其他工具不受影响

- **WHEN** 非 `edit`/`write` 工具调用完成
- **THEN** 卡片摘要与展开行为与现状一致,不出现 diff 计数或 diff 视图

### Requirement: Web 后台任务面板
Web SHALL 在会话界面提供后台任务面板：顶栏在当前会话存在运行中 job 时显示数量入口；面板列出任务（标题或命令、状态、运行时长或退出码），选中后显示命令、工作目录、状态及输出尾部，运行中自动跟随新输出，向上查看后不强制滚到底部并提供回到底部入口。运行中任务 SHALL 有停止按钮，停止期间防止重复提交。面板 MUST NOT 提供启动任务的入口，打开与关闭不改变输入框草稿、附件与历史浏览状态。无任务时入口隐藏或显示空状态，且在 375、768、1440、1920 像素宽度下无横向溢出。

#### Scenario: 查看与停止
- **WHEN** 用户从顶栏打开面板，选中运行中的 `uv run` 任务并点击停止
- **THEN** 输出详情持续更新直到状态变为 stopped，停止按钮随之消失，其他任务不受影响

#### Scenario: 长输出与滚动
- **WHEN** 任务输出持续增长，用户向上查看较早内容
- **THEN** 不强制滚到底部，提供回到底部入口；输出显示与服务端保留的尾部一致，截断处有标注

#### Scenario: 响应式布局
- **WHEN** 用户在 375 与 1440 像素宽度打开含多个任务的面板
- **THEN** 列表与详情均可读，命令与输出可折行或滚动，无横向溢出

#### Scenario: 旧网关
- **WHEN** Web 连接不支持 job 的旧网关
- **THEN** 不显示任务入口或显示需要重新启动网关的提示，其他功能正常

### Requirement: Web 后台任务回报呈现
job 回报输入 SHALL 在 transcript 中以系统提示卡呈现（jobId、标题、状态、退出码，输出尾部默认折叠，可展开），MUST NOT 显示为用户消息气泡；终态变化时卡片状态与面板一致。

#### Scenario: 回报卡
- **WHEN** 后台任务退出并向会话回投回报
- **THEN** 消息列表出现系统提示卡，可展开查看输出尾部，随后显示模型的新一轮回答，用户气泡数量不变

#### Scenario: 刷新后一致
- **WHEN** 用户刷新页面或切换会话再回来
- **THEN** 回报仍以系统提示卡出现，且面板中的任务状态与卡片一致

### Requirement: Web 手机配对设置

Web 设置 SHALL 新增「手机配对」入口，在电脑本机提供局域网访问开关、地址选择、实际监听状态、限时二维码、可复制的配对文本和刷新操作，延续当前设置风格。默认只给出「手机与电脑连接同一局域网，在 App 中扫码」等简短指引；必要时提示防火墙及网络隔离，并说明关闭拉起 gateway 的前端会同时停止手机访问。运行在 WSL 时，候选地址 SHALL 为 Windows 局域网地址，并标明访问经由 Windows 侧中继；中继状态与失败原因须可见。配对能力不可用或用户从非本机访问时 MUST 明确说明，不显示可操作的管理控件。

#### Scenario: 本机开启与扫码
- **WHEN** 用户在电脑打开手机配对设置并启用入口
- **THEN** 启动成功后显示实际地址、二维码及到期状态，手机扫码即可配对；关闭或失败时不继续显示有效二维码

#### Scenario: 多网卡与过期
- **WHEN** 电脑存在多个可用局域网地址，或二维码过期
- **THEN** 用户可选择供手机访问的地址；过期二维码明确失效并提供刷新，不把回环或无效地址当成手机可达地址

#### Scenario: 旧网关或远程 Web
- **WHEN** 当前 gateway 尚不支持配对管理，或用户经局域网地址远程打开 Web
- **THEN** 显示更新/重新启动电脑端或在电脑本机打开设置的指引，不尝试绕过管理边界，不影响普通聊天

#### Scenario: WSL 下选择地址
- **WHEN** 用户在 WSL 中运行 neko web 并打开手机配对设置
- **THEN** 地址下拉只列出 Windows 局域网地址而非 WSL 内部 172.x 地址，开启后显示该地址、中继状态与二维码；关闭手机访问或中继失败时二维码消失并说明原因

### Requirement: Web 已配对设备管理

手机配对页 SHALL 显示已配对设备的名称、连接状态与最后连接时间，提供明确的单设备撤销操作及结果反馈；证书临近到期时 SHALL 提示，并提供需二次确认的重新生成证书操作（撤销全部设备）。撤销 SHALL 提示该设备无法继续连接、已受理任务仍继续，成功后更新实际设备状态；操作失败或迟到结果不得冒充成功。页面 MUST 支持键盘、触屏及现有主题，管理秘密不得出现在聊天内容或常规调试输出中。

#### Scenario: 撤销与同步
- **WHEN** 用户撤销在线手机并确认
- **THEN** 页面显示授权已撤销、手机断开，其他设备和电脑会话继续工作；刷新页面不恢复已撤销授权

#### Scenario: 管理失败与访问
- **WHEN** 撤销失败，或用户在 375px/1440px 宽度使用键盘访问管理页
- **THEN** 失败保留真实状态并可重试，二维码和设备列表不溢出，开关、刷新、撤销均有可访问名称与焦点

### Requirement: 数学公式渲染

Web 的 Markdown 渲染 SHALL 将行内 `$...$` 与块级 `$$...$$` 中的 LaTeX 渲染为数学公式，覆盖聊天消息与其他复用 Markdown 渲染的位置。公式内的反斜杠命令（如 `\{`、`\,`、`\!`、`\left`、`\frac`）MUST 保持原义，不被 Markdown 转义吞掉；代码块与行内代码中的 `$` MUST NOT 被当作公式。公式输出 MUST 经过消毒，不放宽对其余模型输出的消毒规则。

#### Scenario: 行内与块级公式

- **WHEN** 模型回答包含 `$s_i = q\cdot k_i$` 与独占一段的 `$$\text{Attn}(q,K,V)=\text{softmax}\!\left(\frac{qK^{\top}}{\sqrt{d_k}}\right)V$$`
- **THEN** 前者以行内公式、后者以居中块级公式呈现，界面不出现 `$` 定界符与原始 LaTeX 源码

#### Scenario: 转义命令保持原义

- **WHEN** 公式包含 `\{`、`\,`、`\!` 等转义命令
- **THEN** 渲染结果与 LaTeX 语义一致，反斜杠不被 Markdown 吞掉

#### Scenario: 代码中的美元符号

- **WHEN** 回答的代码块或行内代码包含 `$HOME`、`$x$` 等文本
- **THEN** 内容按原样显示为代码，不被渲染为公式

#### Scenario: 公式消毒

- **WHEN** 公式文本中夹带 HTML 标签、脚本或 `\href`、`\url` 等可产生链接或执行内容的命令
- **THEN** 界面不执行任何脚本，不产生可点击的外部链接，其余内容正常显示

### Requirement: 非法公式降级

Web SHALL 在公式无法解析时将该公式按原文（含定界符）显示，不得使整条消息渲染失败或丢失其他内容。流式输出中尚未闭合的公式 MUST 在闭合前保持原文显示，闭合后转为公式。

#### Scenario: 非法公式

- **WHEN** 回答包含 `$\frac{a$` 这类无法解析的公式及其他正常段落
- **THEN** 该公式按原文显示，其余段落、代码块与公式正常渲染

#### Scenario: 流式未闭合公式

- **WHEN** 流式回答已到达 `$$\sum_{i=1}` 但尚未收到结束定界符
- **THEN** 界面不报错且显示原文，收到结束定界符后该段转为公式

### Requirement: 输入框高度随草稿同步

Web 输入框的高度 SHALL 始终由当前草稿内容决定（不超过最大高度）。发送成功、命令执行后清空、切换会话、恢复草稿、回填输入历史或插入文件引用等任何改变草稿的路径之后，输入框 MUST 立即呈现与新内容匹配的高度，不得等到下一次键入才恢复。

#### Scenario: 长消息发送后恢复

- **WHEN** 用户发送一条使输入框增高到最大高度的长消息，输入随即被清空
- **THEN** 输入框立即回到单行的正常高度

#### Scenario: 切换会话

- **WHEN** 用户从有长草稿的会话切换到草稿为空或较短的会话
- **THEN** 输入框高度与新会话草稿内容匹配

#### Scenario: 回填历史

- **WHEN** 用户用 ↑ 回填一条较短的历史输入，原输入框因长草稿处于增高状态
- **THEN** 输入框高度随回填内容收缩，光标位置规则保持不变

### Requirement: Web 搜索服务设置

Web 联网搜索设置页 SHALL 提供「搜索服务」选择卡片，风格与站内 design tokens 一致，可选择 tavily（默认）、deepseek，不提供 auto 选项，并说明各项使用的凭据。卡片 SHALL 显示当前选择及各 provider 的凭据状态；选择 deepseek 但缺少 DeepSeek Key 时 SHALL 提示在本页的 DeepSeek 凭据卡配置，或改选 Tavily。选择变更 SHALL 即时保存并同步到其他前端，保存期间防止重复提交，失败显示可重试反馈而不宣称已保存。页面 MUST NOT 显示或回填任何密钥。

#### Scenario: 切换 provider

- **WHEN** 用户在联网搜索页将搜索服务由 tavily 改为 deepseek
- **THEN** 卡片显示当前选择为 deepseek，TUI 同步更新，后续联网调用使用 DeepSeek

#### Scenario: 选择 deepseek 但缺少 Key

- **WHEN** 选择 deepseek 且未配置 DeepSeek Key
- **THEN** 卡片提示需在本页 DeepSeek 凭据卡配置 Key 或改选 Tavily，不要求离开本页

#### Scenario: 保存 Key 不改变选择

- **WHEN** 选择为 tavily，用户在联网搜索页保存 DeepSeek Key
- **THEN** 当前选择仍为 tavily

#### Scenario: 保存失败与重复提交

- **WHEN** 保存选择期间再次点击，或请求失败
- **THEN** 重复提交被阻止，失败显示可重试反馈，页面展示的仍是服务端最终选择

### Requirement: 公式括号定界符

Web 的 Markdown 渲染 SHALL 除 `$..$` 与 `$$..$$` 外，也把 `\(..\)` 渲染为行内公式、把 `\[..\]` 渲染为块级公式，复用「数学公式渲染」与「非法公式降级」的全部规则（消毒、降级为原文、未闭合保持原文）。代码块与行内代码中的 `\(`、`\[` MUST 保持原文；`\\(`、`\\[`（转义反斜杠）MUST NOT 被当作定界符。

#### Scenario: 行内与块级括号公式

- **WHEN** 模型回答包含 `速度 \(v = \frac{s}{t}\)` 与独占一段的 `\[\sum_{i=1}^{n} i\]`
- **THEN** 前者以行内公式、后者以居中块级公式呈现，界面不出现 `\(`、`\[` 定界符与原始 LaTeX 源码

#### Scenario: 代码中的括号定界符

- **WHEN** 回答的行内代码或代码块包含 `\(x\)`、`\[x\]`
- **THEN** 内容按原样显示为代码，不被渲染为公式

#### Scenario: 非法与未闭合括号公式

- **WHEN** 回答包含 `\(\frac{a\)` 或流式中尚未收到 `\]` 的 `\[\sum_{i=1}`
- **THEN** 该部分按原文显示且不影响其余内容，闭合且合法后转为公式

#### Scenario: 括号公式消毒

- **WHEN** 括号公式中夹带 HTML 标签、脚本或 `\href`、`\url`
- **THEN** 界面不执行任何脚本，不产生可点击的外部链接

### Requirement: Web 上下文设置栏目

Web 设置区 SHALL 提供独立的「上下文」栏目（侧栏菜单项，路径 `/settings/context`），不与密钥页混排。页面 SHALL 先以触发位置预览条展示压缩与裁剪在模型窗口上的触发位置（关闭的步骤不显示），再分压缩与工具结果裁剪两组卡片，各带开关；数值项 SHALL 以一键选择的预设档位呈现（含“默认”以清除已保存值，配置文件中的非预设值显示为自定义档位），MUST NOT 要求键盘输入。每项 SHALL 显示当前生效值与来源（默认、配置文件、已保存），并提供全部恢复默认。选择即保存并同步到其他前端，连续点击 MUST NOT 丢失，按点击顺序保存；失败显示可重试反馈而不宣称已保存。裁剪相关项 SHALL 说明其会使前缀缓存失效、默认关闭，且不改变界面中已显示的工具结果。

#### Scenario: 一键调整

- **WHEN** 用户在「上下文」页点选压缩触发的 60% 档位
- **THEN** 该档位被选中并显示来源为已保存，预览条上的压缩标记移到 60%，TUI 同步更新，之后的压缩检查使用新阈值

#### Scenario: 默认状态

- **WHEN** 从未保存过任何设置且配置文件未设置
- **THEN** 压缩开关为开、裁剪开关为关，压缩触发显示“接近窗口上限”，来源均为默认，全部恢复默认不可点

#### Scenario: 开关与关闭项

- **WHEN** 用户关闭裁剪开关
- **THEN** 预览条不再显示裁剪标记，裁剪的数值项变暗但保持可选，压缩不受影响

#### Scenario: 配置文件值

- **WHEN** 配置文件设置了非预设的数值
- **THEN** 该项显示“默认”被选中，并多出一个标注自定义的档位及来源提示；选择其他档位覆盖它，选择“默认”恢复为配置值

#### Scenario: 恢复默认

- **WHEN** 用户选择某项的“默认”档位或点击全部恢复默认
- **THEN** 已保存值被清除，页面显示回落后的生效值与来源

#### Scenario: 连续点击与保存失败

- **WHEN** 用户快速连续点选多个档位，或请求失败
- **THEN** 各次选择按顺序发送且不被忽略，保存期间显示进行中；失败显示可重试反馈，页面展示的仍是服务端最终状态

### Requirement: Web 忙时发送

Web 输入框 SHALL 在会话运行中保持可编辑并允许发送，发送的消息一律排队，输入区内 MUST NOT 提供预选投递方式的开关。按钮与占位文案 SHALL 说明消息将在回答结束后排队处理。发送后沿用草稿保留、requestId 幂等与失败保留规则；`/compact` 命令 MUST 仍先于普通消息解析。

#### Scenario: 运行中发送

- **WHEN** 会话正在回答，用户输入文字并点击发送
- **THEN** 消息被受理并出现在排队条中，草稿清空，输入框保持可用，当前回答不中断，输入区没有引导开关

#### Scenario: 受理失败

- **WHEN** 电脑拒绝该次忙时提交
- **THEN** 保留草稿与附件并显示原因，不显示已排队，同一草稿重试沿用原 requestId

#### Scenario: 空闲时发送

- **WHEN** 会话空闲
- **THEN** 发送行为与现有一致，按钮不显示排队文案

### Requirement: Web 排队条的引导与撤回

Web SHALL 在输入区上方显示当前会话排队输入条，每项含投递方式标识、文字预览与图片数量；仍为排队的项提供「引导」与「撤回」，已是引导的项只提供「撤回」，无排队项时不占位。引导后该项标识变为引导并留在条中直到进入 transcript。撤回 SHALL 把文字取回草稿（草稿为空时覆盖，否则追加到新行），带图片的项仅取回文字并提示图片未恢复；操作结果为已放入时提示已发送并不改草稿。排队条在 375、768、1440、1920 像素宽度下无横向溢出，可键盘操作并有可访问名称。「停止」保持清空全部排队并中止运行。

#### Scenario: 引导一条排队消息

- **WHEN** 用户点击某排队项的「引导」
- **THEN** 该项标识变为引导且不再提供「引导」，草稿与其他排队项不变，当前运行不中断

#### Scenario: 撤回并取回文字

- **WHEN** 用户点击某排队项的撤回，草稿为空
- **THEN** 该项消失，其完整原文回到输入框可再次编辑发送，其余排队项不变

#### Scenario: 撤回时草稿非空

- **WHEN** 用户已在输入框键入新内容并撤回某项
- **THEN** 被撤回文字追加到草稿新行，不覆盖用户的新内容

#### Scenario: 已被放入

- **WHEN** 用户点击引导或撤回时该消息刚进入 transcript
- **THEN** 显示该消息已发送的提示，草稿不变，transcript 中保留该消息

#### Scenario: 旧网关

- **WHEN** Web 连接不提供排队列表的旧网关
- **THEN** 不显示排队条、引导与撤回入口，忙时仍可发送

#### Scenario: 切换会话

- **WHEN** 用户在有排队项的会话与其他会话之间切换
- **THEN** 排队条只显示当前会话的项，不串会话，不影响各会话草稿

### Requirement: Web 右侧工作区栏

Web SHALL 在会话页提供右侧「工作区」栏，含「文件」与「改动」两个标签页，由顶栏入口开合；当前标签与展开的目录、已打开的文件在同一会话内切换栏开合时保留，切换会话时重置。栏的开合与浏览 MUST NOT 改变输入框草稿、附件、聊天滚动位置和输入历史浏览状态。栏默认关闭，不因 agent 修改文件而自动打开。

#### Scenario: 开合保留状态

- **WHEN** 用户打开工作区栏、展开两层目录并查看一个文件后关闭再重新打开
- **THEN** 目录展开状态与所查看的文件保持，输入框草稿与附件未被改动

#### Scenario: 不自动打开

- **WHEN** agent 在栏关闭时修改了文件
- **THEN** 栏保持关闭，仅顶栏入口上的改动数更新

### Requirement: 右侧位置共用

右侧栏 SHALL 与子 agent 面板、后台任务面板共用同一右侧位置，同一时刻只显示其中一个；用户主动打开某一面板时其余面板收起。工作区栏已打开时，子 agent 首次委派 MUST NOT 自动抢占该位置，仅通过消息流中的入口提示；用户关闭其他面板后的恢复规则保持不变。

#### Scenario: 互斥切换

- **WHEN** 工作区栏已打开，用户从顶栏打开后台任务面板
- **THEN** 工作区栏收起，任务面板显示；再次打开工作区栏时恢复此前的标签与浏览位置

#### Scenario: 委派不抢占

- **WHEN** 工作区栏已打开时主 agent 首次委派子任务
- **THEN** 栏保持不变，消息流中的委派卡片与子 agent 入口可用，用户点击后才切换到子 agent 面板

### Requirement: 工作区栏的响应式与可访问性

工作区栏在桌面端 SHALL 以可调整宽度的右侧栏呈现，宽度有最小与最大限制；窄屏（≤1023px）SHALL 以可关闭的抽屉或全屏面板呈现。文件树 SHALL 支持键盘导航（方向键移动、左右展开/收起、Enter 打开），标签页与按钮具有可访问名称，焦点在关闭后回到顶栏入口。在 375、768、1440、1920 像素宽度下 MUST 无横向溢出：长路径折行或省略并可通过标题查看完整路径，代码区在自身容器内横向滚动。

#### Scenario: 键盘操作

- **WHEN** 用户仅用键盘在文件树中移动、展开目录并按 Enter 打开文件
- **THEN** 焦点状态可见，查看器显示所选文件，按 Esc 关闭抽屉后焦点回到顶栏入口

#### Scenario: 各宽度布局

- **WHEN** 用户在 375 与 1440 像素宽度打开栏并查看含长路径、长行代码的文件
- **THEN** 页面无横向溢出，长路径可辨识，代码在查看器内滚动

### Requirement: 工作区栏的旧网关与错误降级

Web 连接不支持工作区接口的旧网关时 SHALL 隐藏该入口或提示需重新启动网关，其他功能正常。文件树、查看器与改动列表的加载失败 SHALL 在栏内给出可重试的错误提示，MUST NOT 影响聊天、审批、提问等主流程。

#### Scenario: 旧网关

- **WHEN** Web 连接到不支持工作区接口的旧网关
- **THEN** 不显示工作区入口，或显示需要重新启动网关的提示，聊天与其他面板正常

#### Scenario: 读取失败

- **WHEN** 文件读取因权限不足或超时失败
- **THEN** 栏内显示错误与重试入口，聊天流与输入框不受影响

### Requirement: Web 顶栏工作区图标入口

顶栏的工作区入口 SHALL 是图标按钮而非文字药丸：使用右侧栏图标，agent 改动文件数大于 0 时以角标显示，超过两位数时显示上限形式。按钮 MUST 保留可访问名称（含改动文件数）、`aria-expanded` 与悬停提示，开合与焦点回归行为不变，并在旧网关上继续隐藏。

#### Scenario: 有改动

- **WHEN** agent 已修改 3 个文件且工作区栏关闭
- **THEN** 顶栏显示右侧栏图标，角标为 3，朗读名称为「工作区，3 个改动文件」，点击打开右侧栏

#### Scenario: 无改动

- **WHEN** 当前会话没有改动文件
- **THEN** 图标无角标，朗读名称为「工作区」

### Requirement: Web 打开工作区分体按钮

Web 顶栏 SHALL 在工作区入口之前提供「打开工作区」分体按钮：主按钮用上次选择的目标打开当前会话的工作区根目录，下拉菜单列出「VS Code」与文件管理器（名称随平台），每项显示图标。主按钮与菜单项 MUST 有可朗读名称与悬停提示（如「用 VS Code 打开」），菜单可用键盘打开与操作，Escape 关闭并把焦点还给触发控件。当前无会话、连接未就绪或本机能力不可用时 SHALL 隐藏或置灰。

#### Scenario: 默认打开

- **WHEN** 用户首次点击主按钮
- **THEN** 当前会话工作区在 VS Code 中打开，主按钮图标为 VS Code

#### Scenario: 切换目标

- **WHEN** 用户展开下拉并选择文件管理器
- **THEN** 工作区在文件管理器中打开，主按钮之后改为文件管理器图标

#### Scenario: 键盘操作

- **WHEN** 用户用键盘聚焦下拉触发器并按 Enter
- **THEN** 菜单打开且焦点进入菜单，方向键选择，Enter 执行，Escape 关闭并回到触发控件

### Requirement: Web 顶栏窄屏布局

窄屏下顶栏 SHALL 在 375 像素宽度无横向溢出：打开工作区入口折叠进更多菜单或收为仅图标，且不遮挡会话标题、连接状态与导出入口。

#### Scenario: 小屏幕

- **WHEN** 在 375 像素宽度查看顶栏
- **THEN** 打开工作区、工作区栏与导出入口均可见可点或位于菜单内，无重叠与横向溢出

### Requirement: Web 模型选择器

Web SHALL 提供「provider 下拉 + 紧凑模型列表」的模型选择器，取代折叠分组与平铺的模型按钮列表。选择器 SHALL 只列出已启用 provider 的模型；provider 下拉可键入过滤，每项显示模型数，默认选中当前会话模型所属 provider（不可用时选首个可选 provider）。模型列表每项 SHALL 为单行紧凑呈现，显示名称及上下文窗口、是否支持图片与思考能力，并可查看模型 id；当前模型在所选 provider 的列表中高亮并定位。搜索框 SHALL 按模型名、模型 id 与 provider 名即时匹配：有查询词时跨 provider 显示命中模型，按 provider 小标题（不折叠）标注所属 provider，清空后恢复「下拉 + 列表」视图。已启用但缺少 Key 的 provider SHALL 在下拉与列表头标明未配置并提供前往模型服务设置的入口，其模型不可选。

#### Scenario: 下拉切换与列表

- **WHEN** 用户启用多个 provider 后打开模型选择器，在下拉中选择 OpenRouter
- **THEN** 只显示 OpenRouter 的紧凑模型列表，其他 provider 的模型不出现，无需展开或折叠任何分组

#### Scenario: 分组与搜索

- **WHEN** 用户启用多个 provider 后打开模型选择器并输入 `claude`
- **THEN** 仅显示名称或 id 含 claude 的模型，跨 provider 显示并以小标题保留 provider 标注；清空搜索恢复 provider 下拉与单 provider 列表

#### Scenario: 缺 Key 的 provider

- **WHEN** OpenRouter 已启用但未配置 Key
- **THEN** 其下拉项与列表头显示未配置标记与配置入口，模型不可选；配置完成后无需刷新即变为可选

#### Scenario: 超大列表

- **WHEN** 单个 provider 含数百个模型
- **THEN** 列表在固定高度内滚动、操作不卡顿，无横向溢出；已选模型在所属列表中可见

#### Scenario: 键盘与小屏

- **WHEN** 用户仅使用键盘，或在 375 像素宽度下使用选择器
- **THEN** provider 下拉、搜索、模型选择与确认均可访问，焦点可见，Escape 取消并恢复焦点；面板无横向溢出

#### Scenario: 默认选中当前模型的 provider

- **WHEN** 当前会话使用 DeepSeek Flash 时打开选择器
- **THEN** 下拉选中 DeepSeek，列表中 Flash 高亮；若该 provider 已被取消启用，则改选首个可选 provider 并显示不可用提示

### Requirement: Web 联网搜索设置页

Web SHALL 提供独立的「联网搜索」设置栏目（侧栏菜单项，路径 `/settings/search`），不与模型服务页混排。页面 SHALL 承载搜索服务选择（tavily 默认、deepseek，无 auto），并 SHALL 始终同时显示 Tavily 与 DeepSeek 两张凭据卡，各自管理 Key（来源、环境变量状态、保存、移除、申请链接），与当前选择无关。DeepSeek 凭据卡 SHALL 说明该 Key 与「模型服务」共用，在任一页面保存或移除都对另一页生效；该卡 MUST NOT 提供 provider 启用开关。页面 MUST NOT 显示或回填任何密钥。

#### Scenario: 独立入口

- **WHEN** 用户打开设置
- **THEN** 侧栏同时有「模型服务」与「联网搜索」两个独立菜单项，模型服务页中不再出现搜索服务卡片与 Tavily 条目

#### Scenario: 管理 Tavily

- **WHEN** 用户在联网搜索页保存并移除 Tavily Key
- **THEN** 来源在保存值与 keyless（无环境变量时）之间切换，成功后密码框清空，其他 provider 凭据不受影响

#### Scenario: 选择 tavily 时仍可配置 DeepSeek

- **WHEN** 当前搜索服务为 tavily，用户打开联网搜索页
- **THEN** 页面显示 DeepSeek 凭据卡及其当前来源，用户可直接保存 DeepSeek Key，无需前往模型服务页

#### Scenario: DeepSeek Key 与模型服务共用

- **WHEN** 用户在联网搜索页保存 DeepSeek Key
- **THEN** 模型服务页的 DeepSeek 条目同步显示已保存，TUI 的 /login 也显示同一状态；移除后各处同步回退为环境变量或无 Key

#### Scenario: 选择 deepseek 缺少 Key

- **WHEN** 选择 deepseek 且未配置 DeepSeek Key
- **THEN** 页面提示配置 DeepSeek Key 或改选 Tavily，指向本页的 DeepSeek 凭据卡

### Requirement: Web 默认模型设置

Web 模型选择器 SHALL 标识当前默认模型，并对可选模型提供「设为默认」操作；已是默认的模型可取消默认。未配置 Key 而不可选的模型 MUST NOT 提供该操作。操作结果 SHALL 即时反映在标识上并与其他前端保持一致；默认模型 SHALL 只影响新建会话，不改变当前会话模型。

#### Scenario: 设为默认

- **WHEN** 用户在选择器中对某可选模型执行「设为默认」
- **THEN** 该模型显示默认标识，之后新建的会话默认使用该模型，当前会话模型不变

#### Scenario: 取消默认

- **WHEN** 用户对当前默认模型取消默认
- **THEN** 标识消失，之后新建的会话按配置文件或内置默认解析

#### Scenario: 无 Key 模型

- **WHEN** 选择器中存在已启用但未配置 Key 的模型
- **THEN** 该条目保持不可选，且不显示「设为默认」入口

#### Scenario: 跨端一致

- **WHEN** TUI 修改默认模型后用户打开 Web 选择器
- **THEN** Web 显示同一默认模型标识，无需刷新页面

### Requirement: Web Git Bash 缺失提示

Web 连接的网关在应用信息中报告 Windows shell 缺失时，Web SHALL 在聊天页以按当前界面语言的简洁非阻断提示说明命令与后台任务不可用，并给出下一步：安装 Git for Windows 后重新检查，或在配置文件中设置 `shell.path`；配置无效时 SHALL 说明配置路径的问题。提示 SHALL 可关闭，关闭后同一缺失状态在本页面会话内 MUST NOT 再次出现；状态变为可用后提示 SHALL 消失。设置中的「关于与更新」页 SHALL 显示当前 shell 状态（可用时显示 bash 路径）。网关未提供该字段时 MUST NOT 显示提示或 shell 状态行，提示 MUST NOT 影响输入、发送与其他面板。

#### Scenario: 缺少 Git Bash

- **WHEN** Windows 网关报告 shell 缺失，用户打开聊天页
- **THEN** 页面按当前界面语言显示提示（默认中文），含安装 Git for Windows 与 `shell.path` 的指引，输入框可正常使用

#### Scenario: 关闭后不再出现

- **WHEN** 用户关闭该提示，随后 WebSocket 重连且状态仍为缺失
- **THEN** 提示不再出现

#### Scenario: 安装后恢复

- **WHEN** 用户安装 Git for Windows 后在「关于与更新」页触发检查
- **THEN** shell 状态显示为可用及 bash 路径，聊天页提示消失

#### Scenario: 非 Windows 或旧网关

- **WHEN** Web 连接 Linux 网关或不含该字段的旧网关
- **THEN** 不显示提示，「关于与更新」页不显示 shell 状态行

### Requirement: Web 计划模式斜杠命令与状态标识
Web SHALL 只通过 `/plan` 斜杠命令进入或切换 plan 模式，不提供单独的进入按钮（待批准计划卡片上的「取消并退出计划模式」除外）。`/plan` SHALL 出现在命令菜单中并带说明，提交时在 plan 与 normal 模式间切换，命令本身不发送给模型、不进入输入历史；会话运行中输入 `/plan` MUST 提示需先等待或停止，且保留草稿、不切换。plan 模式下输入区 MUST 显示明确且可访问的模式标识。网关未发布计划字段时命令菜单 MUST 不列出 `/plan`，手动输入时提示该网关不支持。

#### Scenario: 命令切换与标识
- **WHEN** 用户在空闲会话输入并提交 `/plan`
- **THEN** 会话进入 plan 模式，输入区显示规划模式标识，草稿清空且没有消息发给模型；再次提交 `/plan` 退出并去除标识

#### Scenario: 运行中输入命令
- **WHEN** 会话回答中用户提交 `/plan`
- **THEN** 显示需先等待或停止的提示，模式不变，输入框内容保留

#### Scenario: 旧网关
- **WHEN** 连接的网关不支持计划能力
- **THEN** 命令菜单不含 `/plan`，输入区不显示模式标识

### Requirement: Web 计划卡片与决定
Web SHALL 在消息流中为 `submit_plan` 渲染计划卡片，展示标题、有序步骤、说明与状态（待批准、已批准、要求修改、已取代、已取消）。待批准卡片 MUST 提供「批准并执行」、「要求修改」（带文字反馈输入）与「取消并退出计划模式」操作；已结算卡片 MUST 只读显示最终状态。决定失败或被其他端抢先时 MUST 显示已结算的真实状态，计划标题与反馈按纯文本显示，步骤与说明（含「假设与风险」）按经过消毒的 Markdown 渲染。

#### Scenario: 批准
- **WHEN** 用户在待批准卡片点击"批准并执行"
- **THEN** 卡片变为已批准，模式标识消失，会话开始执行

#### Scenario: 要求修改
- **WHEN** 用户填写反馈并点击"要求修改"
- **THEN** 卡片变为要求修改，会话保持规划模式并收到反馈

#### Scenario: 取消并退出
- **WHEN** 用户在待批准卡片点击「取消并退出计划模式」
- **THEN** 卡片变为已取消，模式标识消失，会话回到 normal 模式，没有消息发给模型

#### Scenario: 被其他端抢先
- **WHEN** 用户点击批准时该计划已被另一端要求修改
- **THEN** 卡片显示已结算状态，不重复执行

### Requirement: Web 会话列表待批准标记
会话列表 SHALL 为有待批准计划的会话显示"等待批准"状态文字，与"等待回答"区分；浏览器标签标题的等待前缀 SHALL 也覆盖待批准会话。

#### Scenario: 其他会话待批准
- **WHEN** 当前不在该会话，且该会话提交了计划
- **THEN** 会话列表显示等待批准，状态在批准或取消后清除

### Requirement: Web 设置菜单包含外观

Web 设置区侧栏菜单 SHALL 在「模型服务」「联网搜索」「上下文」之后、「手机配对」之前提供「外观」菜单项，指向 `/settings/appearance`，当前页高亮并带 `aria-current`。外观页的外壳、返回聊天入口与窄屏横排行为 SHALL 与其他设置页一致。栏目的具体内容见 `web-appearance` 能力。

#### Scenario: 进入外观页

- **WHEN** 用户在设置页点击「外观」
- **THEN** 路径变为 `/settings/appearance`，菜单项高亮，页面显示主题与聊天排版两组选项

#### Scenario: 窄屏菜单

- **WHEN** 视口为移动宽度
- **THEN** 设置菜单顶部横排，「外观」可点且不遮挡其他菜单项

### Requirement: Web 设置菜单包含语言

Web 设置区侧栏菜单 SHALL 在「外观」之后、「手机配对」之前提供「语言 / Language」菜单项，指向 `/settings/language`，当前页高亮并带 `aria-current`。语言页的外壳、返回聊天入口与窄屏横排行为 SHALL 与其他设置页一致，页面提供「中文」与「English」两个互斥选项，当前语言处于选中状态且可由键盘操作。语言偏好的保存与应用见 `ui-language` 能力。

#### Scenario: 进入语言页

- **WHEN** 用户在设置页点击「语言 / Language」
- **THEN** 路径变为 `/settings/language`，菜单项高亮，页面显示「中文」与「English」两个选项，当前语言被选中

#### Scenario: 窄屏菜单

- **WHEN** 视口为移动宽度
- **THEN** 设置菜单顶部横排，「语言 / Language」可点且不遮挡其他菜单项

#### Scenario: 键盘切换

- **WHEN** 用户用键盘在两个选项间移动并确认
- **THEN** 语言切换生效，焦点保持在所选项上
