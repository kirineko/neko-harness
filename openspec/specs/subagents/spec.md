# subagents Specification

## Purpose

为主 agent 提供内置子 agent 的前台任务委派能力，在独立对话上下文中完成调查、规划或实现，并让用户跨界面观察、停止和恢复任务，保持任务归属及最终结果一致。

## Requirements

### Requirement: 内置角色与工具边界
系统 SHALL 提供 explore、plan、coder 三种内置角色。explore 与 plan SHALL 具有文件发现、内容搜索、读取以及已配置的网络调研能力，不具有直接文件写入或编辑工具。explore SHALL 默认只读，Bash 必须经用户逐次审批后执行，获批命令可能产生修改；plan MUST 无 shell 执行能力；coder SHALL 可使用现有编码工具。所有子 agent MUST 无法再次委派；未知角色 MUST 被拒绝。

#### Scenario: 未知路径调查
- **WHEN** 主 agent 向 explore 提交仅包含调查目标而没有具体文件路径的任务
- **THEN** 子 agent 能发现文件、搜索内容、读取证据并交付结论，未经用户批准不得执行命令或通过命令修改工作区

#### Scenario: 实现和角色限制
- **WHEN** coder 执行明确的实现任务，或 explore/plan 尝试直接写入、编辑、嵌套委派，或 plan 尝试执行 shell
- **THEN** coder 可修改并验证；受限调用在执行前被拒绝，不仅从模型工具列表隐藏

#### Scenario: explore 请求命令执行
- **WHEN** explore 需要 Git、版本查询或其他诊断命令
- **THEN** 可发起 Bash 审批，批准前等待，拒绝后可继续调查；不向 plan、coder 或主 agent 扩散该角色权限变更

### Requirement: 前台委派与上下文隔离
系统 SHALL 允许主 agent 提交角色、任务正文和简短标题进行前台委派，创建时子 agent 仅接收显式任务材料及自身系统资源，不复制主会话历史；接续时 SHALL 使用同一子会话此前的模型上下文，并追加本轮任务。子 agent SHALL 在创建时继承派发配置，接续沿用其模型、思考强度、角色和工作目录。主 agent SHALL 等待本轮委派结算，再收到最终报告或明确失败；中间日志 MUST NOT 自动注入主模型上下文。

#### Scenario: 并行调查
- **WHEN** 主 agent 同轮委派多个独立调查
- **THEN** 子任务可并行运行且上下文隔离，主 agent 在本轮工具结算后汇总各自结果

#### Scenario: 输入材料不足
- **WHEN** 子 agent 无法从明确传入的材料完成任务
- **THEN** 返回缺失信息或限制给主 agent，不伪造已访问主会话历史或已完成任务

#### Scenario: 空闲时接续
- **WHEN** 主 agent 指定当前主会话所属的空闲子 agent 提交后续任务
- **THEN** 在原子会话上下文中执行，主 agent 前台等待本轮报告，不创建替代子会话、不重复执行旧任务

#### Scenario: 同一子 agent 忙碌
- **WHEN** 同一子 agent 已有受理、排队、运行或取消清理中的任务而收到另一轮派发
- **THEN** 明确返回忙碌，且不提交额外输入、不合并回答；重放已受理的同一次调用不被自身互斥拒绝

### Requirement: 委派取消与恢复
委派及子会话 SHALL 持久关联，恢复同一次调用 MUST 复用原子会话与已受理输入。停止主会话 SHALL 级联停止本轮全部子任务；单独停止 SHALL 精确取消当前轮，不停止兄弟任务，主 agent 获得取消结果。取消清理结束且当前轮任务终态后，子 agent 身份和上下文 SHALL 保留并可接续。浏览或断开前端 MUST NOT 取消执行。取消 MUST NOT 被宣称回滚已发生的文件修改。

#### Scenario: 重启时任务未完成
- **WHEN** gateway 在派发后、结果回传前重启
- **THEN** 沿原生任务恢复语义继续或报告中断，不重复创建子会话、重复提交任务或无条件重放有副作用的工具

#### Scenario: 单独停止和全局停止
- **WHEN** 用户停止一个子任务或停止正在等待的主会话
- **THEN** 前者仅停止目标并保留兄弟任务，后者停止所属子任务并保留可查看的已产生记录

#### Scenario: 接续轮停止后再使用
- **WHEN** 子 agent 第二轮被停止，随后同一主会话向它提交第三轮
- **THEN** 第二轮的实际执行与审批等待均已停止，第三轮使用保留上下文；旧停止请求不得停止第三轮

#### Scenario: 清理期间重启
- **WHEN** 停止接续轮的过程中 gateway 重启
- **THEN** 恢复取消清理，直到该轮终态和子会话空闲前不开放新轮，不能仅因主 agent 的等待结束而留下脱离归属的工作

### Requirement: 持久委派记录与容量
系统 SHALL 分别保存稳定子 agent 身份与每轮委派的主会话、调用身份、子会话、角色、标题和最终结果状态，区分排队、运行、完成、失败和停止。子 agent SHALL 显示空闲、排队或运行状态；每轮完成状态 SHALL 以实际运行结算为准，不能以一次内部工具失败判断整个子 agent 失败。并发 SHALL 有界；首版每主会话最多同时运行三个子 agent，同一规范化工作区最多运行一个 coder，不同子 agent 的多余轮次可取消地等待；空闲身份不占用配额，同一子 agent 不接受多轮等待。

#### Scenario: 完成后的历史
- **WHEN** 子任务结束并从活跃任务图移除，随后客户端重连或 gateway 重启
- **THEN** 委派记录及最终状态仍可查看，不变成未知或永久运行

#### Scenario: 队列取消
- **WHEN** 达到并发上限后新任务等待，用户停止主会话
- **THEN** 排队任务一并停止，之后不再启动或占用运行配额

#### Scenario: 工具错误后恢复
- **WHEN** 子 agent 某次命令失败但继续修复并最终正常交付
- **THEN** 内部流程保留失败工具卡，委派状态按最终结算显示完成

#### Scenario: 接续保留旧轮结果
- **WHEN** 同一子 agent 已完成一轮并开始下一轮
- **THEN** 子 agent 显示当前轮活动状态，旧轮报告、终态与耗时保持不变；任务结束后身份回到空闲

### Requirement: 持久子 agent 身份与发现
系统 SHALL 为每个子 agent 提供稳定且绑定主会话的身份，将其返回给主模型，并提供有界可分页查询。查询 SHALL 包含角色、可用状态与有限任务摘要；创建、接续和重启保持身份稳定。接续 MUST 验证主会话归属，不允许修改角色、工作目录或扩大工具权限；历史分叉引用不得成为原子 agent 的控制入口。

#### Scenario: 主模型发现和复用
- **WHEN** 主模型此前的报告不在当前上下文中，查询本会话已有子 agent
- **THEN** 获得稳定身份和可用状态，可指定空闲身份继续任务，不需要猜测内部工具调用 ID

#### Scenario: 非法身份和权限覆盖
- **WHEN** 主模型指定未知、其他主会话或分叉历史中的身份，或接续时提供角色/目录权限覆盖
- **THEN** 调用明确失败且不提交输入，不改变原子会话配置或无关会话

#### Scenario: 既有调用兼容
- **WHEN** 模型使用不带动作的原有角色、标题和任务参数调用委派
- **THEN** 仍创建新子 agent，并返回可用于后续接续的稳定身份

### Requirement: 子 agent 累计与轮次用量
系统 SHALL 分别提供子 agent 累计用量和每轮增量，含输入、输出、缓存 token 和成本；主会话总用量 SHALL 对同一子会话只汇总一次。运行轮显示已记录增量，终态轮保留固定结果；失败或停止仍计入实际消耗。旧上下文在接续请求中再次产生的费用 SHALL 正常计入，缺失历史基线 MUST NOT 伪造成精确零或精确增量。

#### Scenario: 同一子 agent 两轮成本
- **WHEN** 主 agent 成本为 0.10，子 agent 两轮分别为 0.03 和 0.02，另一子 agent 为 0.04
- **THEN** 第一子 agent 累计为 0.05，两轮值分别保留，主会话总成本为 0.19，不重复加入同一子会话累计值

#### Scenario: 取消和恢复后的增量
- **WHEN** 一轮已消耗 token 后取消或等待期重启
- **THEN** 保留原始开始基线和实际累计消耗，重连不重新计算起点；未提交输入即取消的轮次不产生子模型费用

#### Scenario: 历史基线缺失
- **WHEN** 已有旧轮缺少可证明的用量起点
- **THEN** 累计用量仍真实可用，该轮增量显示未记录，新轮正常记录精确增量

### Requirement: 规划模式下的委派限制
主会话处于 plan 模式时系统 SHALL 只允许启动或继续只读角色（explore 与 plan），并 MUST 拒绝启动或继续 coder 角色，拒绝结果说明当前处于只读规划模式。已有 coder 子 agent 的记录与历史保持可查看。

#### Scenario: 启动 coder 被拒绝
- **WHEN** plan 模式下模型请求委派 coder 子 agent
- **THEN** 不创建委派与子会话，模型得到说明限制的错误结果

#### Scenario: 继续已有 coder 被拒绝
- **WHEN** plan 模式下模型尝试继续此前创建的 coder 子 agent
- **THEN** 不开始新一轮，模型得到同样的错误结果，原记录不变

#### Scenario: 只读角色可用
- **WHEN** plan 模式下模型委派 explore 子 agent 做调研
- **THEN** 委派与审批行为与 normal 模式一致
