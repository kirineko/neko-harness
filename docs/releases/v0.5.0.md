**新增**

- Web 工作区移除：切换器里每个项目都有移除按钮（悬停 / 聚焦显示，触屏常驻），点击后确认
  - 只是从列表里隐藏：不删除文件，也不归档会话；该项目的会话随之隐藏，重新添加同一目录即可恢复
  - Web 服务的启动目录（置灰并说明原因）、最后一个项目、有运行中会话（或正在等待回答 / 计划决定）的项目不能移除
  - 移除当前项目后自动切到列表里的下一个
- Web 右侧面板可调宽：工作区、后台任务、子 agent 三个面板共用一个宽度（320–960px，默认 560px，且不超过视口 60%）
  - 拖拽边缘，或用键盘 ←/→（Home/End 到最小 / 最大），双击恢复默认
  - 宽度记在浏览器本地，刷新和新开标签页保持；窄屏仍是抽屉 / 全屏

**实现说明**

- 移除用独立的「已移除路径」记录实现：启动时按已有会话重新登记、fork 这类隐式登记会跳过它，用户显式添加（目录选择、新建会话指定目录、网关启动目录）才会清除，所以不会“复活”
- 面板宽度偏好只存浏览器 localStorage，不经网关，TUI 与手机端不受影响

**已知限制**

- TUI 与手机端没有移除项目的入口，只会正确跟随目录变化
- 面板宽度不跨浏览器、不跨机器同步

**兼容性**

- 应用协议由 8 升到 9（`neko.workspaces` 契约 v2 新增 `remove`），不保留旧网关降级：升级后请退出所有 neko 界面与服务再启动，旧版本的界面或网关会得到协议不兼容提示
- 手机端 API（v1）不变

**内部**

- 测试默认多 worker 并行：全量约 85s → 约 12s；`bun run test:serial` 保留原顺序执行，用于排查时序问题
- 发布流程合并为单个 `release.yml`，推送 `vX.Y.Z` tag 即发版；验证（Linux / macOS / Windows 全量测试与安装冒烟，Android 检查与构建）全部通过后才发布 npm 并创建 Release，发布说明来自 `docs/releases/`
- Windows 首次纳入 CI 并作为发布门禁；Linux 改用 Ubuntu 26.04，GitHub Actions 升级到新的主版本，不再有 Node 20 弃用警告
- 适配 Bun 1.4.4（测试侧）：node:http upgrade socket 的行为变化，以及若干 Windows 路径 / 时序问题
