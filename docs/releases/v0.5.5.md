**重要：运行时由 Bun 改为 Node.js**

从这个版本起，neko 运行在 Node.js 上，用 npm 安装；不再支持 Bun 运行与 `bun add --global` 安装。

- 新安装：需要 Node.js 22.19 及以上（推荐 24），然后 `npm install -g neko-harness`
- 从 0.5.4 及更早版本升级，请**不要运行 `neko update`**，按下面的步骤迁移：
  1. 退出所有 neko 界面与服务
  2. 安装 Node.js 22.19 及以上
  3. 卸载旧安装：`bun remove --global neko-harness`
  4. 用 npm 安装：`npm install -g neko-harness`
- 会话、设置与密钥仍在 `~/.neko/`，原样沿用，不需要处理
- 如果已经在旧版本里运行了 `neko update`：它会把 Bun 全局安装升级到本版本。macOS / Linux 上没有 Node.js 的机器随后无法启动 neko；装了 Node.js 的机器可以启动，但之后的 `neko update` 会提示当前安装方式不支持自升级。两种情况都按上面的步骤 3、4 重新安装即可

**新增**

- 支持 npm 安装与 Node.js 运行：`npm install -g neko-harness` 后，`neko tui`、`neko web`、`neko serve`、`neko update` 均可用
- Node.js 版本过低时，`neko` 的任何命令都会直接说明需要的最低版本与当前版本并退出，不再出现难以理解的加载错误
- `neko update` 改为升级 npm 全局安装：
  - 源码、项目局部安装、`npm link`、Bun 或其他包管理器的全局安装不支持自升级，会提示改用 `npm install -g neko-harness`
  - 当前用户对 npm 全局目录没有写权限时，停止并给出手动命令，不会尝试提权
  - Windows 仍只显示手动升级指引，命令改为 `npm install -g neko-harness@latest`；TUI 的新版本提示同步修改
- 网关的 Unix socket 路径超过系统上限时，启动失败的说明会写明路径、字节数与上限，并提示用 `--storage` 或 `--socket-path` 换成更短的路径

**已知限制**

- macOS / Linux 上，数据目录的路径过长时网关无法启动：Node.js 不能监听超过系统上限的 Unix socket 路径（macOS 103 字节，Linux 107 字节），socket 文件默认在数据目录下。默认的 `~/.neko` 不受影响；用 `--storage` 指到很深目录的用户需要换成更短的路径，或用 `--socket-path` 另行指定。此前在 Bun 上没有这个限制

**兼容性**

- 已有的 `~/.neko/neko.sqlite` 原地沿用，存储格式未变
- 桌面端应用协议与移动端 API 版本均不变，移动端 App 无需更新
- 安装时不再出现 `ws` 的 peer 依赖警告

**内部**

- 开发工具链由 Bun 迁移到 pnpm 与 Node.js：测试改用 vitest，发布打包改用 rolldown，脚本由 Node.js 直接运行；仓库不再依赖 Bun
- 发布流水线在 Linux、macOS、Windows 上用 npm 安装打包产物并在 Node.js 上冒烟，Linux 另用最低版本 22.19.0 再验证一次
- OpenSpec 变更 `migrate-runtime-to-node`、`migrate-toolchain-to-pnpm` 已归档
