**新增与改进**

- 升级到 Pi 1.4.0（chord / pi-ai / pi-durable / pi-tui / pi-env 同步精确锁定）：会话命名的等待改为可跨重启的睡眠，进程在等待期间重启后会按原到期时间继续生成标题；子 agent 排队等待槽位时关闭或中止不再遗留任务
- 压缩触发百分比（Web「上下文」设置、TUI `/context`、配置文件 `context.compaction.triggerPercent`）现在按每个模型自己的上下文窗口计算，不再取所有可选模型里最小的窗口。选定的百分比对任何模型都是「该模型窗口的这个比例」，启用或停用 provider 不再改变阈值
- 模型请求的 `User-Agent` 与 provider 归属显式固定为 Pi 的身份（`pi/<版本> (...)`），兼容只识别 Pi 客户端的模型厂商；请求内容与之前一致
- 终端界面：退出时由 pi-tui 同步恢复终端模式，Markdown 中 CJK 标点旁的加粗 / 斜体、未闭合的 `$$` 块后表格的渲染问题随 pi-tui 一并修复

**兼容性**

- **本地数据库不可回退**：Pi 1.4 打开 SQLite 存储时自动迁到 schema v2，迁移后 0.5.1 及更早版本无法再打开 `~/.neko/neko.sqlite`。升级后如需回退到旧版本，请先备份该文件。自动迁移由 Pi 完成，本版本没有用真实旧数据验证迁移过程
- 设置了压缩触发百分比的用户：大窗口模型会更早压缩。例如 1M 窗口设 80%，以前约在 99% 才压缩，现在在 80% 压缩；小窗口模型基本不变。没设置百分比（默认）时行为不变
- 应用协议仍为 9，手机端 API v1 不变，网关与客户端可按原方式配合使用

**已知限制**

- 同一后台任务被进程崩溃连续截断 5 次且没有提交新状态时，会被停放，不再自动重启；停放事件只经宿主错误通道报告一次，界面暂无查看或重试入口（恢复入口留待后续版本）
- 本版本未在 Windows 上做真机验证（发版流水线会在 Windows 上跑构建、测试与安装冒烟）

**内部**

- 所有文档定义显式声明 `checkpointWhen`（Pi 1.4 要求）；新增睡眠重启、崩溃停放、按模型阈值与请求身份的测试
- AGENTS.md 更新为 Pi 1.4 使用要点；OpenSpec 归档 `upgrade-pi-sdk-1-4` 与 `adopt-pi-1-4-settings`
